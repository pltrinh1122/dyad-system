# Self-diagnostic test levels (seed; the countersign craft's rules/self-diagnostic.md, check scripts/levels.py).
# Copied by hand to <host>/self-diagnostic-levels.txt, the instance file scripts/levels.py checks (<host> is the
# host path, preference `host-path`): the craft's README gives the copy command.
#
# One `<level> <path>` per line: level `unit` (L1, run in-process) or `integration` (L2); path a repo-relative
# test module, run one at a time as `dyad/bin/dyad check --tests <path>`. `#` starts a comment, here or after a
# line's fields. The granularity is the module: a module any of whose tests builds a scratch repo, runs git,
# installs or spawns the runner is `integration`, however many of its other tests are not.
#
# This seed covers the core (`dyad/tests/`), the bundled sysadmin craft (`crafts/sysadmin/tests/`) and countersign
# itself (`crafts/countersign/tests/`). A system adds a line for every test module of every other craft it
# installs, and revises a line whenever a module it names is added, moved, removed or changes level: the check
# fails on a module present but unclassified and on a line naming no module, in that system's own tree, and the
# run-book's `health` step, which runs it, stops the diagnostic there (a script, not a guard: it runs on no push).
# A system whose core predates a module named here deletes that line on copying it (a core labelled 0.10.1 has none of
# dyad/tests/test_incidents.py, dyad/tests/test_trace.py and dyad/tests/guards/agent/test_traces.py). The levels
# below are this tree's, and a receiving system re-observes its own core's modules before trusting a `unit` line:
# on a core labelled 0.10.1 (countersign-system), test_frame.py, test_plans.py, test_rules.py, test_vocabulary.py
# and test_preferences.py each run their guard over the live repo through `dyadlib.repo_root`, which starts
# `git rev-parse` there, so they are `integration` by the criterion below (falsification/self-diagnostic.md D10).
#
# Observed, not judged, in dyad-system at bdd74b3 (core 0.11.0, 2026-10-15): each module was run alone under an
# audit hook on `subprocess.Popen`. A module that started no child process is `unit`; one that started any — git,
# an interpreter, a shell, the runner — is `integration`, and the comment names what it started. Reading the
# package's own files in-process (a Rule, a data file) starts nothing and stays `unit`. A module edited since
# can move; re-observing it is the classification's only test. crafts/countersign/tests/test_levels.py, moved out
# of tests/guards/ by #308's plan revision 2 (falsification D20), was re-observed so after the move: no child process.
