# Naming guard data (beside its guard, guards/naming.py; the table is rules/naming.md). One entry per line; blank lines
# and # comments ignored. The guard fails on a `kind:` whose pattern is not a row of the table.
#   kind: <pattern> = <path glob> = <regex>   — `*` one segment, `**` any; the regex spans the whole path; `<instance>` is the
#                                                instance root (DYAD_INSTANCE); group `id` unique within the kind; group `beside`
#                                                names <dir>/<beside>.py that must exist
#   mode: <pattern> = <path glob> = <mode>     — every selected path is tracked at that index mode (git ls-files -s, never the disk
#                                                bit: core.fileMode=false hides a 100644 behind a 755, #135/#141); untracked warns
#                                                and falls back to the disk bit. Ops scripts are NOT here: their mode is part of the
#                                                Rule-18 form, checked by crafts/sysadmin/guards/ops_scripts.py (one owner)
#   symbol: <module glob> : <name|regex> …    — each selected module defines each plain name at top level; a regex needs one match
#   env: NAME …                                — every DYAD_<NAME> package code reads, no more, no less
#   allow: <path> # <reason>                   — a path a kind claims but that does not match; reasoned; stale fails for a package path
#                                                (dyad/, crafts/) and warns for an instance path (this file travels to other installs); unneeded warns
#
