# Plan #37 — d-work life-cycle on the kanban surface, and an archived state

Base commit of `main`: 0d86d2d. Refs #36 (the board as it is), #22 (its --craft filter).

## Intent as read
The board shows a row's *state* only. "Full life-cycle" reads as every phase a d-work passes through,
visible per card, from the store alone; "including archive" reads as a life-cycle *stage* the store
does not have: today `done` is terminal ("done → none", Rule-16), so the board's Done column grows
forever and the ledger cannot say which finished work is retired. Both parts below; the second is a
core change and the larger one.

## Mutation A — core (agent zone, one PR): the `archived` state
- `dyadlib.STATES` gains `archived`; `TRANSITIONS`: `done → archived`, `archived → none`
  (`done-is-terminal` becomes `archived-is-terminal`; done keeps one exit only). The row fence
  (`rows.py`) reads the table, so it enforces the new transition without an edit.
- Rule-3 Ledger states: `archived` — retired from the working board by an Operator disposition that
  names the row(s); terminal like done — a new row refs it, never reopens it; nothing moves: its
  row, plan and provenance stay where they are (Rule-16 store, Rule-20 references). Rule-16's
  transition table sentence. Vocabulary: `archived` (owner 3, used by 3 16). Falsification
  amendments (Rule-3, Rule-16) with Rule-5 pairs. Tests: `test_dyadlib`, `test_rows` wherever
  "done is terminal" is asserted. `dyad dwork state <id> archived` is the existing verb; a
  ledger-only commit, clerical execution of the naming disposition.
- No `dyad/VERSION` bump (a release bumps).

## Mutation B — sysarch craft (craft zone, one PR): the surface
- `project_kanban.py`: `COLUMNS` gains `archived` (the invariant `columns == STATES` forces it);
  Done shown open, Archived collapsed behind `<details>` (the retired set is what to hide, not the
  finished set). Each card gains a **phase strip**, every phase derived from the store and nothing
  else (no clock — determinism.md): opened (row date) · plan (`plans/<id>.md` exists) · plan-Y
  (a `Y plan` entry, its date) · PRs (`merges PR #n` tokens from `disposed`, listed) · Done-Y
  (`Y done`, its date) · provenance (`provenance/<id>.md`: prompt/disposition counts) · archived.
  Lit or unlit, dates in the hover title; a phase that is present out of order (a Done-Y with no
  plan-Y, a plan file for a backlog row) is drawn but flagged, since that is exactly what the
  board is for. Blocked keeps its blocker. `test_project_kanban.py`: the strip from a fixture row
  per phase, determinism, the flagged-out-of-order case, six columns. `crafts/sysarch/VERSION` 0.1.3.

## Mutation C — infra (one line): `BUNDLE.md` sysarch row 0.1.3 (the bundle guard requires it).

## Falsification
- "Archive as a view (done rows older than N) needs no state" — refuted: age needs a clock (not
  deterministic) or an arbitrary id cutoff; Rule-16 stores state explicitly, and "retired" is a
  fact about the row, not about today's date.
- "Archive by moving files to `d-work/archive/`" — refuted: row files are never deleted or moved
  (vocabulary `row file`); every `refs`, plan id and provenance id resolves by path (Rule-20).
- "done → archived reopens the terminal-state promise" — survives, scoped: done stays never-reopened
  (no path back to open/planned); archived is one further step in the same direction, itself
  terminal. The `done-is-terminal` invariant is renamed, not weakened.
- "Who archives?" — the Operator, by a disposition naming rows (like backlog intake); the Agent
  never archives on its own judgment. Stated in Rule-3.
- Presence: `web-sysarch` on #22–#33, none touching these files. Host actions: none.
