## Intent as read
The claim under test is from #133's completion reply: "rows #164, #165, #170–#173, #177, #181 have no
provenance record; rows like these get no mechanical entry-count check at all, the same gap the root
cause names." The Operator asks: falsify it, then remediate the survivor.

## Findings (origin/main 209dd2a)
- 176 rows, 152 records, 24 rows with no record, 0 orphan records.
- Of those 24, 18 are `backlog` with an empty `disposed` column: #38, #70, #129–#132, #134, #136, #162–#165,
  #170–#173, #177, #181. The warning names only the 8 at or above `SINCE_ID` (164).
- The other 6 are #84–#89. Each records one disposition ("Y backlog (audit sweep #83, …)") and has no record.
  Being below `SINCE_ID`, they are silent.
- `SINCE_ID = 164` means "the d-work that landed Rule-7", which is #164 of an earlier ledger. This ledger's #164
  is a 2026-09-25 backlog row. countersign's `rules/interaction.md` still says 164 "lies above every row id
  of this instance", which stopped being true at row 164. The cut-off no longer separates anything.
- The parent records (#166, #174, #178) hold only bare plan and Done `Y`s. None holds a disposition that opened
  those backlog rows, and none of those rows records one. countersign's I6 names this exact shape — a backlog
  row with an empty `disposed`, opened by the Agent's own finding — which Rule-3 does not admit: `backlog`
  means "opened by an Operator disposition".

## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | The 8 flagged rows lose Operator words to the missing count check. | **Refuted** | Each has 0 dispositions, so 0 = 0 and nothing escapes. The count check is vacuous for them, not missing. |
| 2 | "No mechanical check at all" for rows without a record. | **Confirmed, elsewhere** | #84–#89 hold a disposition and no record. Property 5 runs only when a record exists, so they escape both the count and the warning. The gap is real, but on rows the warning never names. |
| 3 | The id cut-off is a sound way to spare pre-Rule-7 rows. | **Refuted** | It names another ledger's id. It now warns on 8 rows unrelated to Rule-7's landing and exempts 6 that do hold dispositions. |
| 4 | The 8 are harmless, so the warning is just noise. | **Refuted as harmless** | They are backlog rows with no recorded opening disposition. Rule-3's `backlog` requires one; countersign I6 forbids the shape. The defect is in the row, not in provenance. |
| 5 | Backfill the missing records and dispositions. | **Refuted** | Rule-7 property 3 forbids gathering later, and property 2 forbids reading transcripts. Words that were never written cannot be recovered; inventing a disposition is Rule-2 self-ratification. |
| 6 | Make a missing record fail rather than warn. | **Survives, scoped** | Rule-7's reason (a concurrent session that has not loaded the Rule) still stands for a missing *record*. It does not stand for a row that holds dispositions, which only a disposition can produce. |
| 7 | Overlap (Rule-16). | **None found** | No presence file lists `provenance.py`, `rows.py` or Rule-7. |
