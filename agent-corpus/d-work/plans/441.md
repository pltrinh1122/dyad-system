# Plan #441 — `delegation-posture` binds an attended seat; an unattended seat reads its own value (efficient)

## Intent as read
The Operator adjusts #436's preference: the posture matters "especially … only when operator is attending". An
attended seat keeps the trade-off #436 set (`responsive`: the main chat answers at once, tokens spent). Every other
seat should "default to" `efficient` (fewest tokens, the chat busy while it works), and the cos to `responsive`.
Verbatim prompt: provenance #441 entry 1.

## Evidence
- **Who is attended.** Rule-16 Presence: a seat is attended when it is the leader or `attended-seats` names it. The
  leader is the cos (Rule-3 Ledger, "the leader — the cos"). dyad-system has `attended-seats: none`, so today only
  `program-59cec502` is attended. Every secretary (counsel, engineer, operate, distribute, audit) and every desk is
  unattended (cabinet `rules/organization.md` §6: "a desk is unattended unless `attended-seats` names it").
- **Why attendance is the right key.** #436 priced the trade-off as tokens against *chat latency*. A fork re-reads its
  context (~350k tokens over 50 min for #425's fork). A secretary hop costs hundreds of tokens. The latency is the
  Operator's only where the Operator sits. An unattended seat's chat is read by the cos, which relays and moves on
  (Guide §8 route table: "a cos relays, never answers").
- **No code reads the posture.** `grep -rn "delegation-posture\|posture"` over `dyad/` and `crafts/`, `*.py` and
  `*.txt`, finds nothing. It occurs only in `preferences-corpus/PREFERENCES.md` (row, paragraph), the Guide's §3
  "Posture" paragraph, and the cabinet record's #437 amendment. The preference is conduct, so neither shape below
  needs a guard or code change.
- **The guard.** `dyad/guards/preferences/preferences.py` `alternatives()` splits `allowed` on `\|` into backticked
  values. `check_text` fails a value that is not one of them. A cell without `|` is free text, and its value is
  inference.
- **The template.** `dyad/templates/PREFERENCES.md` (the core's preference schema) carries no `delegation-posture`
  row. A fresh install therefore has neither key, and `missing_keys` stays silent.
- **The cabinet release.** `crafts/cabinet/VERSION` is 0.2.0, and `BUNDLE.md` names cabinet 0.2.0. There is no local
  tag `cabinet-v0.2.0`; the only cabinet-line tag is `cos-v0.1.2`. The record's #433 and #437 amendments also say
  0.2.0 is uncut. `git ls-remote` was unavailable in this sandbox, so this was checked locally only.
- **#436's mandate.** The plan stated "one child per zone, ceiling 2", but only C2 was accreted (#437,
  `Y plan (mandate #436)`). C1 was pushed under #436 itself and disposed as its own question:
  `Y merge PR #478 … (delegation-posture responsive, its own question per #427)`. The Done question then named only
  `accreted #437, merges PR #479`.

## Recommendation (Rule-10)
**Path: shape (c), two keys.** These are new names; the counter-proposal is (a).
- `delegation-posture` keeps its key, its value `responsive` and its enumeration. Its meaning narrows to attended
  seats.
- A sibling row, `delegation-posture-unattended`, is added with value `efficient` and the same three values. It is
  read by every seat that is not attended.
- Both values are yours. Both are checked by the existing guard with no code change. Either can be changed by a
  preferences PR, with no craft PR.

**Strongest counter: shape (a).** You wrote "the key setting", singular. Shape (a) adds no row: the attended value
stays in the one key and the unattended `efficient` lives in the Guide. It is the smallest change and the closest to
the letter of the prompt.

**Reconciliation.** "Default to" means a value that can be overridden. Under (a) the unattended value would be
craft content. Changing it would take a craft PR, and it would ship as every installing system's value. A value you
set belongs in the table you own. (c) keeps your one key as the one you named and adds its unattended sibling. The
Guide carries only the fallback for a system with neither row.

**Concession.** If you want literally one key, answer `N` with "(a)". C1 then shrinks to the paragraph, and C2's
paragraph states `efficient` as the unattended value.
