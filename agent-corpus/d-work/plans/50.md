# Plan #50 — an instance-traversal surface for audit

Base commit of `main`: 33d551b. Refs #20 (the reference register this reads), #45 (stores.md, just
corrected). Falsification: inline below (Rule-9).

## Intent as read
The Operator audits by *walking instances*, not by reading schemas. Today `entities` projects entity
**kinds** (one card per guard). Nothing projects the **instances** — row #42, Rule-3, the term
`clerical` — or the edges between them. Asked for: one new surface, hierarchical, click-to-open
drawers and nested subdrawers, **every drawer closed by default**.

## The edges already exist, mechanically

Rule-20's register is an instance-level edge set, and it is already parsed: 28 working extractors
yield **1111 edges** on this corpus today. Measured, not assumed:

| kind | edges | | kind | edges |
|---|---|---|---|---|
| `rule.text->rule` | 291 | | `provenance.id->row` | 46 |
| `record.ledger->provenance` | 180 | | `plan.id->row` | 29 |
| `term.used_by->rule` | 175 | | `incident.dwork->row` | 26 |
| `rule.text->path` | 137 | | `craft_rule.text->provenance` | 25 |
| `term.owner->rule` | 86 | | …18 more | |

So the surface hand-draws nothing (`projection.md` p1): the register *is* the graph, exactly as
`project_entities.py` already draws kind-level relations from it (its `relations-from-register`
invariant asserts precisely that).

## The obstacle, stated before the design

An extractor yields `(where, token)`. `token` is a clean target id (`45`, `3`, `sysarch`). **`where`
is a location, not an instance key**, and its shape differs per kind:

    'agent-corpus/d-work/rows/45.md refs'                  -> row 45, field refs
    "dyad/vocabulary/VOCABULARY.md 'Operator' owner"       -> term Operator
    'agent-corpus/audits/INCIDENTS.md row 2 d-work'        -> incident row 2
    'agent-corpus/falsification/concurrent-session-races.md' -> record, whole file

Every `where` begins with a repo-relative path — that much is structural and uniform. Beyond the
path it is free text. The guard contract (`guards.md`: `ENTITY`, `FIELDS`, `describe`) exposes a
**schema and a count, never an instance enumeration**. That is the real architectural gap this
prompt exposes, and it bounds what v1 can honestly do.

Consequence, accepted rather than hidden: an instance is keyed by **the leading path of `where`**.
For one-instance-per-file entities (row, plan, provenance, rule, record, craft_rule, registry,
frame) that is exact. For **multi-instance files** — `term` in `VOCABULARY.md`, `incident` in
`INCIDENTS.md`, `preference`, `changelog`, `bundle` — the file is one node and each edge carries the
`where` remainder **verbatim as its label**, so `'Operator' owner -> frame` is still readable and
auditable, but the term is not its own drawer. Named as a limitation in the surface's own legend,
not discovered later.

## Mutation — one PR, craft zone (sysarch)
1. `crafts/sysarch/projectors/project_instances.py` — surface `instances`, discovered by the runner
   (`dyad project instances`, `--list`). `collect` builds the graph from `references.REFERENCES`
   alone; `render` emits one self-contained HTML file.
2. `crafts/sysarch/tests/test_project_instances.py` — fixture graph, cycle and depth cases, a live
   run over this instance, and the render-twice byte-comparison every projector's test carries
   (`projection.md` p2, `determinism.md` p3).

**Form.** Top level: entity kinds, sorted; inside each, its instances, sorted. Every instance is a
`<details>` drawer — **closed by default, which is `<details>`' own default**, so "all closed" is
structural rather than a JS reset the Operator has to trust. Opening a drawer shows its outgoing
edges grouped by reference kind; opening an edge opens the **target instance's own drawer, nested**,
built from an inline sorted-JSON graph by inline JS (the `entities` surface already ships inline
CSS+JS, so this is precedent, not a new dependency). Cycles: a node already on the open ancestor
path renders as a marked chip that links to its canonical drawer instead of recursing. Depth is
bounded by the same guard, so the file stays O(nodes + edges) — about 1111 edges — rather than the
exponential a pre-rendered tree would be.

**No `VERSION` bump** — a craft's version is its release d-work's. **No core change**: `references.py`
is Rule-20's and is read, never edited.

## Falsification
- **"Extend the `entities` surface instead of adding a second one."** Refuted: `entities` answers
  *what kinds exist and what is their schema*; this answers *what instances exist and what do they
  point at*. One projector, one surface (`projection.md` p4) — and an audit of 1111 edges inside a
  schema card would drown the schema. Two surfaces over one register is the register working.
- **"Keying instances off `where`'s leading path is hand-drawing, which p1 forbids."** Survives,
  scoped — the sharpest attack, and the honest answer is a boundary rather than a denial. Splitting
  on the first space is structural (every `where` is built as `<path> …`); *parsing the remainder*
  per kind would be hand-drawing, so the remainder is displayed verbatim and never parsed. The
  multi-instance collapse is the price of not hand-drawing, and it is shown in the legend.
- **"Then fix the contract: add an instance enumerator to every guard."** Survives, scoped, and is
  the right long-term shape — `guards.md` is sysarch's own rule, so the craft could own it. Refused
  *here* on scope (Rule-12: choose among realizations of the plan, never widen it): it is a contract
  change across 19 guards plus `guards.md` plus every guard's test, and it should be proposed on the
  evidence this surface produces, not ahead of it. Proposed as a backlog row in the completion reply,
  not absorbed.
- **"Pre-render the whole tree as nested `<details>` and use no JS at all."** Refuted by
  measurement: `rule.text->rule` alone is 291 edges over ~20 rules, so a depth-4 pre-render is
  ~10^4–10^5 nodes and the file stops being viewable. Inline JS over an inline JSON graph is
  O(nodes+edges). Determinism is unaffected — the JSON is sorted and carries no timestamp, and the
  test renders twice and compares bytes.
- **"JS in a projection breaks 'self-contained'."** Refuted: self-contained means no *external*
  resource (`projection.md` p3, `determinism.md` p1); `project_entities.py` already inlines JS.
- **"An audit surface whose edges are the register inherits the register's blind spots."** Survives,
  scoped, and is worth the Operator knowing up front: three kinds have `None` extractors
  (`pr.body->row`, `cache.source->path`, `bundle.component->craft`) and four resolve to `world`.
  Those appear as declared-but-unwalkable, labelled, rather than silently absent — `failure.md`'s
  *loud* property applied to a surface: a gap prints itself.
- **Overlap (Rule-16):** `web-sysarch-adh151` shares this session's `root` and lists 12 files under
  `rows: 15 32`; the only sysarch path among them is `rules/stores.md`, which this plan does not
  touch. No overlap on either file above. Same-root warning stands, as all session.
