# Plan #83 — audit sweep: completeness and coherence of the sysadmin craft

Base commit of `main`: 15c127b. Refs #81, #82 (both `planned`, execution queued), #155 (the
extraction that made this craft), #58 (the d-work that moved its authoring home here).
The sweep itself is done; this plan's mutation is the record of it. **No remediation** — the
Operator's prompt bounds it, and every finding is a `backlog` row instead.

## Intent as read
Sweep the sysadmin craft for completeness (does it hold everything a craft of its stated scope
needs) and coherence (does anything in it instruct two ways, cite what does not exist, or leave a
concern unowned), then produce a plan and one backlog row per finding. Do not fix anything.

## Method
Read-only. Every rule, the vocabulary, the manifest, the templates, the guards, the tests, the
records and the README; then five mechanical cross-checks, each reproduced below so the Operator
can re-run them:
1. every vocabulary term's `rule` column resolves to an existing rule, and the term is used in one;
2. every guard has an owning rule and a test;
3. every template and doc is referenced by a rule, the README or `MANIFEST.md` `seeds:`;
4. every `agent-corpus/…` path a craft file cites exists in this instance;
5. every bare `#<id>` a craft file cites resolves against **this** ledger (Rule-3: a bare `#<id>`
   is a cross-reference into this instance's rows).

## What is sound
Checks 1 and 2 are clean: 14 vocabulary terms, each owned by an existing rule and used in it; four
guards (`changelog`, `events`, `ops_scripts`, `runbooks`), each with a test and a rule that names
it; one projector with a test; one falsification record per rule. `dyad check` is 0 FAIL. The
run-book's ten sections agree across three places — `server-instances.md`, the craft vocabulary's
`run-book` term, and `runbooks.py`'s `SECTIONS` — including `Backup` and `Restore`. (I first
recorded those two as missing from the rule; that was a case-sensitive grep of mine, not a defect.
Corrected here rather than dropped.)

## Findings

**Coherence**

- **A1 — two ledgers' id spaces are interleaved with no marker. (#84, the headline.)** The craft's
  prose cites 13 distinct `#<id>`s. One, `#58`, is this instance's and resolves correctly. The other
  **12** (`#135 #141 #150 #152 #155 #156 #157 #160 #162 #165 #178 #180 #181 #216`, less those below
  the max) are `pltrinh1122/workstation` ids, carried over when authoring moved here (#58). Nothing
  in the text distinguishes them. Today they resolve to nothing; **as this ledger grows past each
  one they begin resolving silently to an unrelated local row** — this instance is at 89 and #135 is
  the next to be crossed. The craft is distributable, so every installing system inherits the same
  time-bomb against *its* id space. The ledger's own `refs` column already has the fix in use
  (`workstation-184`, `surfacer-242`); the craft prose does not use it. Systemic, not
  sysadmin-only: sysarch cites 18 foreign ids, syseng 18 — 48 across the three, so the remediation
  belongs at craft-system altitude (a citation convention plus a guard), not inside this craft.
- **A2 — Rule-11 property 1 is enforced for files but not for citations. (#85.)** Three craft rules
  cite `agent-corpus/d-work/plans/155.md`, `162.md` and `216.md`; none exists in this instance.
  `distribute.instance_state` — the scan that keeps the instance out of a craft — reads content and
  file names, never references, so a craft may not *contain* instance state yet may freely *point
  at* it. `references.py` sees these only as `craft_rule.text->provenance … unresolvable (The
  World), inference` (32 such warnings today), which is the wrong classification: they are not World
  references, they are references into a *named other instance's* ledger, and that is resolvable in
  principle. A1 and A2 are one fault seen twice — ids and paths — and should be remediated together.
- **A5 — three permanent guard warnings with no recorded adjudication. (#88.)** All three rules trip
  `craft/crafts`'s Rule-4 warning ("mentions 'the Agent', 'counter-prompt' — binds the Agent's
  process?"). #156 left the classification to inference, deliberately. But nothing records that the
  judgment was *made*, so a reader cannot tell an adjudicated warning from an ignored one, and the
  three lines are permanent noise in every `dyad check`.

**Completeness**

- **A3 — an undeclared seed. (#86.)** The craft README calls `templates/events-README.md` "seed for
  `<runbooks>/events/README.md`", but `MANIFEST.md` `seeds:` declares only
  `CHANGELOG.md->workstation-corpus/CHANGELOG.md`. The #180 mechanism built for exactly this — warn
  at `craft check`/`install` when a seed's destination is absent, naming the copy — therefore never
  fires for it. The craft documents a seed relationship its manifest does not.
- **A4 — host-level backup and restore is unowned. (#87.)** `docs/backup-timeshift.md` ships a
  whole-machine snapshot and restore procedure. No rule owns it, no guard checks it, no vocabulary
  term names it — it is a doc in a craft whose other content is all rule-backed. Distinct from a
  server instance's `Backup`/`Restore` run-book sections, which `server-instances.md` does own; this
  is the host itself, and the host is this craft's whole subject.
- **A6 — no ops-script scaffolder. (#89.)** `dyad runbook new <instance>` seeds a run-book from the
  craft's template; nothing seeds an ops script from `templates/ops-script.sh`. Every ops script is
  hand-copied against a rule with seven form properties and a guard that enforces them. Rule-13
  property 1 (recurrence proposes code). Minor, and listed last.

**Already covered — not duplicated as new rows**
- The craft's two unwritten scope areas (host-side packaging and installation; the host platform
  abstraction) are **#81**, `planned`. The sweep confirms the gap it names: `rules/README.md` has
  three rows against a stated scope that now has five areas.
- A dyad system with no host at all is **#60**, `backlog`. The sweep confirms this craft has no
  clause for it; nothing to add.
- The launcher defect that disables this craft's own guards on a non-conforming host is **#82**,
  `planned`.
