## What was measured for this record (pinned kernel, Python 3.13.12)
Three experiments, in `/tmp` scratch, no repo file touched. They exist because attack B7 needed
the option space #185's A5 had scored `unavailable`.

1. **A checked-hash `.pyc` is honoured by the very loader `load_module` uses.**
   `importlib.util.spec_from_file_location` + `exec_module` over a source compiled with
   `compileall --invalidation-mode checked-hash`: first load `111`; then a same-size rewrite to
   `222` restored to the original mtime → the loader returned **`222`**, the source's value.
   The same experiment with a timestamp `.pyc` returned **`111`** from a source reading `222`.
2. **The import system never writes a checked-hash `.pyc` on its own.** With
   `SOURCE_DATE_EPOCH` exported, the cache the import system wrote carried flags `0` —
   timestamp — on 3.13.12 and on 3.11.15. So option 1 costs a `compileall` step at install; there
   is no environment variable that buys it.
3. **`PYTHONPYCACHEPREFIX` empties the tree without touching either suppression.**
   `__pycache__` directories in the tree after an import: **0**; `.pyc` under the prefix: **25**.
   It removes the coupling and leaves the staleness, because what it relocates is still a
   timestamp cache.
