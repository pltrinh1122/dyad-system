# Plan #541 — adversarial stress test of the chain of command, and the fences it calls for (falsified)

Base commit of main: (main at opening)

## Intent as read
The Operator: "perform adversarial stress testing of chain-of-command protocol". The protocol as it runs today:
1. The Operator disposes in the cos's chat.
2. The cos records the words on `main` (row `disposed` entry, provenance entry).
3. Each executor reads that record: `dyad merge`, with the Operator's allow rule 5bc7a2d, for merges; the `released`
   workflow for releases; the plan gate for pushes.
4. Seats otherwise act on plan files and on the cos's relays.

The C2 order channel (#533) is not built, so it is attacked only where it would differ. The adversary is a seat, a
subagent or injected text, acting in bad faith or by mistake. Each attack was checked against the code on `main`
(`dyad/scripts/merge.py`, `rows.named_heads`, `.github/workflows/dyad-release.yml`, the fence's first-parent walk).

## Findings, by severity
| # | attack | result | severity |
|---|---|---|---|
| A1 | **A forged `Y release` entry publishes to the world.** Any session can push a ledger-only commit to `main` (Rule-3). The `released` workflow publishes on any `Y release <tag> at <cut> (archive <sha256>)` it finds, and the archive hash is computable by anyone | **confirmed.** The second gate already exists (`RELEASE_APPROVAL=tap` puts the job in the `release` environment, with the Operator as required reviewer, #461 attack 4), but the publish runs of #517 and #526 show no wait, so it is evidently off. Publishing cannot be undone | **critical** |
| A2 | **The allow rule trusts the working tree.** `Bash(dyad/bin/dyad merge:*)` permits a command string. The code it runs (`merge.py`, `land.py`, `package.py`, `dyad/hooks/pre-push`) is loaded from the seat's own checkout, which any session may edit without committing. A seat that edits `merge.py` locally gets an allowed command that pushes anything to `main` | **confirmed by reading.** The harness cannot see the code behind an allowed command | **high** |
| A3 | **An "evil merge" passes the fence.** The fence judges first-parent non-merge commits only (`rows.py`). A merge commit whose tree is not the true merge of its parents carries arbitrary content past it. This holds for any merge pushed to `main`, A2's route included | **confirmed.** Nothing compares a merge commit's tree with `git merge-tree` of its parents | **high** |
| A4 | **A revocation after a Done-`Y` is ignored.** `named_heads` takes the row's last *`Y done`*, not its last disposition. If the Operator says `N` (hold) after the `Y` but before the merge, the recorded `Y done` stays operative, and `dyad merge` executes it | **confirmed by reading** `rows.named_heads` | **medium** |
| A5 | **A seat writes a `Y done` itself.** `dwork state <id> … -d "Y done (…)" --said Y` writes the entry and the provenance text `Y` from any session | **survives, detection only.** The attendance reading flags a disposition recorded in a seat that is not attended (`undeclared`, Rule-16) only if that record's `session:` line names the seat. The entry carries no proof of where the words were given. Rule-7 says so: faithful transcription is inference | **medium** (bad faith only) |
| A6 | Compound commands: `dyad/bin/dyad merge 1 --head <sha> && git push origin HEAD:main` under a prefix allow rule | **unverified.** The harness is expected to split compound commands and judge each part; it is to be observed in the exit test (#540) | low until observed |
| A7 | A subagent runs the allowed verb (Rule-3: subagents never merge) | **survives, conduct only.** The allow rule applies to the whole session, and the verb cannot tell a subagent from the main agent | low |
| A8 | A moved PR head, a short sha, already landed, a conflict, a push race | **refuted:** `merge.py` refuses each, and its tests cover them | — |
| A9 | The cos relays an order a seat treats as authority (#252's exclusion) | **survives:** seats act on the plan file and the record on `main`, and the cos's message is the trigger only (#532 R1). Every relay since #532 cites a recorded entry | — |
| A10 | A seat edits its own permission file | **refuted live:** engineer's harness refused it as "[Self-Modification]" (#532 revision 7) | — |

## Falsification of the remedies
| # | remedy | attack | result |
|---|---|---|---|
| R1 | A1: set `RELEASE_APPROVAL=tap` (a repository variable, the Operator's own setting, plus the `release` environment's required reviewer) | it costs a tap per release | **survives:** a release is already its own question (Rule-11). The tap is the Operator's second, out-of-band check, which no agent-written record can satisfy |
| R2 | A3: a guard comparing each merge commit's tree on `main` with `git merge-tree` of its parents (warn on push, fail in CI) | merges with resolved conflicts differ legitimately | **survives, scoped:** a resolution differs only on conflicted paths. The guard lists the differing paths, so a reader sees them. `dyad merge` never resolves conflicts, so its merges must match exactly |
| R3 | A2: the verb runs `main`'s blob, not the working tree's | the entry point itself is in the tree | **conceded:** a local check cannot defend against local code. So A2 is answered by **detection**: R2 catches the content, R5 catches the authority. The prevention alternative is a server-side merge workflow reading the record from `main`'s code (as `released` does), which removes the allow rule. Kept as a backlog row, decided after the exit test (#540) |
| R4 | A4: the operative entry becomes the row's *last disposition*; if it is not a `Y done`, `dyad merge` refuses and the pre-push F1 reading follows | a later unrelated `Y plan` on a reopened row | **survives:** a done-recorded row takes no further plan entry while its merge is pending (Rule-3's three acts). Any later disposition is about that row's merge, so treating it as superseding is right |
| R5 | A5 and the merge half of A2: reconciliation, every merge commit on `main` maps to an operative `Y done` naming its second parent; promotes the merge part of backlog #534 | it adds a guard | **survives:** detection is the Operator's chosen posture (#532 revision 3), and this is its cheapest form. It warns, never blocks |
