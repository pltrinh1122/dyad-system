## Falsification

- **"Stale is a lie — `mergeable_state: dirty` is about one audit file, not the change."**
  Confirmed, and this is the finding that picks the survivor. The PR's reason for existing is
  untouched; only its footing is. A path that preserves the diff and moves the footing therefore
  loses nothing the Operator verified.
- **"Wait for #38: fix the hook, then base-merge PR #20, and the Done-`Y` already given still
  covers it."** **Refuted — and this refutes my own comment on PR #20**, which said the PR "merges
  as clerical execution of the `Y` already given ... as soon as #38 is fixed." It does not. Any
  conflict resolution — base merge or otherwise — changes the head from `8438731`, and Rule-2's
  Binding holds a `Y` only "if their heads are unchanged since it was asked; otherwise the agent
  stops and re-prompts." **A fresh Done-`Y` is required on every path, including the one I told the
  Operator was free.** Since #38 buys no exemption, waiting on #38 buys nothing here.
- **"Then force-pushing destroys the three commits the Operator's Done-`Y` was given on."**
  Survives, scoped — the honest cost, and the reason this is a plan and not a silent repair. Three
  mitigations, stated rather than assumed: the resulting diff is verified byte-identical to the two
  code files at `8438731` before the push; the superseded shas are written here, in the ledger and
  in the PR comment; and a fresh Done-`Y` is asked regardless, so nothing reaches `main` unverified.
  What it does not cost: PR #20's number, body, or comment thread, all of which survive a force-push.
- **"Open a new PR instead — never rewrite a branch."** Refuted on the balance: a new PR needs a
  fresh `Y` exactly as this does (Rule-2), so it buys no safety, and it splits the record —
  abandoning PR #20 with a standing-down comment that would then be wrong twice. Rewriting a branch
  *this session created* is the case the convention permits; rewriting a peer's is the one it forbids.
- **"Drop the three incident rows from the PR and the conflict vanishes with no rewrite."**
  Refuted: the conflict would vanish and the incident record would vanish with it. Rule-3 Incidents
  requires those rows in this d-work's own PR or the next agent-zone PR. Trading a record for a
  convenience is the wrong trade.
- **"#42 should just fix #38 — the hook is the actual defect."** Refuted *as this d-work's mutation*,
  not as a judgment: the hook defect is real, still unfixed, and still blocks every future base merge
  by anyone. But it is `#38`'s, it is not what this prompt asked, and per attack 2 it does not unblock
