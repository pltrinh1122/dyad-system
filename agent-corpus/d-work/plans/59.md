## Falsification
- **"Deleting a branch whose remote is still live (`craft/45`, `craft/50`) is presumptuous —
  their remote might get deleted differently, or the Operator might want them kept a while."**
  Survives, scoped: both are fully merged (table above), so keeping them costs nothing but local
  clutter and loses nothing (the content is in `main`; the remote branch, if the Operator wants
  it kept, is untouched either way — this plan only ever deletes *local* refs). Proceeding, since
  "sync" is exactly the operation that reconciles a finished branch away, and the two are in the
  same state as the six already-deleted ones by every test that matters (merged, no divergence).
- **"`-d` versus `-D`."** `-d` is strictly safer and sufficient here (git's own ancestry check
  duplicates the `merge-base --is-ancestor` verification above); no branch needs `-D`.
- **"This should have been Rule-8 destructive, not reversible."** Refuted: nothing is destroyed
  that is not already present, verified, in `origin/main` and locally checked out at `main`; the
  undo table makes recreation a one-line command, not a recovery.
- **No honest counter found** to fast-forwarding `main` itself — a clean fast-forward changes
  nothing about what commits exist, only which are checked out.
