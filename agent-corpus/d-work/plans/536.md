## The gap, as #546 measured it
Seats report by `send_message` to a session id. After a hop the report goes to the old session (S5). A terminal holder
cannot receive one at all (S6, S18, S26). Each fails with the single violation "its report never reached the holder".

## Survivor: the inbox store
- **Store.** `<instance>/d-work/inbox/<seat>/<UTC-stamp>-<from-seat>-<n>.md`.
  - **Addressed by seat name, never session id**, so a hop changes nothing for the sender.
  - **One file per message**, so concurrent senders never collide (Rule-16's disjoint-files idea). Append-only: a
    message is never edited.
  - **Read is a marker beside it** (`…​.read`, written by the reader), never a deletion, so history is git's and
    nothing is lost.
  - Ledger-only commits, since it sits under `d-work/`.
  - Keys: `from`, `to`, `row`, `kind` (`report` | `relay` | `ack` | `notice`), `sent`, `body` (verbatim).
- **What it may carry: information, never authority.** The guard refuses a message whose body is disposition-shaped: a
  `Y/N:` counter-prompt, or a `Y plan` / `Y done` / `Y release` entry. Authority stays in the ledger (rows, provenance)
  and is read there. This keeps #252's announcement plane intact, and its command plane is the ledger, not the inbox.
- **CLI.**
  - `dyad inbox post <to-seat> --row <id> --kind <k> <body | --body-file F>` writes one message as a ledger-only land.
  - `dyad inbox read [--all]` prints unread messages for this seat (`DYAD_SESSION`) and marks them read.
  - `dyad inbox list` is read-only.
- **Delivery.**
  - `dyad board resume` and `dyad session touch` print the count of unread messages for the seat.
  - The cos reads its inbox at every turn start, and a terminal desk does too.
  - `send_message` becomes an optional doorbell ("inbox: 1 new"), never the carrier.
- **Seats' conduct, written by counsel.** A seat reports by `dyad inbox post program …`. The cos relays to a seat by
  posting to that seat's inbox, and the Operator's words still travel verbatim, citing the provenance entry.
- **Ride-alongs (mandate):**
  - **#547:** `board resume` skips, or marks stale, an entry whose row is terminal.
  - **#551:** resume's list of seats to announce to includes every owner of an entry.

## Falsification

| 1 | Polling a store cannot interrupt a busy session (#252 M2) | **conceded, scoped**: the inbox carries reports and relays, which are read at the next turn. Interruption stays with the harness's mid-turn messages. The board's write-ahead means nothing waits mid-turn on a report |
| 2 | An unread message is invisible: silence read as consent | **refuted**: unread counts print at every resume and touch, and a `report` the board expects but that never arrived shows as the row's `waiting-on seat` past its `since`. Nothing is inferred from silence |
