### Decision 1: the slug's form
**Choice:** 2 to 4 pieces joined by `-`. Each piece is letters, digits or dots. The first piece opens with a letter;
every other piece opens with a letter or a digit. The whole is at most 32 characters. Case is kept.
- **The pattern:** `dyadlib.SLUG = [A-Za-z][A-Za-z0-9.]*(?:-[A-Za-z0-9][A-Za-z0-9.]*){1,3}`, and `dyadlib.SLUG_MAX =
  32`. One function, `dyadlib.slug_problem(s)`, returns the refusal text or `None`. The verb, the fence and the
  package check all call it.
- **Pieces, not tags.** The guard counts pieces. A defined term keeps its own hyphen and case (`intent-Y`, `d-work`),
  so it is one tag of two pieces. `release-intent-Y` is 2 tags and 3 pieces. 2 to 4 pieces holds 2 tags with up to
  two such terms, or 3 tags with one. Whether the pieces make 2 or 3 tags is the agent's choice. The operator reads it
  in the row's first question (F8).
- **Why the first piece opens with a letter:** so `#<id>-<slug>` never reads as `#<id>-<digit>`. No reader then
  mistakes a label for a range or a longer number (F1).
- **Accepts:** `row-slugs`, `release-intent-Y`, `release-1.1.0`, `macOS-host`.
  **Refuses:** `release` (one piece), `1-x` (opens with a digit), `a--b` (an empty piece), `a-b-c-d-e` (five pieces),
  `row_slugs` (an underscore), anything over 32 characters.
- **Unique.** `dwork new --slug` and `dwork state --slug` refuse a slug another row holds, in any state. The row ids
  differ anyway, so a duplicate is never a binding fault; the refusal is for reading. No guard checks it: a duplicate
  can arise only in a race, and a warning on a field that never changes would stand forever (F9).

### Decision 2: the field and its fence
**Choice:** an optional field `slug`, after `mode`. `OPTIONAL_FIELDS = ("mode", "slug")`, and `Row.slug: str = ""`.
`format_row_file` writes it only when it is not empty, by its existing rule. So every row written before #622 reads and
writes back byte for byte.
- **The parser stays lenient.** `parse_row_file` reads any value. A `mode` outside `MODES` raises, because a third mode
  would change who authorized the row. A bad slug changes nothing but a label. So the form is judged by the guard, not
  the parser, and one bad line never stops every reader of the ledger.
- **The fence**, a new clause `rows.slug_problems(path, before, after, label)`:
  - a row added with a slug: the slug must pass `slug_problem`;
  - a row with no slug may gain one, once; it must pass `slug_problem`;
  - a row with a slug keeps it: a commit that changes or removes it fails.
  - It runs in `check_commit` (on `main` and on each commit of a ledger-only branch), for an added and for a
    modified row file. It runs in `check_merge` too, against each parent, as the `mode` clause does.
- **The package check** (`rows.check_package`): a stored slug that fails `slug_problem` is a failing line.
- **How this differs from `mode`.** `mode` is fixed at birth: a row is born `implicit` or never is, because `mode`
  carries authority (a mandate). A slug carries none. No reader decides anything from it: authority is read from
  `disposed`, and a question binds by numbers (Decision 4). So gaining it once is safe. After that it is as fixed as
  the title.
- **The verb.**
  - `dwork new --slug <s>`: the row is born with it.
  - Under `dwork-slug: on`, `dwork new` without `--slug` is refused, before any write. That holds for
    `--mandate` and `--backlog` too.
  - `dwork state <id> <state> --slug <s>`: it writes the slug onto a row that holds none. It goes with or without a
    disposition.
  - That `state` call is refused when the row holds a different slug. It is refused when the row is `done` or
    `archived`, so a terminal row stays bare (A3). The same slug again changes nothing.
  - Under `off`, `--slug` is still accepted and stored. So turning the preference on later finds the slugs already
    there.
- **The writers keep it.** `dwork state`, `dwork retire` and `release.ready` build the new row with
  `dataclasses.replace`, so they carry every field, this one and any later one (F3).
- **land.py.**
  - `already_landed`: a `state` call that carries `--slug` is landed only when the row already holds that slug.
  - `subject`: such a call's commit reads `ledger: #<id> <state> (slug <s>)`.
