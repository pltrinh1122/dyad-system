# Plan #113 — `concise-mode`: one synthesized reply per prompt

Base commit of `main`: 2d0ca3a. Refs #17 (`batch-disposition-mode`, the preference this one is
shaped after — same zones, same two-PR order, same read-by Rules).

## Intent as read
A preference under which the Agent emits exactly one text reply per Operator prompt: the
synthesis. Everything now spoken between actions — "syncing first", "nearly there", interim
findings restated later anyway — stays in reasoning. Feasibility first; the mutation below is
what a `Y` would authorize once the study is read.

## Feasibility study

**1. What "chatter" is, measured.** In this session's last ten turns the Agent emitted between
two and five visible text blocks per prompt: a one-line preface before the first tool call, one
or more mid-turn progress lines, occasionally a harness-prompted "say what you're doing", then the
synthesized reply. Every fact the interim blocks carried was restated in the final block. The
chatter is therefore redundant *content*, not lost content — hiding it loses nothing a Rule
requires, provided the final block is written to carry it (point 3).

**2. Where the mode lives — and why it binds.** Reply form is Rule-10's concern ("one `Y/N`,
last line, one per reply") and what a reply must carry is Rule-3's (plan, completion evidence,
incidents "in the reply where it occurred or in the completion reply"). A preference row read by
those two Rules is the existing shape (`batch-disposition-mode`, #17). It binds because the frame
loads `preferences-corpus/PREFERENCES.md` at session start and the project's instructions
override the harness's defaults — the harness's own guidance ("give short updates while working")
is the behavior being switched off, and a project instruction is the documented way to switch it.

**3. Every Rule that mentions a reply, checked against a one-reply turn.**
- Rule-3 Plan: "the Agent's first substantive reply to a prompt is a plan" — one reply, is the plan. Holds.
- Rule-3 Completion: evidence pasted verbatim, counter-prompt last line — one reply. Holds.
- Rule-3 Incidents: "reported in the reply where it occurred or in the completion reply, whichever comes first" — with one reply per turn these coincide. Holds, and gets stricter: the incident *must* be in the synthesis, since there is no other reply.
- Rule-3 Batch disposition: queue counts "at the end of every reply" — one reply. Holds.
- Rule-8 blocking question: "the Agent stops and asks" — stopping *is* the reply; the mode says one reply per prompt, not "finish everything before speaking". A turn that hits a blocking question ends there, and that question is the synthesis. Holds.
- Rule-10: one path, counter, reconciliation, one `Y/N` last — reinforced, not strained.
- Rule-2/Rule-11: ratification questions are replies; one-per-question and the #106 batch form are unchanged. Holds.
- Rule-7: reasoning is never corpus (property 2 — the raw transcript never enters). Chatter moved into reasoning is chatter moved *out of nothing*: it was never corpus either. Holds; nothing to record.
- Rule-16: no Rule requires narration for a concurrent session; overlap is read from presence files, not chat. Holds.

**4. The one real risk: an interrupted turn.** Today an interim finding is on screen the moment it
is found; under the mode it surfaces only when the turn ends. If the turn is cut off first —
context compaction mid-turn happened in this very session, at the start of this continuation —
an unspoken finding could be lost with the reasoning. Mitigation, already the design and made
explicit by the mode: anything a Rule requires reported is *written to the corpus* during the turn
(the plan file's falsification section, `INCIDENTS.md`, a row's provenance) before the reply
summarizes it, so an interruption loses narration, never record. The mode's text says so.

**5. Two harness facts outside the corpus, stated.** (a) A mid-turn Operator message (one arrived
this session: "select the most permissive for LICENSE") lands inside a running turn; the single
reply then answers two prompts but may carry one `Y/N` — Rule-3's batch queue already covers the
second. (b) The harness sometimes injects "say a few words about what you're doing" during long
tool sequences; that is an Operator-side fence outside the corpus (Rule-1/Rule-8 name the class);
under the mode the Agent answers it with one status line, never a second synthesis. Both are
conduct the mode's own bullet states, not guard-checkable.

**6. Enforcement.** Inference only, stated — exactly Rule-10's own footing. No guard reads chat.
The check is the Operator's eye and this session's own record: a turn with more than one reply is
an incident (Rule-3), logged like any other.

**7. Verdict.** Feasible now, as conduct bound by a preference row; no code, no guard, no
vocabulary term (a preference key is defined by its `read by` Rule, never in the vocabulary,
Rule-6 Boundaries). Cost: one preferences-zone PR, one agent-zone PR, one infra bundle-row PR.
Pilot risk is low because `off` is one row edit away, and the row is Operator-owned.

## Mutation (what the plan-`Y` authorizes)
1. **Preferences zone, PR 1** — `preferences-corpus/PREFERENCES.md`: new row
   `concise-mode | on | \`off\` \| \`on\` | Rule-10 (reply form), Rule-3 (what the reply carries)`
   and its bullet: `off` — the Agent may speak before and between actions (today); `on` — exactly
   one reply per Operator prompt, the synthesis, emitted when the turn ends (done, or stopped at a
   blocking question): no preface, no progress lines; every finding, incident, evidence block and
   queue count a Rule requires appears in it, written to the corpus first where a Rule stores it;
   a harness "say what you're doing" prompt gets one status line, never a second synthesis; a
   mid-turn prompt is answered in the same reply under the batch queue.
2. **Agent zone, PR 2** (referent after the preference exists, #17's order) — `dyad/templates/

## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | Hiding chatter hides findings; "detect, don't dispose" needs them on screen as found. | Refuted | Every finding the frame requires surfaced is a finding the synthesis carries; the interim blocks this session were restated in full in the final block each time (study 1). | 2 | A cut-off turn loses the unspoken finding. | Survives, scoped | The record precedes the reply (study 4): plan file, `INCIDENTS.md`, provenance are written during the turn; what an interruption loses is prose. The mode's bullet makes this ordering explicit rather than assumed. |
| 3 | "One reply per prompt" forces the Agent to finish a long turn before asking a blocking question. | Refuted | The mode bounds replies per prompt, not work per reply; a blocking question ends the turn and *is* the reply (Rule-8 unchanged). |
| 4 | The harness will keep injecting "say what you're doing"; the mode is unenforceable against it. | Survives, scoped | Outside the corpus, like the harness permission mode (Rule-8 Boundaries); the bullet names the one-status-line answer, and a second synthesis is an incident. |
| 5 | This is a Rule, not a preference — it binds the Agent's process. | Refuted | It selects between two conducts both Rules already permit (Rule-10 fixes the form of the *one* reply, never how many precede it); `batch-disposition-mode` sits on the same footing (#17, attack 1's reasoning). |
| 6 | Ratification-relevant text (evidence, the `Y/N`) could be buried in a long synthesis. | Survives, scoped | Rule-3 already fixes evidence's place (before the counter-prompt) and Rule-10 the `Y/N`'s (last line); the mode adds no freedom there. |
