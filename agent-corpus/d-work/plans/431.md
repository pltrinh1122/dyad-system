## Survivor
Operate owns the alignment **check**: a run-book `<host>/runbooks/sessions.md` whose health command is
`dyad session audit` — for each live presence file a harness session whose title is the seat's `dyad session
name` form, and for each harness session titled in the seat form a live presence file; mismatches printed one
line each (`no harness session`, `no presence`, `title differs`, `stale while titled`), pass = none. Operate
runs it at every reply and on the program's request, records the event, and reports mismatches on its board;
remediation is the writer's (the seat touches; the program retitles/archives), never operate's write.

## Revision 2 — operate vs audit (prompt 2, 2026-10-25; analysis delegated to a subagent, read-only)
**Charters today** (`preferences-corpus/MANDATES.md`): audit — "the standing audit, the self-diagnostic,
incident hardening, the Rule-5 sweeps"; fence read-only over the tree, writes only `<instance>/audits/` and
`<host>/runbooks/events/`, ceiling 0, "proposes rows, opens and fixes none" (Three Lines). operate — "the host:
read-before-act, classes, ops scripts, run-books, change-log rows, the services behind boards"; fence `<host>/`
and `crafts/sysadmin/`, ceiling 6, escalation "a run-book command that does not work as written". Neither names
the harness session list or the presence store.

**Separation of concerns**
| axis | operate | audit |
|---|---|---|
| cadence | continuous: a health command at every reply or on request (sysadmin `server-instances.md` p4, p7) | periodic, watermark-gated (`dyad/playbooks/audit.md` Phase 0: "a clock is not the gate"; `incident-hardening.md`) |
| object | the host and runtime — `~/.claude/projects/<slug>/` is a host artifact (Rule-7 Boundaries), The World (Rule-14) | the corpus and the process: tree, fences, drift, incidents, Rule-5 sweeps |
| act | detect and report one observation (`no presence`, `title differs`); remediation by the writer | grade (coded check vs prose claim, Rule-12) and harden (group failure modes, propose fences) |
| record | the run-book and its events (`<host>/runbooks/sessions.md`, `events/sessions.jsonl`) | `<instance>/audits/<date>-audit.md`; reads events through `dyad project events` |

**Owner: operate.** The check is a host read-only action producing a live observation on a service behind a
board — the run-book + health form Rule-19 and the charter's "services behind boards" already cover. Audit's
fence forbids the continuous cadence (one finding per exercise, ceiling 0). Strongest counter: a harness session
is not a `server instance` (it dies with the chat), and the store compared is the dyad's own presence store, a
process artifact — an audit-shaped drift reading. Reconciliation: the sysadmin rule's p2 admits non-server
run-books by `# sections:`; the harness side is host; the comparison is detect-only; and audit still reads the
events: its drift step grades recurrence (a seat repeatedly `stale while titled` becomes an incident-hardening
input, #409 G1). Both seats, boundary stated: operate runs and records; audit reads and grades, never on a
cadence of its own.
