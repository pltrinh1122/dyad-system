## Intent reading (revision 1)

Prompt (entry 1): the home's line "Why ask a plan at all: every row needs a plan answer before its Done, even when there is no change to make." quoted, then "we need a `dmc` for this judgement because this rules seems to promote red-tape."

| portion | class | against |
|---|---|---|
| a dmc for this judgement | new | no record decides whether a row's plan question is asked; `plan-departure`, `blocker-home`, `mandate-accretable` and `disposition-budget` each presume a plan question was asked; `read-only-answer` decides only whether a row opens |
| "this rule" | false premise, in part | the rule is not the home's paraphrase but Rule-3 Plan, verbatim: "Every plan is asked, a one-line plan included" (RULE-3 line 143). A dmc cannot outrank that sentence, so the record lands with a Rule-3 amendment and its falsification record, or it decides nothing |
| promotes red-tape | ambiguous | two readings: (a) narrow — a row whose plan authorizes nothing (no mutation, no PR, no host action, no carried row) still asks a plan-Y that binds nothing, as #687 does now; (b) wide — any row whose plan adds no information the operator did not already accept at its intent-Y (a small change fully named in the reading) asks a second question. Proposed: (a), since a plan-Y that authorizes nothing is ceremony by Rule-2's own test (a Y binds the acts its question names, and this one names none); (b) keeps the plan-Y's real job, authorizing a mutation, and is left for a row of its own if wanted |

Proposed shape of the record (`dmc:plan-question`), for the plan to fix:
- `asks` — the row will mutate: a PR, a host action (Rule-8), a carried row, a release, a preference change. The plan question is asked, as today.
- `skips` — under `intent-reading: on`, the accepted reading states no mutation and a definition of done observable from what is already on main. No plan question: the intent-Y is followed by the Done question, so the row costs two questions, not three. The plan file still holds the reading and the evidence the Done will cite.
- Out of the record: under `intent-reading: off` the plan is the first and only question before Done, so it is never skipped.
- Fences, from Rule-2: a precedent never settles `skips` (Rule-2 Binding, `dmc:precedent-scope`), so the record is judged by its inputs, not by precedent; work that turns out to need a mutation after a skip is a new plan, asked (Rule-3 Plan, departure).

Definition of done (proposed): the record `dyad/dmc/plan-question.jsonld` exists with the outcomes above; Rule-3 Plan's sentence "Every plan is asked" names the record's `skips` outcome as its one exception, with its falsification amendment; the board's phase table lets an intent-Y on a `skips` row go to `done-ready` without a plan question, so `Awaiting you` and `Coming` count it correctly; a test of each outcome. Built by engineer-1537d8fb, one agent-zone PR, core 1.3.2 → 1.3.3 (unreleased).

#687 meanwhile: its plan question stays asked. Under this record it would be a `skips` row; answering it Y now costs no further question and is the shortest path to its close.

## Intent reading (revision 2)

The operator asked: "explain the root cause.  my intent didn't yield a plan - why?" Revision 1 read the symptom (Rule-3's "every plan is asked"); the root is upstream of it.

Root cause, in order:
1. `crafts/cabinet` play-book `monitor-unit.md` step M6 makes a desk's first act "its registration row and `dyad session touch -r <row>`". The desk opened #687 itself, with the home's spawn prompt relayed as entry 1, so the row was born prompt-opened: under `intent-reading: on` that is the full three-question machine (intent, plan, Done).
2. The work that prompt asked for, spawning the desk, was #682's output and already delivered. #687 holds no work of its own: it exists only so the desk's presence has a row to claim. So the intent-Y found nothing to plan.
3. #682's plan stated no mandate scope carrying the registration row, so it could not be an accreted row closed by #682's Done, as #667 was under #666 (accreted, `Y plan (mandate #666)`, closed by #666's done-Y: zero questions of its own). And #682's Done was given before the desk spawned.
4. Rule-3 Plan then has no exit for a row with nothing to build ("Every plan is asked, a one-line plan included").

So the red tape is made at step 1 and step 3, and Rule-3 only fails to stop it.

Revised proposal (replaces revision 1's single portion):
- (A) root fix, cabinet craft zone: `monitor-unit.md` M6, and the spawn steps of the cabinet's Operating Guide it cites, open the registration row as an accreted row of the spawning row's plan, which names its class ("one registration row per desk spawned, ceiling 1"), born `open` under that plan-Y and closed by that row's Done; a desk spawned after its row's Done registers under no new row and claims its charter's standing row instead. Cabinet 0.7.0 → 0.7.1.
- (B) residual fix, agent zone: the `dmc:plan-question` record of revision 1, for any other row whose accepted reading states no mutation: intent-Y, then Done, no plan question; with the Rule-3 amendment and the board edge.
- Two zones, so two PRs (Rule-1), A first.

Definition of done (proposed, replaces revision 1's): (A) a desk spawned under a plan asks no question of its own for its registration, shown by a test of the play-book's step and the guide's sentence; (B) the record, the Rule-3 sentence and its amendment, the board edge, and a test of each outcome.
