## The defect, read against `dyad/scripts/trace.py` at 5943a1e
- **`_derive` (234–258)** turns any `user` record that is not a tool result, not `isMeta`, and not prefixed as a
  harness line into `kind: operator`. A compaction writes a `user` record carrying `isCompactSummary` and no `origin`
  key, so the summary becomes an Operator message.
- **`anchor` (333–359)** pairs each Operator message only with the **immediately preceding** record (`last_any`), and
  only if that record is a `Y/N:` reply. A false Operator record between a question and its answer breaks the pair.
  So does a harness `notify` record (a task notification) arriving while the Operator is away, which is the same
  mechanism without a compaction. The Done-`Y` then goes unanchored.
- **`intervals` (362–383)** labels the gap from a reply to the next `operator` or `notify` record. With the false
  Operator record, the Operator's real wait before the compaction is booked as an `operator` interval ending at the
  summary, and the time after it as inference. Row #286 measured 2 h 34 m 30 s of #285 misbooked this way, and 2 chains
  broken in one session.

## Mutation
- `_derive`: a `user` record with `isCompactSummary` yields a new kind `compact`. It is never `operator`, never
  `notify`, and it carries no text into the trace (the text never leaves the transcript, as for every record).
- `anchor`: the reply an Operator message answers is the **last `text` record since the previous Operator message**,
  skipping `notify`, `compact`, `thinking` and tool records in between. A real Operator message still resets it, so an
  answer never pairs with a question asked before an earlier answer.
- `intervals`: the Operator wait runs from a `Y/N:` reply to the next real `operator` record, across any `notify` or
  `compact` between. `PRIORITY` already puts `operator` first, so an overlapping background interval does not double
  count.
- Tests in `dyad/tests/test_trace.py`: a compaction between a Done question and its `Y` keeps the anchor and the wait;
  a task notification in the same place does too; a compaction summary is never counted as an Operator message (the
  `operator messages` count and the provenance match).
- `dyad/VERSION` working patch bump, shared with #240 when both are in one PR.
