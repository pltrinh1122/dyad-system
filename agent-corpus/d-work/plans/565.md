## Mutation
**PR 1, agent zone (engineer), `order: required`.** Stacked on #631 (`564-sweep`), because it extends that branch's
`dyad automaton sweep`. It lands after #564.
- The sweep gains backlog findings, read from `origin/main`:
  - **I1 untouched**: no commit has touched the row, its plan or its provenance in `HYGIENE_STALE_DAYS` (default 30).
  - **I2 malformed title**: a title shaped like a flag (it starts with `-`) or empty.
  - **I4 orphaned**: a backlog child whose `refs: parent #N` names a terminal row.
  - **I12 worked under backlog**: a commit on any `origin` branch cites `d-work #N` for a backlog row.
  - **Ranking**: TF-IDF cosine, standard library only. Each backlog row is compared with every row; pairs sharing a
    parent are skipped and tokens in more than 20% of rows dropped. The top pairs at or above `HYGIENE_SIMILAR`
    (default 0.35) are listed as candidates only.
- Output: one `notice` to home, new findings only (A6), grouped by kind.
- Constants and tests in the module, with an `INVARIANTS` entry that keeps the notice free of disposition shapes.
  Tests cover:
  - each finding on a fixture store;
  - sibling exclusion;
  - new-only on the second run.

## Placement (revision 2)
- **Where it runs:** only inside `dyad automaton sweep`, which only `dyad-sweep.yml` schedules, at 06:00 and 18:00
  Pacific. It does not run in:
  - `dyad-package.yml` (CI on push);
  - the pre-push gate;
  - `check`, `check --evidence` or `check --corroborate`;
  - the automaton's merge job.
- **Separate from the guard registry.** The hygiene findings live in a function the sweep calls. They are not a
  guard, so the runner's discovery never picks them up and CI never runs them (Rule-11 Enforcement discovers every
  guard under `dyad/guards/`).
- **Test pinning it:** a test asserts that `check` and `check --corroborate` never call the hygiene function. The
  hygiene tests themselves run in the suite like any test (Rule-12 property 1). The findings never do.
- **Order:** #564's `dyad-sweep.yml` (distribute) is this row's only scheduler. No new workflow and no new cron:
  hygiene rides the sweep run already planned.
- **A8 (new attack):** should the sweep's `check` (full suite) and hygiene be separate runs, so a red suite cannot
  block hygiene? **Survives, scoped:** hygiene runs after `check` whatever `check` returns, and both report in the
  one notice.
