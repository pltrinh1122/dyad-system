# Plan #409 — why the board says 3 live seats while the UI lists 20 sessions

## Intent as read
The Operator's screenshot of the Claude Code session list shows about 20 sessions (program, counsel,
engineer, distribute, audit, two cabinets, eleven cab-* and two terminal sessions). The board said
"0 of 3 live seats attended". Which is right?

## Answer
Both are right about different things. The board's "live" is a presence file whose `seen` is within
`STALE_AFTER` = 6 hours (dyad/guards/agent/sessions.py, advisory per Rule-16: the reader judges
freshness). Today only program, distribute and audit touched their files within that window.
Counsel and engineer last touched theirs on 2026-10-22, so they read `stale` while their harness
sessions still exist. The two cabinets run in receiving repos and cannot write a presence file in
this instance at all (distribute stated it under #345), so they never appear. The cab-* and terminal
rows are harness sessions whose seats are retired or were never seats of the m4 form.

So the sentence should have read "0 of 3 seats seen in the last 6 hours". The attendance reading
(0 attended, mode M3) is unaffected: it is derived from the provenance records, and no seat's record
holds a direct disposition.

  6 hours while its harness session lives. Conduct for the Operating Guide: touch at every reply.
- G2: a cabinet in a receiving repo has no presence file here. Either distribute writes one on its
  cabinets' behalf (breaks "only that session ever writes it", Rule-16) or the board lists cabinets
  from the mandates/rows rather than presence. Engineer intake.
