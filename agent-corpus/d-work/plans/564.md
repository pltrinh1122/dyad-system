# Plan #564 — scheduled automaton sweep: whole-store state guards out of the push gate, swept twice daily

Base commit of main: 1583614

## Intent as read
The operator asks for the guards that re-scan a whole store to move out of the push gate and out of CI on `main`, into
a read-only automaton sweep at 6:00 and 18:00 America/Los_Angeles. The gate keeps every transaction guard and the
state guards of the stores a push touches. `check --evidence` stays complete. The sweep also runs the full suite and
checks for drift outside the repo, against CI, and over time, and reports only what is new, to the home's inbox. The
operator lists two assumptions, two scheduling questions, owners and three decisions.

## Facts read at the base
- A guards-only push gate run takes **9.9 s** here (151 lines). Engineer's #561 profile: `agent/merges` 3.0 s (since
  cached by #563 C4), `agent/prs` 1.8 s, `syseng/invariants` 1.4 s, `infra/manifest` 1.0 s.
- Guard registry (`dyad check --list`): 8 transaction guards (inbox, merges, provenance, prs, rows, containment,
  sysadmin/events, …) and 23 state guards. Most state guards are package checks (rules, vocabulary, dmc, frame,
  crafts, bundle, manifest, preferences, the craft guards), not stores.
- Hosted CI on `main` already never runs on a ledger-only or events-only push (Rule-14 property 3). It runs only on
  code merges, where it is Rule-2 Binding's after-merge corroboration.
- GitHub added a `timezone` key to `on.schedule` (changelog, late March 2026), taking an IANA zone and following DST.

## Recommendations on your three decisions (bound by this plan-`Y`)
1. **12 hours**, as proposed: the same cadence as the schedule, and A4's protection means no merge depends on it.
2. **Notify only.** A release cut already runs every guard in its done-`Y`'s evidence and fences the cut, so a red
   sweep cannot reach a release. Holding cuts on a red sweep would add a second gate that guards nothing extra.
3. **Yes, the sweep runs the full suite** (A8).

## Scheduling
- One workflow with `schedule: - cron: '0 6,18 * * *'` and `timezone: 'America/Los_Angeles'`.
- The job also prints its Pacific hour, so a fall back to UTC evaluation is visible in its log. If the key were
  ignored, both sweeps would run 8 hours early, and A6's age check would still pass.
- It runs from the default branch only, which is where it belongs.

## Counter and reconciliation
- Counter: the saving is seconds per push, and the price is a new standing mechanism and a 12-hour blind spot for
  whole-store drift.
- Reconciliation: the seconds land on every one of the many ledger pushes a day. The blind spot never reaches a merge
  or a release, because every done-`Y`'s evidence runs every guard. The sweep also adds checks the gate never had
  (outside-repo drift, missing CI, time-based staleness). Engineer measures the gate saving first; if it is under
  3 s, the gate split stays out of the PR and only the sweep ships.
