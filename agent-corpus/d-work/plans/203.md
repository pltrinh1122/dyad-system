# Plan #203 — reduce `dyad/tests/` by overlap, irrelevance and fail-loud checks at strategic points

*Rule-15 phase 1. Base commit of `main`: 8dc883c (2026-10-02). refs: 186 199 163 162 202.
Drafted by a delegated sub-agent (read-only; `delegation: plan-and-execute`). Every count below was
observed at the base commit: loader counts from `unittest` discovery without running, and per-test
seconds from one targeted run of the 52 candidates (`--durations 0`). No root was hand-run (Rule-12 p2).*

## Intent as read
The Operator asks for fewer tests in `dyad/tests/` through three channels, each reduction keeping
its check somewhere:
1. **Overlap.** Two checks fail on the same defect. One of them is deleted or merged into the
   other.
2. **Irrelevance.** The subject of a test no longer exists, or its pin has been superseded. The test
   is deleted.
3. **Fail-loud checks in the code under test.** A check that is neither a test nor error-handling
   sits in the target code. A test that exists only to exercise that condition then goes.

**Two readings of (3).** The plan states both before settling.
- **A.** The existing protocol already is channel (3): `INVARIANTS` (Rule-12 p1, syseng
  `invariants.md`), run by the runner's pass and at two mutating call sites, never at import. On
  this reading (3) only moves constant-shape tests into existing lists. No Rule changes.
- **B.** A new check that runs in the code itself, at import or on every use. This reverses
  `invariants.md` p1's "never at import", which was the survivor of #162 attack 1. It therefore
  changes the syseng invariant protocol and Rule-12 p1.

**Settled by the Operator (2026-10-02, relayed in-session; the main Agent records the words).**
- **Reading B, verbatim:** "A new fail-loud check in the code itself: one that runs at import or on
  every use, which would change the syseng craft's invariant rules. this is what i meant".
- **Refinement, verbatim:** "yes, and therefore strategic use is required. for example,
  boundary-checking or state transition, "impossible conditions" that a current test is exercising
  would no longer need to be tested."

**The selection criterion for channel (3) follows from that refinement.** A fail-loud check goes
only at a strategic point:
- **where:** a boundary, a state transition, or a condition that should be impossible;
- **how often:** the point is passed once per process (at import) or rarely (once per
  disposition, once before a host command);
- **never** on a hot path (per row, per file, per path).

**Tests on either side of the line:**
- **Goes:** a test that only exercises such a condition. The check at that point replaces it.
- **Stays:** a test that verifies behaviour (outputs, messages, side effects, a guard's verdict over
  a fixture).

## Constraints of the refactor

- **Rule-12 p1:** the code carries its mechanical check. An invariant counts, and after P2 the

- **`syseng/tests` mapping:** no test file is deleted; only classes and methods go. The guard's

## The protocol (what P1–P3 write)
- **Two lists.**
  - `INVARIANTS` holds pure predicates over the module's literals: no filesystem, git, module
    loading or environment. The module ends with `dyadlib.enforce(INVARIANTS, __name__)`, a
    module-level call that runs them at import and raises `InvariantError` naming every false
    one. There is no off-switch: an env knob would turn fail-loud into fail-optional.
  - `TREE_INVARIANTS` holds the predicates that read the package tree or load modules (the
    references seven, package's two, craft's one, the projectors' register ones). These never run
    at import; they run in the runner's pass and at the existing call sites, as today.
  - The pass keeps reporting both lists as `[invariant]` lines (coexist, never replace), so the
    evidence still names every invariant.
- **The strategic-point criterion**, written into `invariants.md` p1 in the Operator's terms.
  - A fail-loud check is warranted at a boundary, a state transition or an impossible condition,
    placed where control passes once per process or rarely, never on a per-item path.
  - A test that only exercises such a condition is redundant with the check. A behaviour test is
    never converted.
- **Guard.**
  - (iii) accepts `TREE_INVARIANTS` with the same shape rules.
  - New (iv): every module under `dyad/` that declares `INVARIANTS` has the module-level `enforce`
    call (checked by `ast`, never grep). P1 lands it as a warning and P3 makes it fail; it stays a
    warning for `crafts/` modules until a craft follow-up.
  - New (v): one child process imports each pass module and runs its `INVARIANTS` under an audit
    hook that records `open`, `os.listdir`, `os.scandir`, `subprocess.Popen` and `import`. Any
    event fails: "invariant `<name>` does I/O; move it to `TREE_INVARIANTS`". Environment reads
    raise no audit event, so that classification stays inference, stated. `sessions`'
    `writer-is-well-formed` reads a value made at import from `uuid4`, is always true by
    construction, and stays pure.
- **`require_transition`** is the template's worked example of a check at a state-transition
  point: one function, one call site, before the one write.
