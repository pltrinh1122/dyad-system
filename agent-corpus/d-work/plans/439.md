# Plan #439 — fix the refs clobber in `dwork state <id> done`: rename, test, restore the 28 rows from history, a fence on the refs value's shape

## Intent as read
Intake D4 from engineer-1537d8fb, a defect with evidence (Rule-3 Intake), opened by the Operator's `Y`. The close
path of `dyad dwork state <id> done` overwrites the row's `refs` with a list of git branch names whenever the
landing check runs; 28 `done` rows on `main` carry that list in place of their references. Fix the code, pin it with
a test, restore every damaged row from its own history, fence the shape so the next such write is refused where it
is born, and record the incidents. The Operator's `Y` was to this shape (D4); this plan states it as executable.

- **Why nothing caught it.** `rows.py`'s fence admits a `refs` change on any commit (its docstring: "may only add
  a file or change state/disposed/refs"; `dyadlib.allowed` admits same-state edits). `references.py`'s
  `row.refs->row` kind reads ids through `hash_ids`, which collects only `#N` tokens, so `['origin/main', 'main',
  'HEAD']` resolves to nothing and fails nothing. The #202 test that exercises exactly this path,
  `test_dwork_done_state_follows_the_merge` (`dyad/tests/test_package.py:723`), closes on a resolvable head and
  asserts the state, never the refs.
- **Who saw it.** counsel-0032b4c0 on #433's close, restored by hand before committing (main 197f516), and reported
  it; the engineer seat verified the mechanism.

## Mutation (no mandate scope: accretes nothing)
1. **Agent-zone PR — the fix.** `dyad/scripts/package.py`: the landing loop of the `state … done` path moves into
   `landing_refusal(rg, done_entries)`, its branch list named `branches`; the close path keeps the row's `refs`
   unless `-r` is given. Test in `dyad/tests/test_package.py`: a row with `refs: 7 parent #3` closed on a `Y done`
   whose head is `HEAD` keeps `refs: 7 parent #3` (and `test_dwork_done_state_follows_the_merge` gains the refs
   assertion it lacked).
2. **Ledger-only commit to `main` — the restore.** A one-off script in the main seat's scratchpad, never committed:
   for each row with `refs: ['origin/main', 'main', 'HEAD']` on `main` at that moment (re-derived, not this list
   pasted), find its one introducing commit `<c>` by `git log -S`, read `refs:` from `<c>^`, assert the current value
   is exactly the bad list, and run `dyad dwork state <id> done -r '<restored>'`. Then `git diff` must show only the
   28 `refs:` lines; one commit citing d-work #439, its message listing every row and its restored line (the table
   above, re-derived). The fence admits it (attack 2). This lands **before** the agent PR's evidence run, so (3)'s
   state clause reads a clean store.
3. **Agent-zone PR (same) — the fence.** `dyad/guards/agent/rows.py`: `refs_shape_problems` in `check_commit`
   (added or modified row whose `refs` changed and holds `[ ] ' " ,`) and in `check_merge` against each parent; a
   `[`/`]` clause in `check_package`; the module docstring's sentence on refs updated. `package.py`'s `-r` check
   refuses the same characters. Tests in `dyad/tests/guards/agent/test_rows.py`: a commit writing
   `['origin/main', 'main', 'HEAD']` fails; one writing `202 321 parent #5 PR #9` passes; a commit not touching a
   legacy comma refs passes; the package check fails a bracketed refs.
4. **INCIDENTS.md rows** (`agent-corpus/audits/INCIDENTS.md`, ride the agent PR, the file's one-row-per-incident
   convention, several d-works in one cell as its #412–#414 row does): (a) #433 — counsel found its close's refs
   overwritten, restored by hand before committing (197f516); (b) #417, #427, #431 — the program seat's closes wrote
   the bad refs to `main`; (c) #412, #422, #423, #424 — the engineer seat's closes, likewise; (d) #202 … #395 — the
   21 closes of 2026-10-15 to 2026-10-24 by the seats then closing, the mechanism born in #202's own close. Every row
   names the mechanism once and cites #439; cause classified for the next incident-hardening exercise as **mode J
   primary** (a call site added without its call graph: the #202 loop rebinding a name the enclosing verb reads
   later) and **mode Q secondary** (an obligation no mechanism reads: no guard read the shape of `refs`, and the one
   test of the path never asserted it). counsel's #433 stray-presence row is **already on main** (the file's last
   row, "`dyad session touch --help` wrote a presence file …"), so it is not re-added.
5. **Evidence.** `dyad check --evidence` on the agent PR's exact head, pasted verbatim; the restore commit's sha and
   listing; the bracket scan of `main` re-run immediately before the merge (expected 0), and its result.

Sequence: (2) restore → rebase the agent PR onto it → (5) evidence → Done question naming the PR → merge → close
#439 on the fixed code.
