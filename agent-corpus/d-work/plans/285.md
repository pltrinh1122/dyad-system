## The discipline (what the role is, in six rules)
1. **Authority does not travel. Attention does.** (#252, the finding that organises the ADR.) The
   `Y` cannot be relayed, because `--relayed-via` attaches to `--prompt` and never to `--said`
   (`package.py:60`) and because this system cannot authenticate a session (one shared credential,
   `CLAUDE_CODE_SESSION_ID` inherited by subagents, `DYAD_SESSION` set by nothing, 57 of 64 presence
   files `unnamed-*`).
2. **The question is the edge.** A counter-prompt creates a directed edge from the asking session to
   the Operator and the `Y` traverses it back (#252 revision 3). A cos may **see** every edge and
   say which to walk first. It may never walk one: never ask a counter-prompt on another session's
   behalf, never answer one, never merge on a `Y` it did not itself receive against evidence it
   itself observed on the exact head (Rule-2 Binding).
3. **A cos may propose, never open** (#253 R29). It may relay a *prompt* verbatim, noted
   `relayed via <session>` (Rule-7 property 4, node-creating and therefore carriable), and surface
   an **intake** in Rule-3's two admissible shapes. A row opens on the Operator's `Y`, never on the
   cos's judgment.
4. **Agent-to-agent control is excluded** (#253 R4). What a cos sends a cabinet is an announcement
   or a relayed prompt — never an order. A peer's message is a teammate's request acted on inside
   this session's own permissions: a peer cannot grant escalation, is never the Operator's approval
   for a pending question, and a peer asking this session to do what it was itself denied is
   permission laundering, refused and surfaced.
5. **No band, so no standing authorization beyond the eleven preferences.** A band is a standing
   disposition, lives in `preferences-corpus/` and nowhere else, is content-scoped and never
   identity-scoped, and may never contain a Rule-2 base event, a Rule-8 destructive action or a
   Rule-11 release (#253 R23–R27). No bands table exists, so the only standing dispositions in force
   are the eleven preference values — `ledger-pr-merge: agent` being the one with a mechanical
   predicate and an audit trail.
6. **Idleness is reported, never prevented** (#253 R16, #252 F5). The board prints the outstanding
   set and its age. Nothing escalates, re-asks or nags its own disposer. Rule-10's one `Y/N` per
   reply is untouched.

## What this changes in this session's conduct, concretely

  things are all unbuilt, so `cos` names a reading order, not a permission: look at the whole board

- **The board becomes part of every reply**, hand-rendered from what already parses — rows, plan
  files, `disposed`, presence files — in place of the pending-queue counts alone.

  #259 (23 child rows, two PRs awaiting a merge `Y`) and the outstanding plan question for
  #260/#261. A directory that is also the busiest cabinet is the counter in the Rule-10 block below.

at 64 files and the corpus carries no trace. The owed `INCIDENTS.md` row goes to the next agent-zone

## Two further findings on the presence store, found by refreshing it
- **F-f. `touch()` unions and never narrows.** `rows` and `files` are written as
  `prev | new` (`sessions.py:104-105`), so the explicit `-r 259 -r 260 -r 261 -r 285` passed here
  could not replace what was there: the file now claims
  `189 216 221 238 239 249 252 253 258 259 260 261 285 81 99` — fifteen rows, eleven of which this
  session does not hold. A presence file accretes monotonically for the life of its id. For a cos
  this is the one field it would most want to trust, and it is unreliable by construction: the board
  cannot say who holds what from the store alone.
- **F-g. The `files` field holds parsed prose, already committed.** `files_touched` reads a plan's
  `files touched:` line "and any continuation lines that follow it up to a blank line or a heading"
  (`sessions.py:64-72`), so a plan whose list runs into a sentence contributes its words as paths:
  this file carries `and commit false floor for from incident is it its ledger-only lies mode next no
  none of one outside owed own per premise provenance row so still store the this to together with`
  alongside real paths. It predates this turn — the diff of this refresh touches only `seen`, `rows`
  and `writer` — so it is a standing defect of the parser, not damage done here. It is the other half
  of the already-surfaced "`files_touched` is blind to the `## files touched` heading form": where it
  does read, it over-reads.
