# Plan #91 — drift guard: a craft's tree at HEAD vs its last release tag

Base commit of `main`: e763fe3. Refs #61 (sysarch, found by surfacer), #67 (dyad-operator +

## Intent as read
Rule-11 property 4: a release tag equals `<name>-v` + the craft's `VERSION`. Nothing checks the
converse — that once `<name>-v<VERSION>` exists, the tree under the craft's root at HEAD is the
tree that tag holds. Every case above is exactly that: tracked content changed under an unmoved
`VERSION`, so the next bundle shipped an archive under a version number already released with
different content. The by-hand sweep (`git diff --stat <tag>..HEAD -- <root>` per craft) caught
#71's case only because a peer reported it and missed #90's until a rebuilt sha was compared to a
published asset. A guard on the kernel-only path refuses the *push* that creates the drift.

## Mutation
- **Agent zone, one PR.** `dyad/guards/infra/bundle.py` gains `check_drift(root, pkg)`, run from
  `check_package` after the row check: for every live component (core: `dyad/`, tag

  difference is `FAIL 'dyad-operator': dyad/ differs from dyad-operator-v0.6.2 (<n> files) while

  kernel-only path never fetches; CI's full-depth checkout has the tags and corroborates.
  Consequence stated plainly: the first craft-content commit after a release must bump that

## Falsification
- "Belongs in `craft/crafts` (the craft's shape), not the bundle guard" — refuted: the bundle
  guard already owns "row version == live VERSION" and is the one place that knows every
  component and the tag prefix rule; the craft guard runs per craft with no notion of release.
  Registered by discovery, one module — no hand-listing (Rule-11 Enforcement).
- "Stale local tags make it lie: a tag fetched yesterday is checked against today's HEAD" —
  survives, scoped: a stale tag is *the* tag (tags do not move); the only staleness is a tag not
  yet fetched, which skips with a line. The push that creates a tag is the Agent's own.
- "Too strict: every doc typo in a craft forces a version bump" — survives, stated: that is the
  property. A released version names a tree; a different tree is a different version. Patch
  bumps are cheap; the four incidents were not.
- "Check the working tree so `dyad check` catches it before commit" — refuted: HEAD is what a
  push carries and what the pre-push hook judges; a dirty tree is Rule-14's `dirty=` flag.
