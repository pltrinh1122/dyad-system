# Plan #213 — codify the d-work trace as a play-book and run-book

*Rule-15 phase 1. Base commit of `main`: 718d8e3 (2026-10-05). refs: 212.*

## Intent as read
Make the per-d-work performance trace (#212's format) repeatable: a core play-book saying when and
how a trace is made and read, a run-book whose steps run it through the core runner, and the code
those steps call. #212 then produces its traces with this tool instead of a scratchpad script
(#212 revision 2).

## Mutation proposed
One agent-zone PR, all under `dyad/`, citing d-work #213.

1. **`dyad/scripts/trace.py`** — new, core. Reached as `dyad dwork trace <id> [--transcript <jsonl>…] [--out]`.
   - **Reads:** the row, provenance and plan file; git commits and merges that cite `d-work #<id>` or
     touch `<instance>/d-work/*/<id>.md`; and one or more harness transcripts.
   - **Transcript handling:** read in place, never copied (Rule-7 property 2). The default path is
     derived from the working tree's `~/.claude/projects/<slug>/`, which is a Claude Code layout
     (Rule-14: kernel row "Claude Code"). With no transcript found, the trace still writes its
     git- and ledger-only parts and says the time buckets are absent.
   - **Anchors:** each provenance entry is matched verbatim to its user message in the transcript.
     That gives exact timestamps for the prompt and each disposition. An unmatched entry is reported,
     never guessed.
   - **Prints:** #212's format — timeline, buckets, counts, bottleneck line, limits.
   - **Writes:** with `--out`, `<instance>/audits/traces/<id>.md`. Without it, stdout.
   - **Invariants:** an `INVARIANTS` list enforced at import (syseng `invariants.md` p1): bucket names
     unique, every bucket in exactly one partition.
2. **`dyad/tests/test_trace.py`** — fixture transcripts and a fixture ledger, never this session's.
   Covers: anchoring, buckets summing to the window, overlap shown once, the no-transcript path, an
   unmatched entry reported.
3. **Play-book `dyad/playbooks/dwork-trace.md`.**
   - **Trigger:** a d-work is done-ready.
   - **Default:** trace it, with the trace path cited in the completion evidence.
   - **Reading:** how to read the bottleneck line and compare with the median of traced d-works.
   - **Evidence.**
4. **Run-book `dyad/runbooks/dwork-trace.md`.**
   - **Sections:** Locate, Trace, Compare. Each is a `dyad-cmd` step, read-only except Trace with
     `--out`, which writes one instance file (undo: delete it).
   - **Parameter:** the id, as `DWORK`, in the incident-hardening run-book's manner.
5. **Rule-3, Completion counter-prompt.** One bullet: the completion evidence cites the d-work's trace
   (`dyad/playbooks/dwork-trace.md`). A play-book is "read by a Rule, never a Rule" (vocabulary), so
   this is what makes it binding. Also:
   - **Falsification record:** amendment #213 to `dyad/falsification/rules/rule-3-d-work.md`, with the
     pairwise coherence statement (Rule-5).
   - **Vocabulary:** new term `d-work trace`, owner 3, used by 3.
   - **Tests:** `test_playbooks.py` gains the play-book's sections and its Rule-3 citation.
6. **Not here:**
   - Promoting the suite-only checks that #210 and #211 found to guards — a separate row if wanted.
   - Committing any transcript.

## Falsification
- **Attack: a core command depending on Claude Code's transcript layout breaks on another kernel.**
  Confirmed. Rule-14 allows "another CLI inferencing agent". Survivor: the transcript is an optional
  input. Without it the trace degrades to git and ledger events, and says so. It never fails.
- **Attack: tracing every d-work adds cost to each completion.** Measured as a limit: one parse of a
  40 MB transcript is seconds, not a suite run. Accepted; this is what the Operator asked for
  ("for each d-work").
- **Attack: a trace inside the completion reply cannot contain its own Done-`Y` or merge.** Confirmed.
  The trace stops at the Done question and says so. The tail is two clerical PRs, visible in git.
- **Attack: matching provenance to the transcript fails on a disposition like a bare `Y`.** Partly.
  Dispositions are matched in order after the plan question's reply. Text that repeats is matched in
  sequence, and an ambiguous match is reported as such.
- **Attack: a Rule-3 change under a "codify" prompt widens scope.** Considered. Without a Rule citing
  it, the play-book binds nothing (vocabulary), so the citation is the codification. If the Operator
  wants it unbinding, drop item 5 and the play-book becomes reference only.
- **Presence:** no other live session names these files.
