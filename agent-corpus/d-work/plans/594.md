## Intent as read
- **The defect (#546 F2, S13).** `board.resume_view` takes every file in `<instance>/d-work/board/` but `_cos.md` as
  live and re-presents every `waiting-on: operator` question. One `_cos.md` serves every leader, so with two operators
  A's new leader is shown B's question. The sim pins it (`test_seat_hops.py` `KNOWN_GAPS["S13"]`, `test_S13`).
- **Why now.** 1.0 freezes the store format. In `dyad/surface.md` the board entry row (line 76) is `frozen` and the
  cross-row row (line 78) is `moving (#572, #573)`; this PR proposes the new cross-row path form and a new cabinet value
  row, both `frozen`. Revision 6 puts #548 in because the layout is on the surface.
- **What a cabinet is.** One operator's leader and the board it keeps. naming.md §2: `program-<hp>` is the cos,
  `program-<operator>-<hp>` a member pair's leader. `sessions._seat_key` strips `-<hp>`, so the key outlives a hop:
  `program` (solo, and every seat under `flat`) or `program-<operator>`.
