## 2. Consolidation plan
Archiving a session is a hosting action, Rule-8 **reversible**: its undo is `unarchive_session`. Only the cos can
make it, since a seat cannot archive another session. Terminal sessions are not cloud sessions: the Operator closes
those in the terminal, and the cos only relays which ones.

Order, smallest risk first, each batch its own named question relayed by the cos:
1. **Batch A, done, stale and never registered (9):** cab-2-8c27a6fd, cab-5-5fdc4e6e, cab-6-216584db, cab-7-d1dda11f,
   cab-3-242a5502, cab-4-92e3d665, cab-9-351fc81e, distribute-asg-23c0c51b, distribute-client-0976dc97 — nine
   sessions, every row they ever held `done`. Archive. Nothing is lost: their records are on `main`.
2. **Batch B, distribute-b7a0a9fc:** a charter seat with nothing open. Archive it; the cos opens a fresh holder of
   the distribute seat when a distribute row next needs one (Guide §3). Kept separate because it is a charter seat.
3. **Batch C, neglected (4):** audit-89a934d6, cab-8-23d654aa, and the terminals cab-1-e2c6869c and
   cab-11-486a95b2. Each holds rows that are still `planned` or `open` — #336, #346, #348, #350, #401. Archiving a
   session moves no row: the rows stay on the cos's board, unheld. So before batch C the cos asks the Operator,
   row by row, whether each is re-homed to a live seat, kept planned unheld, or retired. A `planned` row cannot be
   archived: Rule-16's table gives it only `open`, `blocked` and `done`. Then the sessions are archived, the two
   terminals closed by the Operator.
4. **Titles.** Every surviving session's title takes the seat form `dyad session name` prints. Today all four live
   seats do, and `operate-8cce8b10: cloud (ds)` lacks only the harness's own suffix, which reconcile ignores (#434).

After the three batches, 4 sessions stay open: program, counsel, engineer, operate.

## 3. The play-book
A run-book in operate's zone, the `sessions` run-book gaining a section `Tidy` with one read-only `dyad-cmd`
command, `census`, and the north star stated as its pass criterion:

> **North star:** the only sessions open are live seats and live desks. A session is archived when every row it
> holds is `done` and its presence is past the window, after the cos relays the Operator's `Y` naming the batch. A
> desk is closed by its secretary when its topic's rows close.

- **Command.** `census` composes what exists today: `dyad session reconcile`, then `dyad session list`. The join to
  the classes above is read by the Agent against this plan's table, stated as inference. That is this plan's first
  run of a recurring task by hand. Rule-13 property 1 makes the second run propose code, a `dyad session census`
  verb in the engineer's zone; that row is outside this mandate and is proposed then, not built here.
- **Cadence.** At session start and on the program's request, as the health command after #438.
- **Output.** A census goes to operate's board as one line per class with its sessions, and a consolidation
  proposal goes to the cos as batches in the order above. Operate never archives, retitles or touches another
  seat's presence. The writer remedies: the cos archives and retitles, a seat touches its own file.
- **Record.** A census is a reading. Under #438 an event is written only when the reading changes.
