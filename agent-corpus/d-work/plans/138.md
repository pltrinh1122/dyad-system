## Findings (scoping workflow `wf_70de145a-a4c`: 13 agents, read-only on the repo, all probes in the session scratchpad)
- **Count.** `scratch()` runs 19 times per module run: 1 in `setUpClass` (L46), 14 in `setUp`
  (L53), and 4 in test bodies (L92, L117, L150, L156). #110's record says 5 in-body callers; there
  are 4. Each call costs about 0.9s: a real `package.py install` subprocess, then `git add` and
  a signed commit. 3 of the 14 `setUp` repos are never used (`test_list_authored_and_core`,
  `test_check` and `test_export_name_entries_and_determinism` read only `cls.src`).
- **Root cause, one level down.** In a cProfile of one install (n=1), 0.775s of 1.018s went to
  `dyad/scripts/distribute.py` L204–206, which runs one `git update-index --add --chmod`
  subprocess per file (about 150). That is production code on Rule-11 p5's one code path, so it
  is out of this scope. It is listed as a finding below.
- **Copy fidelity (measured).** Compared with a fresh install, a copy has 0 differences in path
  set, bytes, modes, `.git/config`, `ls-files -s`, `HEAD^{tree}` and `status --porcelain
  --ignored`. No absolute path appears anywhere, `.git` included: core install writes none and
  never sets `core.hooksPath` (`package.py` only prints the hint). The copy differs in four
  ways: every copy shares the template's HEAD sha, inodes and ctimes are new, directory mtimes
  are the template's, and the index stat cache starts stale. No test reads a sha, an inode, a
  directory mtime or stat-sensitive plumbing.
- **Five candidate forms compared** under this host's git config, under git defaults and under
  umask 077:
  - `copytree(copy_function=shutil.copy)` + `git update-index --refresh`: the only form equal to
    a fresh install on every property checked.
  - Plain `copy2`: leaves 150/150 stale index entries under `checkStat=minimal`.
  - `git clone --local`: writes the template's absolute path into `.git/logs`, adds an
    `origin/<branch>` that can switch on the transaction guards, and changes 144 file modes
    under umask 077.
  - tar snapshot: `copy2` with more moving parts.
  - Rejected without measuring: hardlinks (install truncates the shared inode in place) and
    `git worktree` (it shares objects and refs).
- **Three designs, three judges.** "Risk-first" won 26.5 / 23.5 / 19.5. It adds one lazy,
  private template behind `scratch()` and changes only the helper block. The class hooks and all
  15 test bodies stay byte-identical. It takes grafts from the other designs: a `_MADE` registry
  torn down in `tearDownModule` even when a test fails, an `atexit` backstop, and a
  `dyad-craft-template-` prefix. Two of the three judges reproduced a bug in the smallest
  design: its teardown does not reset the template, so re-entry hits a deleted path.
- **Prototype (monkeypatched from the scratchpad, no repo edit).**
  - Tests: 15/15 pass, including in alphabetical, reverse and 4 shuffled orders.
  - Installs: real core installs drop from 19 to 1. All 18 real `dyad craft install`
    subprocesses remain.
  - Time: 25.8s / 27.1s → 13.9s / 13.4s. That is n=2 per arm on a shared host; three
    independent measurements agree on about 2×.
  - Cleanup: 0 temp dirs left after a passing run or an injected failure. The original leaks 1
    on failure.
- **Adversarial verify (3 lenses: isolation, intent-fidelity, robustness): all survive.**
  Required changes, all taken below:
  - Raise `AssertionError` explicitly instead of using `assert`, so the fidelity check survives
    `python -O`.
  - Merge `import atexit` into the top import line.
  - The docstrings say one real core install runs per module run and name `test_package.py` as
    where the real install is tested (not `test_distribute.py`, which never runs it).
  - No docstring invites direct calls to `_install()`.
  - Report the timing as a host-specific ratio.
