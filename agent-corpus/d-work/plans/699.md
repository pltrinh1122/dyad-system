## Plan
**Intent as read:** the reading above, with the intent-`Y`'s addition: the canon is the bridge from go-to-market to the
roadmap. A symptom the dyad-system does not serve yet is a candidate row of work, never a row by itself (Rule-3: only
the operator opens rows).

**Mutation.**
- **Craft PR** (craft zone, chronicle; `VERSION` stays 0.5.0, untagged, as #696's):
  - `crafts/chronicle/dmc/collateral-symptom-canon.jsonld`. Inputs: the candidate symptom and the tree node it comes
    from; the canon so far. Outcomes, in order:
    - `cause`: it names why, not what is seen; it stays a node of its tree;
    - `unrooted`: it reaches no problem class;
    - `unsourced`: no source or reference tree holds it, and no reader evidence;
    - `restated`: it rewords a node already beneath another entry;
    - `duplicate`: it is an entry's symptom in other words; it joins the entry, adding its source;
    - `canon`: it enters, its plain wording judged by `collateral-problem-plainness` at its proficiency.
  - `crafts/chronicle/scripts/symptom_canon.py` with `crafts/chronicle/tests/test_symptom_canon.py`: the coverage
    check. Every top-level symptom of every tree in the canvas set is an entry's source or a recorded exclusion with
    its outcome. Every entry's source resolves to a tree node. Every `served` or `partly` cites a path that exists.
    The wording and the outcome are inference, made once per symptom; coverage is code (Rule-13).
  - `crafts/chronicle/rules/collateral.md` §5: the canon, its record, its two readings; falsification rows for
    C1–C7 and R1–R3 below.
- **Infra PR**: `site/lean-canvas/symptoms.md`, seeded from the trees on `main` once #696's infra PR has landed (its
  two target trees, the hallucination reference, the three reference trees) and from the `platform-ops` and
  `regulated-engineering` source trees already there. **order: required**: this PR follows #696's infra PR, whose trees
  it reads.
