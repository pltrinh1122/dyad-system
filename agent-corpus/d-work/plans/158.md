## The defect that must land first
`cmd_guards` returns at `package.py:360` — `skip [guards] transaction guards: no <base>` —
**before** the suite gate #155 added. So in any system where `origin/main` does not resolve (a fresh
install, a system with no remote, one whose default branch is not `main`), the pre-push hook runs
the package checks, skips the transaction guards, and **never reaches the suite at all**. The
headline of this release is inert exactly where a new downstream installation starts.

## Mutation (what a plan-`Y` authorizes)
One agent-zone PR, branch `agent/158-gate-reachable`:
1. `dyad/scripts/package.py` — move the suite gate above the base-ref check, and when the base does
   not resolve run the suite rather than skip it: an unknown range cannot be shown to be
   ledger-only, and the safe default for a gate is to test. The transaction-guard skip line is
   unchanged.
2. `dyad/tests/test_package.py` — its check: with a base ref that does not resolve, `cmd_guards`
   still runs the suite and still prints the transaction-guard skip line.
No `VERSION` bump: 0.9.0 is unreleased, so this change joins it rather than superseding it. No
`BUNDLE.md` change: its rows already match. No Rule, vocabulary or preference change.

practice wrote for itself in #106: a release publishes to the world.

## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | The release needs no code change: cut the tags and be done. | **Refuted** | It would publish a feature that never runs in a fresh install, which is the case the Operator's own reason names. The tags are cheap to cut and impossible to move (Rule-11 property 4); shipping the gap and fixing it in 0.9.1 spends a version number on a defect found before the release. |
| 2 | Then the fix is bigger than "move three lines": a system with no `origin/main` now pays ~40 s on every push. | **Survives, scoped** | It does, and that is the safe direction: a gate whose range cannot be established should test, not wave through. A system that wants the cheap path has `DYAD_INSTANCE` and a resolvable base; one that has neither is a fresh install, where the suite is exactly what a first push should run. |
| 3 | "Greatly benefit the downstream installations" — measure the claim. | **Survives, scoped** | For a downstream system the gain is what #154 measured here: the suite at 40 s instead of 120 s by hand, and a push-time gate where there was none. The size of the gain depends on that system running tests by hand today, which this instance did 134 times in a session and another instance may not do at all. The honest claim is "the gate exists and the cheap path is reachable", not a number. |
| 4 | Releasing mid-stream is unsafe: another session is actively changing the tree (#152, `countersign`). | **Refuted, scoped** | A tag names a commit, not a branch; a later commit cannot disturb it. `countersign` stays out of this release by #156's own amendment — unreleased crafts may be absent from the bundle — and its release belongs to the row that owns it. |
| 5 | 0.9.0 should become 0.10.0: #155 adds a verb and changes what a push does. | **Refuted** | 0.9.0 has never been published, so nothing downstream has ever seen it; a version number is spent when it is released, not when it is written.
