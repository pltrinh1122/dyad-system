## Intent as read
- **What happened.** On #573's cut the automaton merged #642, #651 and #652 in one push (#562 (a), one push per cut).
  Corroboration then failed with `rule-1 containment (push range) FAILED [range ba004ff..145206c]: touches multiple
  zones: agent preferences`. Reproduced at the base:

  ```
  $ python3 dyad/guards/infra/containment.py range ba004ff 145206c
  FAIL [range ba004ff..145206c]: touches multiple zones: agent preferences
  ```

- **Why.** `check --corroborate` runs containment's `range` mode, which judges the PR transaction: each commit plus
  the whole diff, over `before..after`. That fitted a push to `main` holding one PR. Since #562 a push can hold a cut
  of several PRs, each a transaction of its own, and Rule-1 binds a commit and a PR, never a push range (#166).
- **The fix.** Judge each merge commit's PR range (first parent to second parent) in `range` mode, and the push's own
  non-merge first-parent commits in `commit` mode.

## Mutation (engineer, one agent-zone PR, tagged v1.0.0)
- **`dyad/guards/infra/containment.py`:** a new mode `landed <before> <after>`.
  - For each first-parent commit of `before..after`, oldest first:
    - a merge is judged in `range` mode over `p1..p_n`, for each non-first parent;
    - a non-merge is judged in `commit` mode.
  - It prints one `ok [landed] <subject's PR or sha>: <zone>` line per merged PR, and the fails otherwise.
- **`dyad/scripts/package.py` `cmd_corroborate`:** the push-range step runs `landed` in place of `range`, and its
  name becomes `rule-1 containment (each PR the push lands)`.
- **Tests:**
  - a two-zone cut of two single-zone PRs passes, with one line each;
  - a cut holding one cross-zone PR fails;
  - a direct non-merge two-zone commit fails;
  - `range` over the same cut still fails, unchanged;
  - corroboration's step name.
- **Verification for the DoD:** run `containment.py landed ba004ff 145206c` and the corroboration step on live `main`.
- Mandate scope: none of its own. Host actions: none.

## Counter and reconciliation (Rule-10)
- **Counter.** Keeping `range` and landing one PR per push would also pass. That undoes #562 (a), one push and one
  gate per cut.
- **Reconciliation.** Rule-1 never bound a push range (#166). Judging each landed PR is the same check the PR would
  get on its own, so nothing is weakened, and the cut keeps its one push.
