## Intent as read

nowhere else. Rule-3 Incidents puts an incident row in `agent-corpus/audits/INCIDENTS.md`, written in

is the same route by which #301's incident I3 row landed, in #216's agent-zone PR, earlier today.

What this row does **not** do: fix any of the five mechanisms. Each is a `detect, don't dispose`
finding whose fence belongs to the row that owns it — #202 for I4, Rule-20 property 2 and
`dyad/guards/agent/sessions.py` for I7's two observations, `dyad/scripts/package.py` `cmd_tests` for
I8. The incident log is the input to the incident-hardening play-book
(`dyad/playbooks/incident-hardening.md`), which groups a ledger by failure mode and closes each one;
an incident recorded only in a plan file is invisible to it. That is the whole value here.
