Proposed record, `dmc:audit-trigger` (mechanical, read from the sweep report's existing lines):
- A1 code moved: `reading: audit watermark: … changed` (the code tree, Python or git differs from the newest audit record). Due.
- A2 incidents unhardened: `finding: hardening: … holds rows past the watermark` by at least a fixed count, 10 (this record's, not a preference), so a single incident does not call an audit. Due.
- A3 Rules unswept: `finding: audit drift: dyad/rules/ changed after the newest Rule-5 sweep record`. Due (the Rule-5 sweep part).
- A4 release: a release tag published since the newest audit record. Due.
- not-due: none holds, or the same condition set was already posted (one notice per state, folded like the sweep's other findings).
The sweep posts `audit due: A1, A3 …` to the home's inbox once per changed state; the home asks the question; nothing runs on a clock.
