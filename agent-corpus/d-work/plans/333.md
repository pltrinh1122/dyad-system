# Plan #333 — an audit of where the Agent spends tokens, and which frequent acts code should take

*Rule-15 phase 1. Base commit of `main`: b68fe43 (2026-10-17). refs: 331 161 154. Seat
`ds-cabinet-cloud-4`, host `cloud linux x86_64`. Prompt relayed via sharp-shannon (#331).*

## Intent as read
Evaluate the tools the dyad-system Agent has — the `dyad` CLI, the guards, the play-books and
run-books, the crafts' scripts, delegation to subagents — for doing its work with fewer tokens, by
finding the activities it repeats most and asking of each: is it already mechanized, could code do
it, or could a cheaper delegate do it? The evidence is all past activity: the ledger (333 rows, their
plans and provenance), `INCIDENTS.md`, `git log` and the PRs. The output is an evaluation that ranks
candidates, not a remediation: as #161 did, survivors are proposed as rows for the Operator to open.

What is new against #154/#161/#204: those measured **wall-clock** (tests, pushes, hooks). This one
measures **tokens**, which is what an inference budget (#143) is spent in, and asks of every
recurring act — not only the mechanical ones — what inference it costs.

## What can be measured, and what only derived
- **Measured:** per-session token usage and cost from the hosting (`list_sessions` /
  `get_session` → `external_metadata.usage`: input, output, cache read, cache write, `cost_usd`) for
  every cloud session still listed; for reference the cos alone reads $114 and 99.8 M cache-read
  tokens today. Counts of rows, commits, PRs, files touched per commit, commands invoked in commit
  messages, plan and record sizes in bytes.
- **Derived:** tokens per d-work, per act class. No transcript is in the corpus (Rule-7 property 2),
  so per-act tokens are estimated from artifact sizes (bytes the Agent wrote and read per act ≈ 4
  bytes/token) and apportioned from session totals by the rows each session worked. Every derived
  number is labelled so, with its formula.
- **Not available:** terminal sessions' usage (not in the hosting), sessions already purged, and
  any per-tool-call split. Stated as gaps.

## Method (executed by delegated subagents, read-only, in parallel; the main Agent writes)
1. `git fetch --unshallow` in this worktree (the clone is shallow, 75 commits visible of ~1,400).
2. **Ledger miner:** every row — states, `disposed` entry counts, refs depth, accreted vs prompted,
   plan-file size, provenance size, time open→done; the classes of work by title.
3. **Git miner:** every commit — zone, ledger-only vs code, files per commit, subject patterns
   (recurring clerical shapes: "ledger: #N opened/planned/done", merges, re-pins, rebases), the
   commands their messages cite.
4. **PR miner:** every PR — size, commits, time open, review rounds, rebases, closed-unmerged.
5. **Session usage:** every listed session's `usage`, mapped to seats and rows by title/tags.
6. **Traces and incidents:** the 81 traces' bucket shares (inference vs mechanical vs wait);
   `INCIDENTS.md` failure modes whose recovery cost inference.
7. **Tool inventory:** every `dyad` verb, guard, play-book/run-book and craft script; for each
   recurring act found in 2–6, which tool covers it, partly or not at all.
8. **Evaluation:** a table of recurring act × frequency × estimated token cost × current tool ×
   proposed mechanization (code, play-book, cheaper-model delegate, or none), falsified.
