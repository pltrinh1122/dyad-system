## Survivor — the identity-record schema
A JSON-LD object, `@context` = `["https://schema.org", {"dyad": "https://github.com/pltrinh1122/dyad-system/blob/main/dyad/vocabulary/VOCABULARY.md#"}]`.

| key | from | required | holds |
|---|---|---|---|
| `@id` | JSON-LD | yes | a stable IRI for the system: `https://github.com/pltrinh1122/dyad-system#system` |
| `@type` | schema.org | yes | `SoftwareSourceCode` |
| `name`, `alternateName` | schema.org | yes | `The Dyad System`, `dyad-system` |
| `description` | schema.org | yes | one paragraph, following the vocabulary's definition |
| `codeRepository`, `url`, `license` | schema.org | yes | repo URL; repo URL; the license IRI (`https://spdx.org/licenses/ISC`) |
| `author` | schema.org | yes | `Person` by `url` only |
| `isBasedOn` | schema.org | no | the practice and the bond repos |
| `programmingLanguage`, `runtimePlatform` | schema.org | yes | `Python`; the kernel (Python 3.12, git), without versions beyond the kernel pin |
| `hasPart` | schema.org | yes | each craft in `BUNDLE.md`: `{@type: [SoftwareSourceCode, dyad:core craft | dyad:Tended craft], name, path}` |
| `dyad:party` | extension | yes | the two parties: `{role: Operator, kind: human, act: disposes}`, `{role: Agent, kind: model, act: proposes}` |
| `dyad:invariant` | extension | yes | the craft invariants as short strings: no-self-ratify, falsification, provenance |
| `dyad:frame`, `dyad:rules`, `dyad:vocabulary` | extension | yes | paths: `dyad/CLAUDE.md`, `dyad/rules/`, `dyad/vocabulary/VOCABULARY.md` |
| `dyad:entrypoint` | extension | yes | `dyad/bin/dyad` and the install command |
| `dyad:releases` | extension | yes | the Releases URL and the tag scheme (bundle `vX.Y.Z`, core `dyad-operator-vX.Y.Z`, craft `<craft>-vX.Y.Z`) |
| `dyad:registration` | extension | yes | `not registered with the commons` |

Forbidden in the record: versions, dates, commits, emails, anything not resolvable to a path or URL.

### Survivor — schema additions
| key | from | required | holds |
|---|---|---|---|
| `audience` | schema.org | yes | `Audience`: an Operator who directs an AI coding agent (Claude Code or another CLI agent) and wants to keep every decision |
| `dyad:purpose` | extension | yes | `{problem, approach, target, nonGoals[]}` — the purpose every dyad system shares; each field cites, in `dyad:source`, the artifact that states it |
| `dyad:appliedTo` | extension | yes | this instance's domains: `[{name, path}]` — what it is applied to, which another system with the same attributes would state differently |

### Draft values (for the Operator to refuse or correct)
- `problem`: Delegating real work to an AI agent without losing human authority or the record of why. An agent that
  acts on its own judgment makes decisions no one made; an answer machine adds nothing the human did not already have.
- `approach`: An Operator–Agent dyad. The Agent proposes, falsifies its own claims and executes; the Operator alone
  disposes, with `Y` or `N`. Every unit of work opens on an Operator prompt, is authorized by a plan-`Y`, and closes on a
  Done-`Y`; the Operator's words are kept verbatim, and guards check the record mechanically.
- `target`: 1+1>2 — the pair produces what neither would alone. The Agent may challenge on intent, never overrules,
  and keeps an independent view; the pair must not collapse into one voice.
- `nonGoals`: an autonomous agent (nothing moves without the Operator's disposition); a general workflow engine or CI
  product; an affiliate of the practice commons (not registered with it).
- `appliedTo` (this instance): authoring, checking and releasing the core craft `dyad-operator` and its Tended crafts
  (`dyad/`, `crafts/`); administering the Operator's own workstation (`workstation-corpus/`).
- `dyad:source`: `dyad/CLAUDE.md`, `dyad/rules/RULE-2-no-self-ratify.md`, `dyad/rules/RULE-3-d-work.md`,
  `dyad/rules/RULE-7-provenance.md`.

The prose introduction opens with the same purpose, in this order: the problem, the approach, the target, what it is
not, what this instance applies it to.
