# Plan #220 — falsify: CI validates integration form and structure; unit regression is an audit job

*Rule-15 phase 1. Base commit of `main`: 85e92e8 (2026-10-05). refs: 219 217 210.*

## Intent as read
The claim:
- the intent of the per-change gate ("CI", the local push gate, Rule-14 property 3) is to show that
  the system's integration form and structure are valid;
- verifying that the unit tests show no regression belongs to audit.

The Operator asks for it to be falsified before anything encodes it.

## Falsification (done read-only; the record will hold it)
| # | attack | result | survivor |
|---|--------|--------|----------|
| A1 | What is "form and structure" concretely? The invariant pass (72 lines) and the ~25 state and 5 transaction guards judge the live repo: zones, rows, transitions, provenance, rule blocks, vocabulary, manifest, references, bundle and drift. Install integration is the scratch install and the craft install. | survives, scoped | CI = invariants + guards + one install smoke. This set exists today: about 4 s for the guards, plus the install cases. |
| A2 | **The gate validates itself.** A unit regression in a guard or the runner can make the guard *pass* falsely. The live repo is valid, so CI stays green while the fence is broken, and invalid structure can then land unseen until audit. | **confirmed** | Unit tests of the *gate's own code* (guards, the runner, hooks, the `dwork` writers) are CI, run when the range changes that code. Unit regression of non-gate code (projectors, trace, runbook, livetest, hostadapter) is audit. |
| A3 | **Checks that exist only as tests.** #217 found three form checks with no guard: redaction, `incidents.check` and the trace store's `check_store`. Moving the tests to audit-only would drop them from CI. | **confirmed** | They are promoted to guards first. Only then does the split hold. |
| A4 | **Rule-2 Binding.** The merge evidence (`check --evidence`) runs every root, and the Done-`Y` ratifies on observed passes. Audit-only unit regression means a merge ratified without them. | **confirmed as a Rule cost** | Either keep `check --evidence` full (the split applies only to the push gate), or amend Rules 2, 12 and 14 so the Operator ratifies on form evidence alone. The record names both and makes neither. |
| A5 | **Does the push-time suite catch regressions?** This machine's transcripts hold 32 `git push` results with `[Rule-12]` lines. In all 32 the suite passed (`FAILED` count 0). Failures were found earlier, by hand runs and by `check --evidence` before the push. | survives, scoped | The push-time suite caught nothing in the observed window. The value of unit tests at the gate is the A2 self-check, not regression catching. The scope is one host; other hosts' transcripts were not read. |
| A6 | **Regression window.** A regression found at audit lands on `main` first, and other sessions build on it (Rule-16). The fix cost is a bisect. | confirmed as the cost | It is bounded by the audit cadence. The record names the cadence as the open parameter. |
| A7 | **Duplicates.** #217 found 15 unit tests that re-judge the live repo, duplicating guard verdicts. | supports the claim | Under the claim these leave CI *and* audit, because the guards already give the verdict. They are deleted as follow-up work, not here. |

**Survivor (to be recorded):** CI's intent is integration form and structure *plus the gate's
self-validity*. That means the invariants, the guards, an install smoke, and the unit tests of any
gate code the range changes. Unit regression of everything else is an audit job. Three
preconditions apply before it is adopted:
- the three suite-only checks are promoted to guards (A3);
- a decision is made on `check --evidence` (A4);
- an audit cadence is set (A6).

**Effect on #219.** #219's subset rule becomes narrower. Step 3 selects only gate-code tests, and
the hub verdict "full suite" moves to audit. #219's PR #308 is unchanged. The record cites it as
the measured basis.
