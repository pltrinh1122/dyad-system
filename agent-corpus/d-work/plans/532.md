# Plan #532 — seats merge on a recorded Done-Y: close the seam between the ledger's authority and the session's permission (falsified)

Base commit of main: (main at opening)

## Intent as read
The Operator, answering finding S9 of plan #531 revision 4: "the seat should not be refusing merges. evaluate the
current failure in the seam when delegating and work. each seat has the authority to merge if it has been granted the
`Y-done` either directly or relayed by `cos`."

## The failure, as observed
- **2026-10-27, #494.** distribute-a603e150 verified the Done-Y on `main` (`Y done (merges PR #530 at fb51aa1…)`). Its
  pinned merge was then refused by **its session's harness permission classifier, "Merge Without Review"**. The seat
  correctly did not route around the block. The cos merged instead, and has merged every seat PR since (#517, #520, #524,
  #525, #526, #527, #530).
- **Earlier, #451.** engineer's tag push was refused by the same classifier as **"Create Public Surface"**. Releases were
  then run by an Operator script, until the `released` workflow (#461) moved publishing off the seats.

## The seam
- **Authority lives in the corpus.** The Operator's Done-Y is given in the cos's chat, recorded verbatim on `main` (the
  row's `disposed` entry naming each PR at its head, plus the provenance record). Rule-2 makes executing it clerical, for
  whichever Agent session executes it.
- **Permission lives in the session.** Each harness judges an outward act against its own transcript and its permission
  rules. In the seat's session there is no Operator turn approving the merge: the cos's relay arrives as a cross-session
  message, which the harness treats as a peer's data, never as the user's word. So the classifier sees a merge nobody in
  that session authorized, and it refuses.
- **Nothing connects the two.** The cos's merges pass only because the Operator's `Y` is typed in the cos's own chat. So
  the cos executes every seat's merge. That contradicts the cabinet's text ("each seat executes its own merges", Guide §2)
  and its availability rule (#432), and it blocks the cos-as-a-mode (#531 G).
- **Rule-1 Boundaries (#23) is right to forbid the shortcut.** A Rule never reads permission out of itself. The bridge has
  to be an Operator-side permission that points at the corpus.

## Options
- **O1. Status quo:** the cos merges every PR. It works, but it breaks the cabinet's text, loads the cos, and blocks G.
- **O2. A broad allow rule** for the merge tool in `.claude/settings.json`. It works, but any seat could then merge with no
  Done-Y at all, because a hosted merge runs no pre-push hook.
- **O3. Attend the seat** for its Done question. It works only where the Operator sits (as with communicate), and spends
  the Operator's span.
- **O4. A guarded merge verb plus a narrow allow rule.** `dyad merge <pr> --head <sha>` reads `origin/main`. It executes
  only when the operative `Y done` on a row names PR `<pr>` at exactly `<sha>`, the PR's live head is that sha, and the
  head is not yet on `main`; otherwise it refuses, printing why. The repository's `.claude/settings.json` allows **that
  verb only** (`Bash(dyad/bin/dyad merge:*)`, and the `./` form), never the raw merge tool. The permission the Operator
  grants then reads: "a seat may merge exactly what the ledger records your Done-Y on".
