### The claim, falsified: "one consolidated tree serves every segment"
| id | attack | result | survivor |
|---|---|---|---|
| K1 | **A tree has one root, but each segment starts from its own symptom.** | survives, scoped | the file holds a graph, not a strict tree. There is one symptom root per segment, and the branches meet in shared causes and in the one anchor, which every segment shares already. Each symptom root is tagged with its segment |
| K2 | **The same statement may be a root cause for one segment and only a cause for another**, because the whys differ by segment. | **confirmed** | a node's outcome must hold for every segment whose branches reach it. Where it does not, the node is split into one node per segment, each with its own outcome. A join across segments is allowed only where the outcome is the same |
| K3 | **One change anywhere makes the whole tree stale**, so every segment's lookups stop while one segment is being worked on. | **confirmed** | the header holds one digest per segment, over the lines that segment's branches reach. A change re-judges only the segments it touches |
| K4 | **Lookups get slower** in a large file. | survives, scoped | a lookup starts from the segment's own symptom root and reads only its branches |
| K5 | **The selection rule ranks across segments by mistake.** "Joined by how many branches" would count other segments' joins. | **confirmed** | ranking counts only the branches reachable from that segment's root. `problem.md` stays per segment, citing node ids in the one file |
| K6 | **Node ids collide**: each segment's tree starts at N0. | **confirmed** | ids carry the segment slug where they are segment-specific, e.g. `platform-ops.N0`. A node shared across segments takes a neutral id, `X1`, `X2` and so on. The ids of the file already on `main` are prefixed, never renumbered, so every citation still resolves by prefix |
| K7 | **Consolidation is worth the cost.** | survives | it closes #678's T7 gap: a root cause shared by several segments is found once and shown as shared, which a set of separate trees cannot show. That is also the evidence a go-to-market needs when choosing targets |

**Verdict:** the claim **survives, scoped**:
- one file, a graph of segment roots joined into shared causes and one anchor (K1);
- an outcome holds for every segment that reaches a node, or the node is split (K2);
- a digest per segment (K3);
- ranking within the segment (K5);
- ids prefixed by segment (K6).

**What the consolidation changes.**
- **§6 and `collateral-why-tree`** (craft zone): the record path becomes `<canvas set>/why-tree.md`, with the
  per-segment digests, the split rule, the segment-scoped ranking and the id form. `stale` reads the segment's own
  digest. One new test: `mixed-outcome` (a node shared across segments whose outcome differs by segment). The
  falsification rows K1–K7 replace T7's row with a superseding one.
- **The tree file** (infra zone): `site/lean-canvas/platform-ops/why-tree.md` moves to `site/lean-canvas/why-tree.md`,
  its ids prefixed `platform-ops.`, its header carrying the `platform-ops` digest. `problem.md`'s citations gain the
  prefix.

`ready` for `platform-ops`, and `off-tree` still passes. The review page shows the `platform-ops` part of the
