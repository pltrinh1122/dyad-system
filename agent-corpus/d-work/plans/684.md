## Intent as read, revision 2 (provenance #684, entry 2)
The operator's words: "remember, the intent of the why-tree is to eliminate red-herrings when new problems come up by
traversing the holistic tree and not just for a single segment. segmentation are tags/attributes for each node of the
tree". No `Y` or `N`: entry 2 is a `prompt`, and the intent question stands, revised.

**What changes.** Revision 1 kept segments as roots of the graph and scoped lookups to a segment (K4). Read now:
- **The tree is one whole, and its purpose is screening.** When a new problem comes up, it is traversed against
  **every** node, not one segment's branches, to find whether the problem is already explained: a symptom of a known
  root, or a known cause. A problem that maps to a known node is a **red herring** as a new problem. It takes that
  node's outcome and its root, and is never decomposed again. Only a problem that maps to no node is new and is
  placed, diverging from its nearest parent.
- **Segments are tags on every node**, not roots: each node carries the set of segments it holds for, e.g.
  `{platform-ops, team-leads}`. A segment's view of the tree is the nodes tagged with it.

**Revision 1's attacks, re-read:**
- **K1** (one root per segment): **superseded.** Symptom nodes are many, and each is tagged. No node is a "segment
  root".
- **K2** (an outcome differs by segment): stands. A node's outcome holds for every segment in its tags; where it does
  not, the node is split, and `mixed-outcome` catches it.
- **K3** (staleness): revised. The header holds a **whole-tree digest**, which a holistic lookup reads, and a digest
  per segment over the nodes tagged with it, which that segment's selection reads.
- **K4** (lookups start from a segment): **refuted by this prompt.** A lookup traverses the whole tree; that is the
  point.
- **K5** (ranking): stands. Selection for a segment counts only the nodes tagged with it.
- **K6** (id collisions): **refuted.** With segments as tags, ids are global and need no prefix. The `platform-ops`
  ids already on `main` are unique in the one file, so they keep their ids and gain tags, and no citation changes.
- **K7** (worth it): stands, and strengthened. Screening across segments is the purpose.

**New attacks, on the purpose:**
| id | attack | result | survivor |
|---|---|---|---|
| K8 | **A false match across segments.** The same words mean different things to two segments, so a holistic lookup marks a real problem as a red herring. | survives, scoped | a match takes the node's outcome only for the segments in its tags. A claim from an untagged segment that matches by meaning is placed as a **tag candidate**, labelled H, and the node gains the tag only when the removal test holds for that segment too |
| K9 | **Red-herring elimination hides new evidence.** A known symptom raised again may carry new information. | survives, scoped | it is not decomposed again, but it is placed as a new symptom node joined to its known parent (`→ N<id>`), with its source. The tree records that the problem recurred, and the `stale` rule (re-derive on reader evidence) still applies |
| K10 | **Nothing decides "known or new".** | **confirmed** | `collateral-problem-depth` gains a first step: a claim is **known** (maps to a node: it takes the node's outcome and root, and a red herring is named as such) or **new** (placed first). A new tree test, `untagged`, fails a node with no segment tag |

**Definition of done (revision 2, proposed).**
- **Craft PR:**
  - §6 states the purpose (screening new problems against the whole tree), one file per canvas set, segment tags on
    every node, the holistic lookup, red herrings, tag candidates, the whole-tree digest plus per-segment digests,
    segment-scoped ranking and the split rule;
  - `collateral-problem-depth` gains the known/new step;
  - `collateral-why-tree` gains `untagged` and `mixed-outcome`, and `stale` reads the right digest;
  - falsification rows K1–K10 (T7's row superseded).
- **Infra PR:** `site/lean-canvas/platform-ops/why-tree.md` moves to `site/lean-canvas/why-tree.md`. Every node is
  tagged `{platform-ops}`, the ids are unchanged, and the header carries both digests. `problem.md`'s citations point
  to the new path.
- **Evidence:** a holistic lookup run on one new problem, to show a red herring caught.
