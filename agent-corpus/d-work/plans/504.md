# Plan #504 — the criterion for bundling a craft with the core (falsified)

Base commit of main: b02bc31

## Intent as read
The Operator disagrees with "neither should be bundled with the core" (communicate, chronicle) and asks to align on the
core-bundle inclusion criterion: what is it now? The Operator's claim: the most distinguishing criterion is whether a
craft directly contributes to the overall purpose of The Dyad System.

## Today
Two different things carry the word "bundle":
- **The bundle** (`BUNDLE.md`, tag `vX.Y.Z`, Rule-11 property 7): every craft in the tree, at its first release.
  Inclusion is automatic; no criterion.
- **A bundled craft** (Rule-11 property 2): a Tended craft the *core's* archive carries, so a core-only install has it.
  The written criterion: "A core Rule that cites a craft by path is the reason to bundle one … and it is the only
  reason the core's install may write outside its own root." The mechanism: the craft's own `BUNDLED_WITH_CORE = True`.

## Falsification
| # | attack | result |
|---|---|---|
| 1 | The written criterion is what is applied | **refuted — a finding**: core Rules cite four crafts by path (sysadmin in 6 Rules, sysarch in 8, syseng in 4, cabinet in 2) and only sysadmin declares `BUNDLED_WITH_CORE`. The criterion actually applied was narrower — "a core-only install goes red without it" (#114) — so a core-only install today ships Rules that cite three crafts it does not carry |

| 3 | Purpose is judged by inference; the path test is mechanical (Rule-12) | **survives, scoped**: keep both — (a) **dependency**, mechanical: a craft a core Rule cites by path is bundled, and a guard fails a cited, undeclared craft (closes attack 1 for good); (b) **purpose**, declared: a craft no Rule cites is bundled when it serves the system's purpose for *every* installing Operator — its declaration carries a one-line `PURPOSE` reason and is ratified by the Done-`Y` of the PR that adds it. Inference stays where it must, at the Operator's disposition |

| 5 | Applied to `communicate` (a cabinet function) | **bundled, by (a) and (b)**: cabinet is cited by Rules 3 and 16, and its seats exist to spend the Operator's attention only on decisions. The function line rides cabinet. I withdraw "not bundled" for it |

## Survivor
Rule-11 property 2 states the criterion: a Tended craft is bundled with the core when (a) a core Rule cites it by path,
or (b) it serves the system's purpose (`dyad:purpose`, #496) for every installing Operator, declared by the craft with a
one-line `PURPOSE` reason; never for one instance's applied domain alone. A guard fails a craft a core Rule cites that
does not declare itself bundled.
