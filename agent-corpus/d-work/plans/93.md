## Read so far (read-only; `dietrichgebert/ponytail` v4.10.0, cloned to the scratchpad)
- The claim today: "~54% less code (up to 94%), ~20% cheaper, ~27% faster, 100% safe" — agentic
  benchmark 2026-06-18, Haiku 4.5, 12 feature tasks, n=4, metric = `git diff` added LOC in real
  headless Claude Code sessions on `fastapi/full-stack-fastapi-template@cd83fc1`; four arms
  (baseline, ponytail, caveman as terse-prose control, a seven-word "YAGNI + one-liners" prompt).
- Recomputed from the writeup's own per-task table: −54% is the **ratio of summed LOC** (dominated
  by three frontend over-build tasks: 404→23, 287→23, 251→95); the **mean of per-task ratios is
  −35%, the median −27%**; frontend six −60%, backend six −22%. The README's "~54% is the mean
  across 12 feature tasks" names the aggregate, not the mean task effect. Baseline mean LOC from
  the table is 184.75; the writeup states 191 (four force-killed cells, it says).
- Tokens: the Operator's "in spite of more tokens" is the author's own concession for reasoning
  models — cost-verification 2026-06-17: gpt-5.4-mini +26%, gpt-5.5 +39% *more* expensive under
  ponytail (the ruleset is re-sent every call; a terse baseline leaves less to cut), correctness
  100% there too; on Claude −20% cost. The caveman control shows the split in one row: −18% LOC at
  +7% tokens. So "less code even when it costs more tokens" is supported *and scoped* by the repo
  itself: model-dependent, not a universal.
- Raw run data is not in the repo (`runs/<stamp>/` kept locally, "gitignored and regenerable");
  the harness (`benchmarks/agentic/run.py`, `tasks.py`, `judge.py`, `loc.js`) is. Verification from
  the repo is therefore internal consistency plus method reading; a re-run is ~200 headless Haiku
  sessions (~$15–25 at the writeup's per-task cost) — a World action with a credential, not this
  d-work's, offered as a follow-on.
- Method quality, to its credit: a superseded 2026-06-17 run found its own contamination (the
  plugin's `SessionStart` hook fired on the baseline arm, collapsing the gap to ~4%), fixed
  isolation, and re-ran; the single-shot 80–94% is retracted in place as a chatty-baseline artifact
  (issue #126). Safety tier: 100% (20/20) vs 95% for the bare one-liner prompt — one slip, a
  floor; the guard kept was the path-traversal check.
- The mechanism (`skills/ponytail/SKILL.md`, 120 lines): a seven-rung ladder run *after* reading
  the code (need? · already here? · stdlib? · native platform? · installed dependency? · one line?
  · then the minimum); a "never simplify away" floor (trust-boundary validation, data-loss
  handling, security, accessibility, anything requested); "lazy code without its check is
  unfinished — ONE runnable check"; a `ponytail:` marker on a deliberate ceiling with its upgrade
  path; root cause over symptom ("grep every caller"); output pattern `[code] → skipped: [X], add
  when [Y]`; intensity levels (lite/full/ultra); persistence via a session-start hook that
  re-injects the ruleset. A companion `ponytail-review` skill: one line per finding, tagged
  `delete:|stdlib:|native:|yagni:|shrink:`, scored `net: -N lines possible`.
