# Plan #214 — what a d-work trace does, and its overhead

*Rule-15 phase 1. Base commit of `main`: c8e504a (2026-10-05). refs: 213 212.*

## Intent as read
State the inference and mechanical work a trace performs, and measure the time it adds to each d-work.

## Answer by design (given now, in the reply)
**Mechanical, inside `dyad dwork trace`:**
- Parse the session transcript, about 40 MB and 16k lines here.
- A few `git log` calls.
- Read the row, provenance and plan files.

**Inference, by the Agent:**
- One tool call to run it.
- Reading its output and citing it in the completion reply.

The tool itself does no inference.

**Overhead that depends on where the trace is stored:**
- **`agent-corpus/audits/traces/` (#213 as planned).**
  - Committed in the work PR, it must be generated before that PR's push. It then misses the PR's own
    push and evidence runs, the costliest events.
  - Committed separately, it is a record-only push: one extra PR cycle and two full-suite runs per
    d-work (#210).
- **`<instance>/d-work/traces/<id>.md` (proposed revision 2 of #213).**
  - It rides the clerical Done commit that already exists.
  - That commit is ledger-only, so it adds no PR, no push and no suite run (#211, `suite_gate`).
  - Written there, the trace can also include the work PR's push, evidence and the Done-`Y` itself.
