# Plan #337 — gh versus the GitHub connectors, for this seat

*Rule-15 phase 1. Base commit of `main`: the head this row was opened on (2026-10-17). refs: 333.
Seat `ds-cabinet-cloud-4`.*

## Intent as read
The Operator asks why this seat reached GitHub through an MCP connector rather than the `gh` CLI,
which they take to be more efficient, and offers an OAuth login if one is needed. They then add that
the connector should be working.

## Findings (read-only, observed in this container)
- `gh` 2.89.0 is installed and the agent proxy already authenticates it at egress:
  `gh api repos/pltrinh1122/dyad-system --jq .full_name` returns the repository. `gh auth status`
  reports the `GH_TOKEN` as invalid because that token is a placeholder the proxy replaces. An OAuth
  login would add nothing.
- GraphQL is blocked at the proxy, so `gh pr view|create|merge` fail with HTTP 403. The REST form
  works (`gh api repos/{o}/{r}/pulls …`).
- Two GitHub connectors are attached. `GitHub_App` refused `create_pull_request` with
  `403 Resource not accessible by integration`. `github` created PR #418 a moment later.
- Why MCP was used: the session's harness instructions direct GitHub work to the MCP tools. `gh` was
  not tested until asked.
- Efficiency, by audit #333's cost model (cost = calls × context): `gh api … --jq` returns only the
  filtered fields, while a connector returns whole JSON into context. Example: `list_sessions` here
  returned 166 k characters. Per call, the CLI is the cheaper path for reads.

## Mutation proposed
None to the repository beyond this row's ledger files. Conduct for this seat from now on:
- GitHub reads and writes go through `gh api` (REST) with `--jq` filters.
- The `github` connector is the fallback where REST lacks a route.
- No OAuth login is requested.

## Rule-10 block
- **Path:** adopt `gh api` (REST, `--jq`) for this seat; no OAuth; the `github` connector as fallback.
- **Counter:** the harness instructs MCP for GitHub, and a connector call is typed where a REST call is hand-built.
- **Reconciliation:** the Operator's preference governs. The REST routes this seat needs (pulls, merges, check runs) are stable, and `--jq` keeps the context small, which is the cost #333 measured.
