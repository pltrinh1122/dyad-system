**Ambiguous, with the reading taken:**
- **A1. Release planning: forward or back?** Read as forward: a plan of what the next release should hold.
  `release.md` still decides, after a landing, whether a change set releases and at what number. A release itself
  stays Rule-11's question. A plan ratifies nothing and publishes nothing.
- **A2. Who runs it.** Read: the home, because it owns the backlog and promotion. The release plan goes to
  distribute, the unit that ships crafts, as a notice: information, not authority.
- **A3. What a run costs you.** Read, against #623's target: one grooming reply, with at most one question, the
  retirement form, when a row has a retirement ground. Promotion stays where it is, at a unit's idle moment, asked by
  `promotion`. The release plan asks nothing. The run is read-only, recorded as its run-book's event (an events-only
  commit, clerical), so no row opens for it (Rule-3: monitoring is no d-work).
- **A4. When a run is due.** Read: `groom-trigger` decides. The moments are a release landed, promotion finding no
  candidate while a unit idles, hygiene findings over a fixed count, or your prompt. No new preference, because a
  preference change is a question of its own.

## Definition of done (proposed, for the intent-Y to accept)
1. **The play-book and its run-book** (`dyad/playbooks/backlog-groom.md`, `dyad/runbooks/backlog-groom.md`). They name
   the trigger, the steps in order (hygiene, retire, size, promote, plan the release), the question each step may
   ask (at most the retirement form per run) and its evidence. Each step cites its criterion and redefines none.
2. **Two new criteria**: `release-plan` and `groom-trigger`, in `dyad/dmc/`, each with a home file that defines its
   outcomes, passing the `dmc` guard.
3. **`promotion` revised**: the release plan is an input, and within a class a row planned into the next release
   ranks first. Its home section in `d-work.md` says the same.
4. **One read-only report command** for the run-book's steps (Rule-13: grooming done by hand each time is a recurring
   inference task). It prints each backlog row with its hygiene finding, retirement ground, promotion class, size and
   release target, and the projected next release per craft. It comes with its tests.
5. **A first run on this backlog**: the report over the 22 rows and the release plan it projects, in the completion
   evidence. Any retirement form it proposes is asked after the Done, as its own question.
