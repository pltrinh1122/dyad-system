## The plan

counsel writes the play-book, run-book and criteria text; engineer writes the code and tests. The home verifies,

## Mutation
1. **`dyad/dmc/groom-trigger.jsonld`** (new; kind inference; home `playbooks/backlog-groom.md`; owner Rule-3). It
   decides whether a grooming run is due now. Outcomes, in precedence order:
   - **G1 operator prompt**: due.
   - **G2 release landed**: a release tag published since the last grooming event. Due.
   - **G3 promotion found nothing**: `promotion` reached `no proposal` while a unit is idle and the backlog is not
     empty. Due, once per backlog state.
   - **G4 hygiene over the count**: `board resume` prints five or more hygiene lines. Five is a number in the
     home file, not a preference.
   - **not due** (default).

   Floor: no run while the backlog's rows and the board are unchanged since the last grooming event, except under
   G1. That floor stops a G3 loop (F4).
2. **`dyad/dmc/release-plan.jsonld`** (new; kind inference; home `playbooks/backlog-groom.md`; owner Rule-11 by
   reference, as `release-class`; `alsoIn` `playbooks/release.md`). Per groomed backlog row it decides where the row
   falls. Outcomes:
   - **next release**: the row's projected class releases. That class is the highest of `release-class`'s for the
     craft whose root the row's work is under, or a critical fix. It has no unresolved ref, and `altitude` sizes it
     as one definition of done.
   - **a later release**: the row releases, but below the class that sets the next release's theme.
   - **rides any release**: maintenance. It needs no release of its own.
   - **held for a major**: breaking. It is planned only on your prompt for a major.
   - **not plannable**: no craft root can be read from its title, refs or plan, or `altitude` says split. The
     report names what is missing.

   The projected number per craft is `release-number` applied to the highest class among that craft's next-release
   rows. The plan publishes nothing and ratifies nothing. A release stays Rule-11's question.
3. **`dyad/dmc/promotion.jsonld` revised**, with its home section "Promotion when the board is empty" in
   `dyad/playbooks/d-work.md`. It gains one input: the release plan, from `_cos`'s `release-plan` line. It gains one
   precedence clause: within a class, a candidate the plan places in the next release comes first. No outcome
   changes.
4. **`dyad/playbooks/backlog-groom.md`** (new) and **`dyad/runbooks/backlog-groom.md`** (new, sections `Report`).
   - Parameter: none.
   - Trigger: `groom-trigger`.
   - Steps, in order:
     1. **report**: run the run-book's one read-only step.
     2. **retire**: `retirement-candidate` per row, then `retirement-sweep`.
     3. **size**: `altitude`.
     4. **promote**: `promotion`'s ranking, recorded. It is proposed only at a unit's idle moment, as now.
     5. **plan the release**: `release-plan`. It is written to `_cos` as `release-plan`, and posted to distribute
        as a notice.
   - Question: at most the retirement form, once per run.
   - Evidence: the run-book event's id and the `_cos` line.
5. **`dyad board groom`** (new read-only verb): `dyad/scripts/groom.py`, plus a row in `dyadlib.CLI`. It prints one
   line per backlog row:
   - its `#id-slug` and age;
   - its hygiene lines, imported from `hygiene.py` and never recomputed (Rule-13);
   - its refs' states;
   - its adjacency score against the board's anchors, by `hygiene.ranking`;
   - whether a `_cos` promise names it;
   - the craft roots read from its plan file, if any.

   Then the last tag per craft (as `release changes` reads it) and the last grooming event. It prints facts, never a
   judgement: the class columns are the home's. Test: `dyad/tests/test_groom.py`.
6. **The board guard** (`dyad/guards/agent/board.py`) admits a `release-plan` key on a `_cos` file, written by
   `board set`. Test: its existing test file.
7. **`dyad/tests/test_playbooks.py`** gains `BacklogGroomPlaybookTests`. The play-book must name every criterion it
   cites and redefine none; the run-book's sections must match its header. The `dmc` guard judges the two new
   records on every push.
8. **First run** (after the PR's evidence, before the Done): `dyad runbook run backlog-groom report` on this
   instance. It is one events-only commit, clerical. The home's five steps go into the completion evidence. The
   `_cos` `release-plan` line is written only after the Done lands, because until then the key is not admitted on
   `main`.

Mandate scope: none. Host actions: none. Release: none. The core craft's `VERSION` is not bumped here: whether the
change set releases, and at what number, is `release.md`'s call after landing (`plan check` will warn of an
unbumped released craft; this sentence answers it).
