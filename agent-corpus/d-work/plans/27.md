# Plan #27 — architecture rule: fail early and loud

Base commit of `main`: c96c9aa. Refs #25 (an instance of the rule), #24 (the incident that argues it),
`crafts/syseng/rules/invariants.md` (the rule it must not contradict).

## Intent as read
Encode "systems should fail early and loud" as an architecture rule. The Operator said *architecture*,
so the home is the sysarch craft (`crafts/sysarch/rules/`), whose README requires each rule to open
by naming the core Rule whose kernel reads it.

## Finding — taken literally the claim contradicts a rule the Operator already ratified
`crafts/syseng/rules/invariants.md` property 3 bans `assert` in craft code, and one of its stated
reasons is that an `assert` "stops at the first failure". Property 4 specifies the invariant pass as
"a FAIL is red but the checks still run". Three more places refuse to fail at all, deliberately:
Rule-20 property 2 (an absent or empty store *skips*, never fails), Rule-11 property 7 (a missing
`BUNDLE.md` skips), Rule-7 (a row with no provenance record *warns* — "a red `main` is the wrong way
to learn that"). So a rule reading "abort at the first fault" or "every unknown is a failure" would
contradict four ratified positions at once and would make a fresh install red — the exact outcome
Rule-11 property 5 and Rule-20 property 2 exist to prevent.

The claim is right in the sense that is *already* this system's, and the rule's job is to say which:
- **Early is a place, not a moment.** Detect where the fault is first *knowable*, as high as it goes
  on this ladder: **declaration** (a predicate over a module's own constants, run before any check) →
  **transaction** (a hook, before the commit or push) → **run** (a guard over the tree) → **use** (the
  call site). #24 is the worked example: the broken `pre-commit` was perfectly loud at *use* — exit
  126, `Permission denied` — but the fault was introduced by #6's mode sweep and was knowable at
  *declaration*, so it survived a whole d-work cycle unnoticed. #25 is the same shape: a verb rename
  is knowable at declaration and nothing declares it.
- **Loud is named and attributable.** Every fault prints a line naming itself — and so does every
  check that was *skipped*, with its reason. The system already does exactly this
  (`FAIL [invariant] <module>: <name>`, `FAIL <kind>: <where> -> <token>`, `skip <kind>: <reason>`);
  the rule names it so a future mechanism cannot quietly swallow one.
- **Fatal is not early.** A run completes and reports every fault it found. "Stops at the first
  failure" stays refused; "cannot be checked here" stays a printed skip, never a failure.

## Falsification
- **"Early means abort at the first failure."** Refuted: `invariants.md` p3 refuses precisely that,
  on the Operator's own rule at #161. Survivor: early is the earliest knowable *point*, not a moment
  to stop at.
- **"Loud means everything becomes a failure."** Refuted: the absent-store skip exists so a fresh
  install is not red (Rule-11 p5, Rule-20 p2). Survivor: loud covers what was *not* checked as well
  as what failed; loud and fatal are independent axes.
- **"This re-owns Rule-20 property 2's severity."** Survives, scoped — and is the orthogonality line
  the rule must hold: per-entity severity stays with the Rule that owns the entity (Rule-20 for a
  reference, Rule-11 p7 for the bundle, Rule-7 for a record). `failure.md` states the stance and
  defers every severity decision by name; if it ever decides one, it has taken another Rule's concern.
- **"A rule with no mechanical check is decoration, in a system built on mechanical checks."**
  Survives, scoped — the honest cost, conceded rather than argued away. It is a design stance, like
  `projection.md`'s "whether a surface is legible … is inference". Its bite is that plans cite it and
  it names the ladder that decides *where* a future check belongs; #25 is already its first instance.
  If the Operator wants it mechanical, the way is a guard per instrument, not a checker for a stance.
- **"syseng, not sysarch."** Survives, scoped: syseng owns the instruments (invariants, determinism,
  the `assert` ban) and the Operator said *architecture*. Survivor: the stance goes to sysarch and
  cites the instruments; syseng keeps them. If the Operator prefers syseng, the file moves and nothing
  else in the plan changes.
