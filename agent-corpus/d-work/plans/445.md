## Decision criteria (from plan #430 and Rule-11)
1. **Model content is in.** Anything that defines the cabinet model or its vocabulary — the cabinet craft's
   tree, the core Rule sentences and vocabulary rows that cite it, the guards those sentences name — ships
   in the three tags. Landed: all of the above. Pending and in if merged before the cut: #441's Guide half
   (#483), #438's Rule sentences and fence code.
2. **A core correctness fix to a command the release's own process runs is in.** #439 (every close corrupted
   its row) ships in `dyad-operator-v0.12.0`; the cut waits for its merge.
3. **Instance content is never in a release.** Preference *values* (`PREFERENCES.md`, `MANDATES.md`), the
   workstation run-books (#444's census, #431's sessions run-book), events and the ledger are this
   system's; they sit on the cut commit but no tag carries them. The templates that seed them
   (`crafts/cabinet/templates/`, `dyad/templates/PREFERENCES.md`) are in.
4. **Tooling that changes no shipped behaviour waits.** #443 (the `--land` form) is excluded unless done
   before the cut; the cut does not wait for it.
5. **A Rule sentence with new guard behaviour is in only when its code and text are both on main**
   (#438): never a half-landed class. If #438 is not whole by the time #439 and #483 land, it goes to the
   next release and the cut proceeds.
6. **Nothing is bumped twice.** Core stays 0.12.0 (untagged since #459), cabinet 0.2.0 (untagged), bundle
