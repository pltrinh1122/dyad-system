# Plan #219 — the test subset CI should run if the full suite runs only during audit

*Rule-15 phase 1. Base commit of `main`: 9fafb51 (2026-10-05). refs: 218 217 211 210.*

## Intent as read
Suppose the full suite (Rule-12's every root) runs only at audit. Identify which tests the per-change
gate should still run. "CI" here means the local push gate, which is this system's CI (Rule-14
property 3); hosted CI only corroborates on `main`.

## Already done (read-only)
A static dependency map of all 45 test files (921 tests), at `9fafb51`: what each file imports,
loads with `load_guard`, names by `*.py`, or loads with `load_package`. Changes were then sized by the
files they would select.

## Mutation proposed
1. One agent-zone PR adding the audit `agent-corpus/audits/2026-10-05-ci-test-subset.md`, citing
   d-work #219. It contains:
   - **The subset rule:** the invariants and guards always; the test files whose dependency set
     meets the changed modules; the suite-only live checks when the range touches the records they
     read; nothing more for a ledger-only or record-only range; and the full suite whenever a hub
     module changes (`dyadlib`, `package`, `livetest`, `rows`), or a test file or the runner itself
     changes.
   - **Measured subsets:**

     | change | tests selected (of 921) |

     | the `rows` guard | 311 |
     | `dyadlib` | 882 |
     | record-only | 0 |

   - **What the change costs in the Rules.** The merge evidence today runs every root (Rule-2
     Binding, Rule-12 property 2, Rule-14 property 3). Running the full suite only at audit amends
     all three. The audit names that cost and does not make the change.
2. No code and no Rule edit. A `dyad check --impacted` implementation would be a follow-up row, if

## Falsification
- **Attack: a static map misses dynamic dependencies.** Confirmed. Examples: a test that spawns
  `dyad/bin/dyad`, which imports everything; `load_module` by a built path; craft discovery.
  Survivor: hub modules and the runner always select the full suite, and any test that spawns the
  entrypoint is in every subset. The audit states the map's blind spots.
- **Attack: count is not time.** Confirmed. `test_package` alone is about 46% of core time (#204), and
  it is in every `package.py` subset. The audit gives times from the #204 per-module profile, not
  just counts.
- **Attack: fewer tests at the gate lets a regression reach `main`.** Confirmed as the cost. The audit
  names the window — a regression lands and is caught at the next audit — and the Rule amendments.
