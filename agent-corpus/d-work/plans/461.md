## Survivor (recommended): `released` hosted on GitHub Actions
- **Request.** On the Operator's release Y, the cos records it (ledger-only) and the distribute seat writes one request
  file, `<runbooks>/releases/<tag>.md` (tag, cut sha, expected archive sha256, row id), events-only-like, to main.
- **Service.** A workflow on push to main (the `released` run-book's command, Rule-19) reads new requests, checks the
  row carries `Y release <tag>`, the tag equals its VERSION, builds by the one code path, verifies the sha256, creates the
  tag and the Release, and appends an event. Idempotent; the tag-push trigger is removed so nothing double-fires.
- **Operate.** The distribute seat owns its run-book: health = last event per request, a reconcile of requests to tags
  and Releases. Optional gate (attack 4): environment approval, one tap.
- **Counter (the Operator's own shape):** a long-running daemon on the workstation (Rule-19 server instance, systemd,
  the Operator's credentials). It works, but it adds a machine that must be up and a process to keep alive (attack 5),
  and it holds publish credentials on a desktop.
- **Reconciliation:** what the Operator asks for is the properties (persistent, configured once, mechanical, operated by
  distribute); Actions has them without a process anyone maintains. If the Operator wants the workstation host instead,
  the same request/event contract holds and only the runner changes.
