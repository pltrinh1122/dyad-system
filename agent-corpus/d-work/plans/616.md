## The criterion proposed: `release-timing`
**Question.** A change set since a craft's last tag holds a critical fix. Release now, or hold?

**One fact frames it.** A release is cut from `main`, and 1.x keeps no maintenance branch (#611 Q5, reading (a)).
So a release now carries everything on `main` since the tag. If a capability or enhancement is already there, the
fix ships as that minor; a "patch now" exists only when nothing above a fix has landed since the tag.
`release-number` still says which part moves. This criterion decides only when.

**Inputs.**
1. **Release path:** does the defect refuse a cut, a publish or an install?
2. **Exposure:** does an installing system run a released version that gives it the wrong result? Read from a
   report, an incident or a known install. Unknown counts as exposed.
3. **Workaround:** is there a stated step an exposed system can take until the release?
4. **Fix landed:** is the fix on `main`, or still a row?
5. **Minor in reach:** is a capability or enhancement already on `main` and unreleased, or a planned row expected to
   land with it?

| code | outcome | when | then |
|---|---|---|---|
| `fix-first` | the fix before any cut | the defect breaks the release path itself | No release is cut until the fix is on `main`. The next cut, whatever its number, carries it. |
| `cut-now` | release at once | an installing system is exposed with no workaround, or data is lost or leaked; or the inputs cannot decide | The home proposes the release as soon as the fix lands. The number follows the change set: a patch, or the minor `main` already holds. This is today's rule, kept as the default. |
| `fold` | ride the next minor | not exposed, or a workaround is stated, and a minor is in reach | The fix waits for that minor. When the minor lands, the critical fix is why it is proposed at once (release.md's existing sentence). |
| `hold` | hold and decide later | not exposed, or a workaround is stated, and no minor is in reach | The change set waits and is decided again at a trigger below. |

**Precedence.** `fix-first`, then `cut-now`, then `fold`, then `hold`.
**Default.** `cut-now`: when exposure cannot be read, today's rule stands.

**Decided again** on any of these events:
- a done-`Y` lands a change under the craft's root (the play-book's existing Trigger);
- a report or incident shows an installing system exposed;
- the operator asks.

No time cap applies. Elapsed time changes no system's exposure (F4).

**Its first use, on the live case** (the completion evidence repeats it on the merged text):
- `main` holds #615, a capability, unreleased since `dyad-operator-v1.0.0`. Any release now is 1.1.0, and the
  "1.0.1" patch cannot be cut separately.
- The tag-check deadlock refuses every push after a cut until the tag exists, so it breaks the release path:
  `fix-first`. Its row is not yet open.
- Reading: open the tag-check row first. The next cut is 1.1.0, carrying #615 and that fix. No release before it.
