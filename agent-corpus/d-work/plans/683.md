**A false premise in #678's rule (found by this reading).** §6 puts the judged commit in the tree file's own header,
`judged: <outcome> at <commit>`. A file cannot name the commit that adds it, because the hash is computed from the
file. So the header can only name an earlier commit, and Q3's lookup check ("the file is unchanged since that commit")
then always fails. Read: the header records a **content digest** instead, `judged: <outcome> (nodes <sha256 of the
node lines>)`. A lookup recomputes the digest, which any reader or a later guard can do. `collateral-why-tree`'s
`stale` then reads "the node lines no longer match the digest". This is a two-line change to the craft (§6 and one
record), and it goes in its own craft-zone PR, before the tree file's infra-zone PR.

## Falsification
| id | claim | attack | result | survivor |
|---|---|---|---|---|
| H1 | a content digest proves the tree unchanged | whitespace or line-ending edits change the digest without changing the tree | survives, scoped | the digest is over the node lines as committed; a whitespace edit is a change, and the tree is judged again, which is cheap |
| H2 | the digest can be checked by hand | a reader can't compute a sha256 by eye | survives, scoped | `sha256sum` over the lines after the header reproduces it; a later guard can run it, and the PR body states the command |
| H3 | superseding N1.1.1.1 removes the circularity | the timing cause still sits close to RA | survives, scoped | the new parent names when the tool asks, RA names what is missing, so a why connects them and neither rewords the other; `circular` is re-run in the evidence |
| H4 | dropping RA from `problem.md` loses nothing | the reader's own phrase ("approve keystrokes, not intent") goes | survives | it stays as a quotable node, and a pitch can cite it by id |
| H5 | two PRs keep the zones apart | the second waits on the first | survives | that is the stated order; nothing in step 2 lands before step 1 |

**Counter.** Keep the commit-based header and record the judged commit in `index.md` instead, avoiding a craft change.
**Reconciliation.** That would move the tree's state out of the tree, and the lookup would read two files to answer
one question. The digest keeps the tree self-checking, at the cost of one craft PR.
