**A false premise in #678's rule (found by this reading).** §6 puts the judged commit in the tree file's own header,
`judged: <outcome> at <commit>`. A file cannot name the commit that adds it, because the hash is computed from the
file. So the header can only name an earlier commit, and Q3's lookup check ("the file is unchanged since that commit")
then always fails. Read: the header records a **content digest** instead, `judged: <outcome> (nodes <sha256 of the
node lines>)`. A lookup recomputes the digest, which any reader or a later guard can do. `collateral-why-tree`'s
`stale` then reads "the node lines no longer match the digest". This is a two-line change to the craft (§6 and one
record), and it goes in its own craft-zone PR, before the tree file's infra-zone PR.

**Ambiguous, with the reading taken:**
- **A1. How to fix RA's circularity.** The two options #761 named: rewrite the parent as a cause about the tool, or
  lift RA and drop the parent. Read: **supersede the parent** N1.1.1.1 with "The tool asks for approval at the moment
  of execution, not at the moment of intent", a cause about timing. RA stays as the answer to it, so the branch keeps
  five distinct whys.
- **A2. Which roots reach `problem.md`.** §6 selects one to three, ranked by the anchor's exits, then by joins. That
  gives **RD** (the trail) and **RC** (no check of the result against intent), both exits of the anchor branch, then
  **RB** (risk, joined twice). **RA** (intent as an approvable object, joined once) drops out of `problem.md`, though it
  stays in the tree. Your symptom N0 sits beneath each of them, since every branch starts from it.
- **A3. The removal test for RC and RD.** Read: each test is written as a line in the tree, "removing it removes …",
  naming the symptoms whose branches reach the root, labelled H like the rest.
