## Intent reading (revision 2)

Prompt (entry 2): "what will be the remaining gap after grooming for staleness?" Revision 1 judges whether an old row still stands. Four gaps remain after it:
- G1 still valid, never worth doing: a `holds` row is kept, and promotion holds while any question is owed, so a row can be read and kept forever. No retirement ground covers "still true, no longer wanted": that is the operator's call, and nothing asks it.
- G2 undecided forever: an `undecided` row is reported with what is missing, and nothing goes to get it.
- G3 throughput: five per run, and a run only when `dmc:groom-trigger` fires; a backlog growing faster than five per grooming is never read through.
- G4 stale open work: grooming reads only `backlog` rows. Rows `open` or `planned` with no movement (#503 open since 2026-11-07, #498 planned and quiet since 2026-11-11) are the work-in-flight lines' (`dmc:work-in-flight`), which report and never close.

Proposed additions (to revision 1's definition of done):
- G1: `dmc:backlog-staleness` gains `unwanted-candidate`: a row read `holds` at two readings `hygiene-stale-days` apart and never promoted between them → listed in the run's one retirement form as "still true, still wanted?", its ground the two readings, so the operator decides keep or archive; a keep resets it.
- G2: an `undecided` row read twice the same way → asked in the same form, its missing input named.
- G3: the run reads five, or a tenth of the backlog, whichever is more; a backlog the reading has not covered in 90 days is a `dmc:groom-trigger` condition (due).
- G4: left out of this row, which grooms the backlog; stale open work is the work-in-flight record's and a row of its own if the operator wants it closed rather than reported.
