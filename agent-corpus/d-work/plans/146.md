# Plan #146 — falsify "dyad-system models explicit-mode better; dsys models implicit-mode better"

Base commit of `main`: 1178fcb. Builds on #142, #144 and #145.

## Intent as read
The Operator's model of human–agent interaction has two modes:
- **explicit-mode**: the *agent* receives and processes a *human's prompt*, and outputs signals or
  artifacts.
- **implicit-mode**: the *agent* receives and processes *signals from an external system*,
  possibly the outputs of an earlier explicit-mode interaction.

The claim to falsify is **C = C1 ∧ C2**. C1: dyad-system models explicit-mode better. C2: dsys models
implicit-mode better. The model itself is also attacked, as the "standing license to challenge on
intent" allows.

| A1 | **C1: dyad-system models explicit-mode better.** Is its prompt → processing → artifact loop more complete than dsys's? | **Survives, scoped to "built and enforced".** | dyad-system is explicit-mode end to end, and enforced: an Operator prompt opens a d-work (Rule-3), a plan file and plan-`Y` bind the mutation, artifacts are PRs and reports, and Done-`Y` verifies the output against the prompt. | A2 | **C2: in dsys, is it an *agent* that processes system signals?** | **Refuted.** dsys's signal path is the automaton executor, which its spec defines as "**Not an agent.** It never prompts, never judges" (`automaton-executor-spec.md:33`). And it is spec only, "NOT approved for implementation" |

## Verdict
**C is refuted as stated.** C1 survives, scoped to operational modelling (A1). C2 is refuted (A2, A3):
dsys does not model an agent processing system signals. It models *automatic* processing without
an agent, plus a human-gated escalation to explicit-mode, and it models that escalation better than
dyad-system does (A5).

## Survivor
A refinement of the Operator's model, which both repos support:

| mode | who processes | the input | human role | best modelled in |
|---|---|---|---|---|
| **explicit** | agent | a human prompt | originates and disposes | dyad-system (built, enforced); dsys richer in typing, unbuilt |
| **implicit** | agent | a system signal | **pre-authorizes** (standing disposition) and disposes exceptions | neither: dsys specifies the pre-authorization (`set_standing`, three keys), dyad-system lacks it (#145 S2) |
| **automatic** | non-inferring executor | a system signal | none per signal; designs it beforehand, triages its exceptions | dsys (executor built on fixtures, I-14 totality, disclosures); dyad-system only for its own guards and hooks |

Plus the **escalation edges**: automatic → explicit (dsys: disclosure → drain → triage) and
implicit → explicit (both: anything outside the standing scope returns to a human).

**Corrected claim:** *dyad-system models explicit-mode better in practice. dsys models
automatic-mode, and the escalation from automatic to explicit, better. Neither yet models
implicit-mode, an agent acting on system signals under pre-given human authority, beyond
specification.* This also places the #143 budget argument: tokens are spent in explicit and
implicit modes, never in automatic-mode. So the budget lever is moving work from implicit to
automatic, which is dsys's design direction.
