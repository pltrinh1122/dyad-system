holds them, so countersign-system can use `infrastructure/` in zone `infra` (four zones), without
changing anything for dyad-system or its client. Prerequisite of countersign-system #2 (revision 3);
the Operator's `Y` to "adopt infrastructure/ … re-plan #2 … with the dyad-system core prerequisite

  `host-zone` (`workstation` | `infra`, default `workstation`). Durable per instance, unlike an
  environment variable (hooks, CI and a new session all read the tree, not the shell).

  `workstation` resolves to the host zone. Rule-1 gains one sentence (the host row is instance data
  read from the preferences); its falsification record gains the amendment; vocabulary if a term is
  added. Core 0.9.1 → 0.10.0 (new preferences).

  sysarch projectors (`project_schema`, `project_instances`), syseng `naming_rules.txt` read the host

- Preferences (preferences zone): dyad-system's `PREFERENCES.md` gains both keys at today's values.
- Infra: `BUNDLE.md` rows follow the versions.
- Evidence: with the defaults, `containment.py zones` and every guard's output are byte-identical to
  today's on dyad-system (a test pins it); a scratch instance with `host-path: infrastructure`,
  `host-zone: infra` classifies `infrastructure/*` as `infra` and has four zones.
