# Plan #6 — file modes from the index, not the disk bit (workstation#173)

Base commit of `main`: 7ddffdb. Refs workstation-173, workstation-202 (the live seed it blocked), #21
(the bundle whose archives this affects).

## Intent as read
"Verify, then close or fix." Verified — fix. `distribute._mode(p)` is `0o755 if os.access(p, X_OK)`:
the disk bit. This checkout is on the ntfs-3g mount (`fuseblk`, `core.fileMode=false`), where every
file reads executable, so (a) every archive built here carries 755 on every member — the v0.5.0,
dyad-operator-v0.5.0, sysarch-v0.1.2 and syseng-v0.1.2 assets I published today all show
`-rwxr-xr-x dyad/CLAUDE.md`, and CI's ext4 build of the same tree would not: the "deterministic"
archive is only deterministic per host (Rule-11 p5, syseng determinism); (b) `install()` chmods the
destination from the same bit, and on a `core.fileMode=false` destination `git add` ignores the disk
bit and records 100644 for every new path — the entrypoint and both hooks land non-executable, which
is exactly what rejected workstation's 197-h2 push. `dyadlib.tracked_mode`'s docstring already names
this trap (#135, #141); `distribute.py` never used it.

## Mutation
1. **Agent zone** (`dyad/scripts/distribute.py`, `dyad/tests/test_distribute.py`, `dyad/VERSION`):
   - `modes(repo, rels, tracked)` → `{rel: 0o755|0o644}`: from one `git ls-files -s` over the roots
     when `repo` is a work tree (never the disk bit); when the source is an archive, from the tar
     members themselves (`install()` keeps the archive handle instead of trusting an extracted tree,
     whose bits an ntfs mount already lost); the disk bit only for a bare directory that is no work
     tree and no archive, printed as a warning.
   - `archive_bytes` writes those modes → the same bytes on any host (determinism restored).
   - `install()`: after copying, when `dest` is a work tree, `git update-index --add --chmod=+x -- rel`
     for every 755 file (the one channel that reaches the index on a `fileMode=false` host; what
     workstation's stopgap does by hand, generalised over every tracked-755 path, no name list);
     idempotence compares `tracked_mode(dest, rel)` (or the disk bit where dest is not a work tree)
     against the wanted mode — a second install is still `0 changes`.
   - Test reproduces the mechanism on any filesystem, not only ntfs: a fixture repo with
     `core.fileMode=false`, a file chmod 755 on disk but `update-index --chmod=-x` (index 100644) →
     the archive member must be 0644; install into a second `fileMode=false` repo → `bin/dyad`'s index
     mode must be 100755 there. Plus a run on this mount itself (skipped where the path is not fuseblk).
   - `dyad/VERSION` 0.5.0 → 0.5.1 (patch).
2. **Infra zone** (`BUNDLE.md`): `version: 0.5.1`, row `dyad-operator | 0.5.1` — the bundle guard
   requires it once the core bumps; merges after PR 1.
3. After Done-Y: release counter-prompts for `v0.5.1` and `dyad-operator-v0.5.1` — the first archives
   built here with correct modes. The four assets published today are not withdrawn (tags never
   move; the extra exec bits on `.md`/`VERSION` members are harmless to run, wrong to keep as the
   reference build); the release notes name v0.5.1 as the corrected build.

## Falsification
- "Just hardcode the three executables" — refuted (the peer's own caveat): the set is whatever the
  index says is 755 — a craft's `templates/*.sh`, `server/*.sh`, the next hook — never a list.
- "Read the disk bit but skip on fuseblk" — refuted: the index is the truth on every filesystem
  (`git archive`, a clone, CI all read it); the disk bit is at best a fallback for a non-repo tree.
- "update-index stages the file, which install should not do" — survives, scoped: on a
  `fileMode=false` host there is no other channel to the index, and the installer's next step is
  `git add -A` anyway; documented in the install summary line, applied only when dest is a work tree.
- "Archives from an extracted tree lose modes on ntfs, so install-from-archive still breaks" — the
  reason modes come from the tar members, not the extracted files (mutation 1, second bullet).
