## Diagnosis (read from `dyad/scripts/package.py`, `merge.py` and `automaton.py` at the base)
1. **Each push runs the suite.** `automaton.run` calls `merge_mod.merge` once per PR, and `merge.attempt` pushes its
   own merge commit. The gate's `suite_gate` runs the suite for every push whose range carries code, so a cut of n
   PRs runs n suites.
2. **The evidence never matches.** The memo is keyed on the exact tree. A merged tree is never the PR head's tree
   (#558: `007c2667` merged against `31daeaba` at the head), even when the two differ only under
   `agent-corpus/d-work/`. #558's final main differed from the evidenced head `4d9b367d` in 13 files, all of them ledger,
   so the three runs, about 670 s, judged code the evidence had already passed.
3. **A lost race re-runs the suite.** A race re-merges onto a moved main, and the new tree misses the memo for the
   same reason. A retry with backoff cannot beat a gate longer than main's quiet interval: PR #600 lost twice.
4. **The draft's third point was wrong, and is corrected here.** The draft said the gate's own pass never writes a
   memo. The replay refutes it: the gate wrote one memo per merged tree, and a re-replay hit them, taking 79 s. A gate
   pass is partial, and so unmemoized, only when it skipped an installed root (#199 N5).

## Mutation (on plan-`Y`)
- **(a) One push per cut, all or nothing. Engineer, agent zone.**
  - `merge.py` gains `merge_all(repo, [(pr, sha), …])`: every check of steps 1–3 for each named PR, then the merges in
    the order the entry names, one `--no-ff` commit per PR in one worktree, then one push.
  - A refusal at any PR pushes nothing and is posted once to home, as today.
  - Each PR keeps its own merge commit, so GitHub marks it merged.
  - `automaton.run` calls it once per row.
  - `dyad merge <pr> --head <sha>` stays for a single PR.
- **(b) The code-keyed skip. Engineer, agent zone, `package.py`.**
  - (b1) `suite_memo_parts` gains `code`: the sha256 of `git ls-tree -r` of the tree with `<instance>/d-work/` and the
    events store pruned. `suite_memo_clause` gains a clause: a hit on every part except `tree`, with `code` equal, skips
    with one line naming both trees. This covers a re-merge after a ledger-only drift in the same checkout.
  - (b2) Under `--pre-push`, the gate also skips when the pushed tree's `code` equals the code digest of a head an
    operative `Y done` on the base names, with one line naming the row and the head. Diagnosis 2 is this case. It
    does not apply under `check --evidence`, which never reads a memo and never skips (Rule-2 Binding).
  - The evidence block gains a `code=<digest>` line.
- **(c) Ledger-only races are free.**
  - The automaton re-merges at once on a lost race, with no backoff. After a ledger-only drift, the second push hits
    (b1) or (b2) and runs the guards only.
  - The clerical lane (closes, notices) then runs beside the code lane without forcing reruns.

## Counter and reconciliation (Rule-10)
- **Path:** (a)–(c), inside the gate, one rule for every pusher.
- **Strongest counter:** (b2) lets a gate skip a suite on the strength of evidence it did not run. That is a judgement
  carried across machines, where until now every skip was proven on the pushing checkout.
- **Reconciliation:**
  - The evidence (b2) relies on is the evidence the Operator already ratified the merge on (Rule-2 Binding), for
    identical code.
  - The guards still judge every pushed tree.
  - Hosted CI corroborates on main.
  - The trust is put to the Operator as its own decision, and (a) with (b1) still delivers one run per cut without it.
- **Rejected alternatives:**
  - An automaton-only bypass: a privilege for one pusher.
  - Partitioning the code lane by path: unsound for selecting tests, and no faster on one runner (attack 4).
