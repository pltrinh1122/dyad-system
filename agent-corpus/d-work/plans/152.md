## Mutation (Seed-0)
**M1 — governance scaffold by the one install path.** Run `dyad/bin/dyad install
/home/user/countersign-system` from dyad-system `main`. That is Rule-11 p5's single code path:
deterministic and idempotent, writing the core craft `dyad/`, the bundled `crafts/sysadmin/`, the
`dyad-*` workflows, the git hooks, the preference and ledger seeds from templates, and one import
line in the host `CLAUDE.md`. **No instance data crosses.** Rule-11 p1 keeps the instance out of the
craft, and `dyad check` in the new repo scans for instance strings. So nothing of dyad-system's
ledger, nor anything of its commercial client, is copied. Then set `core.hooksPath dyad/hooks`
there.

**M2 — the architecture as a Tended craft, `crafts/countersign/`** (zone `craft`, Rule-1). A craft
authored here first and extracted later: the craft-instantiation play-book's D3', "a craft that does
not exist yet is authored here first". Contents:
- `README.md`: the Countersign Architecture in one page. Every consequential act carries a human
  countersignature, given per turn (explicit), in advance (implicit, a standing countersigned
  mandate) or beforehand (automatic, a countersigned release), with anything unsigned escalated
  back.
- `rules/architecture.md`: the three modes and four edges (codify, delegate, escalate, return) as
  target properties, citing #146's and #147's survivors.
- `vocabulary/CRAFT.md`: countersign, the three modes, the four edges, standing countersignature,
  and each of #142 §2's collisions resolved to one meaning. It must pass the craft vocabulary check
  (Rule-6 `check_craft`).

- `VERSION` 0.1.0, `MANIFEST.md` (`requires: dyad-operator>=0.9.0`). No guards yet: the craft
  guard's contract applies once code exists.
