## Intent as read
The test fixtures create git repositories with `tempfile.mkdtemp()` and remove almost none: 42 test
files across the core and the five crafts, 102 call sites. Measured on this host during #202,
`/tmp` went from 437,047 to 450,390 used inodes across one core-suite run — **about 13,300 inodes a
run** — into a RAM-backed tmpfs with a fixed 1,048,576. At 24,876 orphaned fixture directories the
inodes ran out while the bytes sat at 9%, and then: `unittest discover` died with
`OSError: Errno 28 No space left on device` (489 errors of 657 tests), before that it had timed out
at its own 600-second ceiling, the harness's own tool-output files failed, and **no push could leave
any clone**, because the pre-push gate runs the suite. It took a destructive host action under its own
counter-prompt to clear (#202's change-log row). With 611,529 inodes free that recurs in roughly 45
suite runs; this one session ran 27.

What this row does: make the suite sweep after itself at the one place every sanctioned suite run
passes through. What it does not do: fix the 102 call sites (attack A1), or touch the crafts.

## Mutation proposed — one agent-zone PR, one merge
1. **`dyad/scripts/package.py`, `run_suite`** — the one child every suite run goes through
   (`check_rule_12` and `cmd_tests` both call it): make a temp root in the *parent*
   (`tempfile.mkdtemp(prefix="dyad-suite-")`), hand it to the child as `TMPDIR`, `TMP` and `TEMP` in
   the env `suite_env()` already builds, and remove it in a `finally` — in the parent, because the
   child is killed outright at the 600-second `timeout` and runs no cleanup of its own (attack A5).
   `DYAD_KEEP_TMP=1` skips the sweep and prints the path, so a failing run can still be read
   (attack A3).
2. **`dyad/tests/test_package.py`** — Rule-12 property 1, the check that enters with the code: the
   child's `tempfile.gettempdir()` is the root `run_suite` made; the root is gone when `run_suite`
   returns, on a passing target and on a failing one; `DYAD_KEEP_TMP=1` leaves it and names it; and
   the env carries all three variables, since a subprocess may read any of them.
3. **`agent-corpus/audits/INCIDENTS.md`** (183 → 186) — the rows this seat owes, each `d-work` cell
   naming where it happened: #202's I1 (the live row #202 used as a CLI fixture and set `done` in the
   working tree, restored from `HEAD`), #202's I2 (this row's own subject: the inode exhaustion that
   stopped every push), and #326's I1 (the miscount below).
4. #326's row, plan and provenance record.
