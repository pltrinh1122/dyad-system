## Intent as read
The host's active `gh` account is `asg-peter`, which is not a collaborator on
`pltrinh1122/dyad-system`, so `gh pr create` has been refusing since #178 and that d-work had to be
merged locally. The Operator asks for the active account to be `pltrinh1122` again. Both accounts
are already in the keyring, so this is a switch, never a re-authentication.

## The host action (Rule-8; classed by `crafts/sysadmin/rules/host-mutation.md`)

(classes, the change log's columns, `actor` naming hands only) and `ops-scripts.md`;
`workstation-corpus/` holds no rules of its own, only `INFRASTRUCTURE.md`.

| | |
|---|---|
| **action** | `gh auth switch --user pltrinh1122` |
| **class** | **reversible** — it changes state and has a stated undo (the craft rule's second class, beside `git config`) |

`gh` is a declared library row of the manifest (`dyad/infrastructure/INFRASTRUCTURE.md`, 2.45.0

## The record this action requires, and the file it needs
Rule-8's Conduct and the craft rule both require a change-log row in
`<host-path>/CHANGELOG.md` — and **that file does not exist**. The craft guard has been asking for
it by name on every run: "seed 'CHANGELOG.md' not copied to workstation-corpus/CHANGELOG.md". So
this d-work seeds it from `crafts/sysadmin/templates/CHANGELOG.md` and writes the first row. That is
not scope creep: a required record cannot be written into a file that is absent, and Rule-8's
Enforcement makes the absence itself a breach to report.

**Sequencing, and why the switch comes first.** The change-log row lands in a workstation-zone PR
(Rule-1), and a PR cannot be opened until the account is switched. So the order is: plan-`Y`,
switch, verify, then commit and open the PR that records it. The record follows the action by one
step, which Rule-8 permits — it requires the row in the same d-work, not before the action.

## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | It is not reversible in practice: switching may drop the other account's token. | **Refuted** | `gh auth status` shows both accounts logged in to github.com via the keyring, one active. `gh auth switch` changes which is active and nothing else; the undo is the same command with the other name. |
| 2 | Another session may depend on `asg-peter` being active, and `gh`'s active account is global to this host. | **Survives, scoped — and it is the real cost** | It is global, so this does affect any concurrent session. `dyad session list` shows no live session but this one, all others stale, and the Operator has asked for the switch directly. Stated rather than assumed: if a peer is mid-PR under `asg-peter`, this will refuse it the same way #178 was refused, and the undo is one command. |
| 3 | Do nothing: #178 merged locally without a PR, so the refusal is survivable. | **Refuted** | It is survivable once. Rule-2's Binding rests on a reviewable PR under `merge-disposition: with-done`, and Rule-14 property 3's local-merge path is written for an unreachable hosting, not for a standing identity mismatch. Leaning on it repeatedly would turn an exception into the practice. |
| 4 | Seeding the change log is a second concern and belongs in its own d-work. | **Refuted** | The action requires the row; the row requires the file. Splitting them would mean performing a reversible host action with nowhere to record it, which is the breach Rule-8's Enforcement names. |
| 5 | Use an ops script (Rule-18) so the Operator runs it. | **Refuted** | Rule-18's trigger is a host action the Agent *may not* run — privilege, credentials, physical presence. Both accounts are already authorized here and the Agent can run this itself, so the trigger does not fire. |
| 6 | The switch is destructive, not reversible: it changes who the world sees. | **Refuted, scoped** | It changes which token `gh` presents next; it writes nothing to either account and loses no data, and the craft rule's destructive class is "no undo, or loses data, or the undo is untested". The undo here is one command and will be run in verification if the postcondition fails. |
