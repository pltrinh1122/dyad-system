## Finding — the two READMEs draw a line, and it does not fall where #27 put the file
- `crafts/sysarch/README.md`: "its entities and their relations, the contract every guard meets,
  the manifest's form, the projection surfaces, the store patterns and the release shape". Every
  one of its six rules is **structural**: what a thing is shaped like and where it sits.
- `crafts/syseng/README.md`: "*Implementation* discipline — how the code that realizes a design is
  written so it stays verifiable". Every one of its seven rules is **behavioural**: what the code
  does at run time (`invariants.md`, `determinism.md`, `idempotence.md`, the `assert` ban).

`failure.md`'s three properties, tested against that line:
1. *Early is a place, not a moment* — the ladder declaration → transaction → run → use. Placement,
   but of a **detection in a run**, not of a file in a tree. `guards.md` places a guard module;
   this places a check's rung. Different axis; not sysarch's.
2. *Loud is named and attributable* — every fault and every skip prints a line naming itself.
   Run-time output. Behavioural.
3. *Fatal is not early* — a run reports every fault and does not abort at the first. This is
   `crafts/syseng/rules/invariants.md` property 4 verbatim in substance ("a FAIL is red but the
   checks still run") and property 3's stated reason for banning `assert` ("stops at the first
   failure"). Behavioural, and already half-written in syseng.

Two of three land in syseng outright; the third lands on an axis sysarch does not own.

**The orthogonality test settles it.** If `failure.md` goes to sysarch, sysarch owns *where a
fault is detected* while syseng's `invariants.md` owns *what a run does having found one* — one
concern split across two crafts, which is the gap Rule-5 names for the Agent Rules and the craft
READMEs reproduce for crafts. In syseng the stance sits with the instruments it governs, one rung
above them, and `invariants.md` becomes its first instance rather than its rival.
