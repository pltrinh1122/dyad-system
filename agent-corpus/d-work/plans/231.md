# Plan #231 — release readiness for the next release, by scanning every active branch

Base commit of `main`: 423a50e04fa8d8bc8c17927707cec6e260670da2

Revision 2 (2026-10-07, after the Operator's `N`: *what are the significant enhancements that the new
release would bring*). Revision 1 answered only whether the release can be cut. It assumed the
downstream value was self-evident and never named it, so the Operator could not weigh the hold
against what the hold is costing. Revision 2 leads with what the release delivers and keeps the
readiness verdict second, where it belongs — the reason to care about the blocker is the value it is
sitting on.

## Intent as read
Name what the next release would give a downstream installation, in terms of what those systems can
then do or stop paying for, and then say whether it can be cut. The branch scan is the method the
Operator named for the second half, not the whole question.

## Method (read-only, performed before this plan was written)
1. `git fetch --all --prune --tags`; fast-forward `main` (it was 240 commits behind).
2. All 160 remote branches: `git rev-list --count origin/main..<branch>` and the three-dot diff of
   each branch that is ahead; `gh pr list --state open`; the one local branch.
3. Per component, `<tag>..HEAD -- <root>`: commit subjects, file count, insertions and deletions.
4. Every `VERSION` against `git tag -l`; `BUNDLE.md` rows against the tree; every craft's
   `MANIFEST.md` `requires:` floor against the tags that exist.
5. `dyad check` locally (exit status and `fail` count); `gh run list --branch main` and the failing
   job's step list.
6. The measured figures behind the performance work, read from the audits that recorded them
   (`2026-09-30-test-performance-refactor.md`, `2026-10-02-test-reduction.md`), never re-derived here.

## Part A — what the release would deliver

The core craft is 27 commits and 75 files past its released tag (`+5920 / −756`). Grouped by what a
downstream system gains:

### A1. The push gate stops costing two and a half minutes (#199, #164, #162, #176)
The single largest change for anyone running this practice. Three skips, each measured in two
independent clones, n = 3:

| act | before | after | ratio |
|-----|-------:|------:|------:|
| `check --guards`, empty range | 145.16 s | 2.68 s | **0.018** |
| `--pre-push`, tree already passed (suite memo) | 147.41 s cold | 2.73 s hit | **0.0185** |
| `check --evidence` (the merge evidence) | 143.52 s | 149.24 s | 1.040 |

The suite memo is a per-checkout record that one exact tree passed every root, keyed by the tree's
sha256, the interpreter, git's version, the roots run and the instance's settings; the pre-push path
reads it, `check --evidence` never does. That asymmetry is the design, and the last row is the proof
of it: the evidence path got *slower* (the cost of 39 more tests), because no skip is allowed to make
the merge evidence cheaper. An installed, unmodified craft tree also skips its own test root at the
gate — a downstream system does not re-run the author's tests to push its own ledger.

### A2. The test mass shrank without losing a check (#203)
`dyad/tests` went 634 → 584 cases: 39 whose assertion a surviving check already made were merged
away, 12 became **fail-loud checks** at their strategic points (a boundary, a state transition, an
impossible condition — raising in the code itself rather than passing in a test), and the stale and
unfalsifiable ones were retired. Core modules now enforce their pure `INVARIANTS` at import, so a
broken data model fails loudly on load instead of waiting for a suite; `TREE_INVARIANTS` holds the
ones that read the tree. Rule-12 property 1 and the vocabulary carry the new terms.

### A3. A system can put its host records where it wants (#175, #179, #169)
`host-path` and `host-zone` become preferences, seeded by the template. A system that keeps no
separate host corpus runs four zones with its host records in `infra`; one that does keeps five. The
manifest gains a `profile` cell (`authoring` / `operating` / `both`) and a system's own operating rows
become its instance contribution — the core no longer ships one machine's operating dependencies to
every install. `.claude/*` is classified as `infra`, so committed harness adapters have a zone. The
host tests are hermetic: a suite run never touches the real host.

### A4. Provenance fails where the gap is born, not forever after (#191)
The provenance guard splits in two. A transaction check judges each pushed commit — a new row brings
its words, a `backlog`→`open` brings the prompt, k new dispositions bring k entries — so the gap fails
on the push that creates it, in the session that wrote it, including a session that has not loaded the
Rule. The state check now reads an instance-owned legacy list instead of a hard-coded `SINCE_ID` that
had drifted into warning about unrelated rows. `dwork new|state` refuse to write a row or a
disposition without its words, and make every refusal before the first write.

### A5. The pre-push hook judges what git is actually pushing (#194)
It read `origin/main..HEAD` and the tree on disk; it now reads the refs from git's stdin and refuses a
push it cannot judge — a ref that is not the checked-out HEAD, or a dirty working tree. A deletion or
an already-pushed ref carries no new commit and passes. (This session hit the new refusal once, for an
uncommitted presence file: it works.)

### A6. Two recurring clerical faults are fenced at the source (#133)
A `;` inside disposition text used to split into a second ledger entry and fail Rule-7's count — four
recurrences. `dwork new` used to take `--backlog` as the row's title, which is immutable, so six rows
on `main` are still titled `--backlog`. Both are refused at the source now. A downstream system
inherits the fences without inheriting the scars.

### A7. Measurement and review become standing procedures (#213, #223, #166, #227)
- **d-work trace** — per-d-work timing from the first anchored prompt to the Done-`Y`, every second in
  exactly one bucket (the Operator's wait, the Agent's inference, a mechanical kind), with a play-book,
  a run-book, a store and its own guard. The new preference `dwork-trace` decides whether every
  completion cites one. No transcript is ever committed, so an ephemeral session's timing survives it.
- **standing audit play-book** — the review exercise, repeatable.
- **ds-report-incidents play-book** plus one parser for the incident log, and the trace store checked
  in the guard pass rather than only inside the suite (a guard-only push used to skip it).

### A8. The Tended crafts
- **syseng 0.4.0 → tree**: the fail-loud invariant protocol as a craft rule, and its guard fails a
  core module that does not enforce its `INVARIANTS` (+529 / −76). This is the rule behind A2.
- **sysarch, sysadmin**: read the host path (A3); sysadmin also loses a duplicated rule table.
- **countersign 0.2.0 and disclosure 0.1.0, never released at all.** countersign carries the
  Countersign Architecture's eight-entity schema and the interaction model — five primitives, eight
  imperatives, the `yes`/`no`/`amend` answer grammar every system's own words map onto. disclosure
  carries one rule, one gate and one surface for what may leave a dyad system in a document handed
  outside it: *assembled by allow-list, gated by deny-list*. Both are installable practice no
  downstream system can obtain today.

**The one-line answer.** The release makes the practice cheap to run (A1, A2), portable to a system
shaped differently from this one (A3), and self-recording where it used to rely on the Agent
remembering (A4, A6, A7) — and it is the first release that could carry countersign and disclosure.

## Part B — readiness

### B1. Nothing is waiting to be merged
Of 160 remote branches, three carry a commit `main` lacks — `ledger-198-open`, `ledger-206-open`,
`ledger-224-open` — each one ledger-only commit whose row is already on `main` and `done`. They are
leftovers, not work. No open PRs. The one local branch is 0 ahead. The hold #198 placed on the release
(PRs #223, #224) is discharged.

### B2. Every component is unreleased, and the core's number understates its tree
| component | `VERSION` | newest tag | commits to its root since `VERSION` was set |
|-----------|-----------|-----------|---------------------------------------------|
| dyad-operator | 0.10.1 | `dyad-operator-v0.9.0` | 21 |
| sysarch | 0.3.0 | `sysarch-v0.2.2` | 0 |
| syseng | 0.4.0 | `syseng-v0.3.0` | 2 |
| sysadmin | 0.2.1 | `sysadmin-v0.1.3` | 1 |
| countersign | 0.2.0 | none | 2 |
| disclosure | 0.1.0 | none | 0 |
| bundle | 0.12.1 | `v0.11.0` | — |

Part A is what 0.10.1 is labelling: a new guard, six amended Rules and changes to the one distribution
code path. That is minor-level change wearing a patch label; syseng is the same case (its 0.4.0
predates A8's protocol). No guard fails either number, because neither is tagged.

### B3. The tag order is forced, and the bundle's row set is a decision
sysadmin, sysarch and syseng declare `requires: dyad-operator>=0.10.0`, disclosure `>=0.9.1`; the floor
resolves against tags and the newest core tag is 0.9.0, so **every craft's install is refused today**
(`dyad check` prints one warn per craft). Core tag first, crafts second, bundle last. `BUNDLE.md` omits
countersign and disclosure, which #156 permits only while a craft is unreleased: releasing either
forces an infra-zone `BUNDLE.md` edit in an order Rule-1 cannot satisfy in one PR — the #170 class,
already a backlog row.

### B4. Blocker: the only mechanical check of what a release publishes is red
`rule-11 package` has failed on every push to `main` since 2026-09-25, latest at `0699b69` (2026-10-06).
The failing step is, verbatim: *install core, then export and install the sysadmin craft, into a scratch
repo; run the guards there; install both again (idempotent)*. `check` and `build` in the same job pass.
That step is Rule-11 property 5's only mechanical check of the install path, and an install of that
path is what a release publishes. Row #201 holds the diagnosis — the core install writes a bundled
craft's tree but no `crafts/REGISTRY.md` row, so the later `craft install` of the same craft is refused
as locally authored — and row #228 is open to repair it. Locally `dyad check` exits 0, no `fail` line,
130 package files, warns only; that does not contradict CI, because the kernel-only path never installs
into a scratch repo.

### B5. Verdict
**Not ready, and the cost of the hold is now explicit.** Part A is what is sitting behind B4: a
55× cheaper push gate, a portable host layout and two unreleased crafts. One blocker (#201, repair
open as #228), one correction owed (core `VERSION` → 0.11.0, syseng → 0.5.0), two decisions (whether
countersign and disclosure join this bundle, and therefore six tags or eight).
