# Plan #350 — one seat, one holder: scope the seat's write and stop the presence `files` line reading prose

*Rule-15 phase 1. Base commit of `main`: 8c9e0b1 (2026-10-20). refs: 297.*

## Intent as read
The Operator renamed this session `cab-e2c6869c: term-1 (ds)` — the hosting's display name now
carries both the seat and the harness session id, which is the human half of the disambiguation
#329 surfaced. The mechanical half is unfixed and is what this row does. Two defects, both
observed live on `main` during #329:

1. **Two live holders write one presence file.** `dyad session touch` warned that
   `ds-cabinet-term-1.md` was last written by a different, still-live process (writer
   `fef59c4e265d`), and a third writer (`d55ac2a1f40e`) overwrote it between this session's touch
   and its `git add`, so commit `55c02d0` carries another holder's `rows:` line —
   `259 328 329 331 334 336 338 339 343 345 346`, of which only 329 and 346 are this session's.
   Cause: `~/.bashrc:148` exports `DYAD_SESSION=ds-cabinet-term-1` for every interactive shell on
   this host (written by #297 for "every future session you run from here"), and three `claude`
   processes are now live in three trees. Rule-16's Presence claim — "only that session ever
   writes it — zero cross-session write conflict by construction" — is therefore **false as
   written**: the construction holds per `DYAD_SESSION` value, not per session.
2. **The `files` union reads prose as paths.** `sessions.files_touched` matches every line
   beginning `files touched:` and swallows each following non-blank, non-heading line as a
   continuation. Plan `336.md` mentions the phrase 17 times in prose, so the union on `main` now
   holds tokens like `amends`, `carried`, `children`, `twenty-three`, `until`, `were` beside real
   paths. The near-miss signal Rule-16 exists for is reading noise.

## Mutation proposed
- **A1 — the parser (agent zone).** `dyad/guards/agent/sessions.py` `files_touched`: keep a token
  only if it is path-shaped (contains `/`, or ends in a tracked extension), and stop a match whose
  own line yields no path-shaped token, so a prose mention of the phrase contributes nothing.
  Tests in `dyad/tests/guards/agent/test_sessions.py`: plan 336's real shape (many mentions),
  a wrapped list (the case #24/#179/#185 added), a brace group (still dropped whole), and a prose
  paragraph after a real list.
- **A2 — the write (agent zone).** `touch()` refuses, rather than warns, when the file's last
  writer is a *different and still-live* process under the same `DYAD_SESSION`, naming both writer
  tokens and telling the second holder to pick its own value. A dead previous writer still
  passes — that is a later holder re-taking the seat, which #295 settled as correct — so the
  refusal is exactly the two-live-holders case and nothing else.
- **A3 — the Rule and its record (agent zone).** Rule-16 Presence's parenthesis is amended to say
  what is true: one file per `DYAD_SESSION` value, written by whichever process holds that value,
  and two live holders of one value are refused by `touch()` (A2) rather than merged.
  `dyad/falsification/rules/rule-16-concurrent-sessions.md` gains this attack with its evidence
  (`55c02d0`, the two writer tokens, the merged `rows:` line) and the Rule-5 pairwise statement;
  `agent-corpus/falsification/seat-vs-harness-session.md` (#295) gains the live instance of its
  F1 case.
- **A4 — the incident (agent zone).** One `agent-corpus/audits/INCIDENTS.md` row: this session
  committed another holder's presence content in `55c02d0`, cause the unconditional profile
  export plus `touch()` warning where it should refuse, consequence a pushed presence file whose
  `rows` names seven rows this session never opened.
- **A5 — the id collision (agent zone).** A second `INCIDENTS.md` row: this row was first
  allocated **349** and pushed; the push was rejected because the cos had allocated 349
  concurrently for the same broadcast rename prompt (`8c9e0b1`, title
  `cos-59cec502: cloud (ds)`). Resolved by abandoning the local commit, resetting to
  `origin/main` and re-allocating through the CLI as 350 — ids are allocated
  `max(origin, local)+1` (`crafts/sysarch/rules/stores.md`), which is collision-free only when
  the two sessions fetch at different moments, and two seats answering one broadcast prompt is
  precisely the simultaneous case. Cause, consequence and the resolution are the row's content;
  no plan item was lost, and the plan file is byte-identical but for its own id.

No host action: `~/.bashrc` is **not** edited. A2 makes the collision loud at the moment it
happens, which is cheaper than changing the Operator's profile and leaves the seat takeable from
any terminal, as #297 intended. One PR, agent zone, citing this row.

mandate scope: none — four named deliverables, no class of row accreted.
disposition budget: 2 — this plan-`Y` and one Done-`Y`.
