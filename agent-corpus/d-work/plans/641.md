**Ambiguous, with the reading taken:**
- **A1. M only, or P too.** Read: **M**, the records whose every outcome is a predicate. A P record cannot be
  labelled mechanical while one of its outcomes needs judgement. Coding its mechanical part as a pre-filter is a
  different change: the record stays `inference` and gains a helper. That is adjacent, and would be a row if you ask.
- **A2. The test.** Read: a record is codified only if each input is read from a stored fact, and each outcome's
  `when` is a predicate a test can exercise.
  - A record whose input is not stored is not codable. `batch-engagement` reads whether your reply was a bare token,
    which may not be stored. So the plan re-checks each of the 20, and one that fails the test is reported and kept
    as inference.
- **A3. Behaviour.** Codifying must not change an outcome. Each record's tests pin its outcomes as the record states
  them, so a record whose code disagrees with its prose is a finding to ask about, never a silent change.

**Adjacent, out:**
- the 33 P records' mechanical parts;
- the 34 I records;
- any change to an outcome's meaning.

Each would be a row if you ask for it.
