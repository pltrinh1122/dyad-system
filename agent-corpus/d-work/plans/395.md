## Intent as read
The tag pushes the hosting refused from this session (HTTP 403) rewritten as one shell script that runs
from any cwd on any host with git and the Operator's own push rights.

## Delivered (no repo mutation): the script
`release-tags.sh`, POSIX sh, printed in the reply. It makes a throwaway bare, blob-less clone of the
remote into a temp dir (so cwd and any existing checkout are irrelevant), verifies each release commit
exists there at its exact sha, refuses a tag that exists on the remote at another sha (tags never move,
Rule-11 p4), skips one already there at the same sha (idempotent), cuts both annotated tags with the
release messages (the Y, the head, the evidence sha256, the archive sha256), pushes both in one push,
and lists them from the remote. `DRY=1` does everything but the push; `DYAD_REMOTE` selects the SSH
form. Dry-run observed from `/tmp` in this container: both tags cut at their commits, would push.

## Finding: the bundle guard fails every push once `cos-v0.1.2` exists
Observed in a scratch worktree with both tags present: `FAIL [bundle] 'cos' is in the tree but has no
bundle row` (Rule-11 p7: a released craft without a row fails). With one row added and the bundle
version bumped the guard passes (`ok [bundle] 5 components, v0.15.0`). So after the tag push every
push to `main` by every seat — ledger-only included — fails at the pre-push gate until the row lands.
The row must therefore land **before** the tags are pushed: an unreleased craft may have a row (the
guard only warns), a released one must.

## Mutation proposed (one child, distribute's domain)
An infra-zone PR: `BUNDLE.md` gains `| cos | 0.1.2 |` and `version: 0.15.0` (the bundle's own
version, independent of the core's); nothing else (sysarch 0.3.2 and syseng 0.4.1 stay unreleased and
keep warning, as #170 allows). Held by distribute-b7a0a9fc, delivered with its evidence block, merged on
the Done-Y of this row; then the Operator runs the script. Mandate scope: one row for that PR, ceiling 1.
Order: the row lands → the script pushes the tags → the release workflow publishes → `v0.15.0` (the
bundle's own release, Rule-11 p7) may be asked afterwards as its own question.
