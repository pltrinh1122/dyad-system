**Ambiguous, with the reading taken:**
- **A1. "Upstream row".** Read: the row the fix would ride. That is either the row the fault blocks, or another open row
  whose files the fix shares, as #622 was for #620. A done row is never reopened (Rule-16), so the row that caused the
  fault is never a candidate.
- **A2. "Blocking".** Read: it stops a row's next act. An evidence block that is red, a gate refusal, or a merge that
  cannot run all count. A warning that blocks nothing is out: it is recorded, and work continues.
- **A3. "Downstream".** Read: surfaced in one row's verification, with its cause outside that row's own diff. A fault
  inside the row's own diff is the row's to fix, and nothing to decide.
- **A4. Who opens its own row.** Read: the criterion recommends; you dispose. A finding reaches a row only through your
  disposition (Rule-3 Scope). So the "own row" outcome is a proposal put to you, with the blocked row held meanwhile.

Duplicate: none. False premise: none.

**The threshold, proposed for the plan to falsify.** A blocking downstream fault gets its own row when any one of these
holds:
- (a) it blocks more than the one row, or `main` itself;
- (b) it is a second occurrence of the same failure mode;
- (c) no open row's definition of done covers its fix, so you would judge it on its own (`altitude` `split`);
- (d) its fix needs a zone or a unit the host row does not have.

Otherwise it rides: inside the blocked row, or in the open row whose files and definition of done cover it. Either way
the plan says so, and a revision is asked whenever `plan-departure` says `new-plan`. An existing fix is ported first,
before any of this.

**Applied to its own case:** #622 revision 2 meets (a), since `main` was red too, and (b), as F16's second occurrence. By
this threshold it would have been its own row. It is built and authorized, so the completion evidence applies the
record to it as a finding. It is not undone unless you say so.

**Counter.** A row of its own costs three questions and a hold on the blocked row, where a revision costs one question.
The criterion makes small fixes slower.
**Reconciliation.**
- Riding coupled #620's Done to #622's whole landing.
- The same timing test reached three rows in two days.
- The threshold sends a fault to its own row only when it spreads (a), returns (b), stands outside the host's purpose
  (c) or outside its zone (d). Every other fault still rides, at one question.

### Decision 1: the cheapest lawful home for a fix that is not the blocked row's own
**Choice: a carried row.** The d-work play-book gains a step that prescribes one class of row: the fix of a fault that
stops the plan's row from outside its own diff, when the fix only restores what is already stated (Decision 2). A plan
that states the class carries such a row under its plan-`Y`. It is born `open` (`dwork new --mandate <row>`), with a
plan file of its own that is not asked. Its Done rides the blocked row's done-`Y`, except as Decision 2's spread rule
says. Each plan states the class in one line:

    Mandate scope: the d-work play-book's blocker-fix row (a restore that stops this row from outside its diff); ceiling 1.

A plan that carries other rows adds them on the same line, the total last.

**The attack against Rule-2.** Rule-2's never-accretable list ends: "any mutation the plan did not describe". Is a
class described by rule a mutation the plan described?
- **For a restore, yes.** Its end state is already stated, by a Rule, a record, a check or a test the operator has
  ratified. The class names the row by properties a reader can decide (escalate-edge T2): the row's next act stopped,
  the cause outside its diff, and no stated text changed. #570 described its children the same way, by end state.
- **For a change, no.** Its end state is stated nowhere, so it is a mutation no plan described. It is asked: a
  revision (one question), which describes it.
- **So the class carries restores only.** That is why Decision 2's test is restore or change. Rule-2's list is
  unchanged, and no Rule-2 sentence is needed (Q3).
- **T5, "the row's initiation is the mandate's own operator words".** The row's entry 1 is the plan-`Y`'s words,
  copied (Rule-7 property 4). The agent's finding only shows that the class is met, as #589's did.

**Where the class cannot carry the fix, it falls back to a question:**
- a destructive host action, a release, an intake or a preference value: its own question, under its Rule;
- a reversible host action: Rule-8 wants the plan to name it, so a revision names it;
- a Rule edit: a Rule edit changes stated text, so it is a change, and a revision.

### Decision 2: the threshold, recast as one test
**When does a fault still need your attention?** Only when your judgment could change the outcome before the work is
spent. That is:
- the fix is an act a `Y` never carries (its own question);
- the fix **changes** what a check, gate or Rule decides (a revision, before it is built);
- the fix **adds** what the system did not have, so you would judge it apart (its own row, `altitude` split).

Otherwise the fix is a **restore**, the agent decides it, and the evidence reports it.

**The test.** A fix is a restore when, after it, every Rule, record, check and test decides what its stated text
already says, and:
- no stated text changes: no Rule sentence, no record outcome, no threshold, ceiling or assertion;
- no check leaves the evidence block or the pre-push gate. Rule-2's Binding rests on what the evidence covers. A
  check that moves out of it is a change even when a classing text supports the move (Q2).

Anything else is a change. A fix that cannot be told apart reads as a change.

**The outcomes, in precedence order:**

| outcome | when | then | new questions |
|---|---|---|---|
| its own question | the fix is an act Rule-2 never lets a `Y` carry | asked under the Rule that owns it; the rest of the fix follows this table | 1 per act |
| the row's own | the cause is in the blocked row's own diff | not downstream: the row fixes it; `plan-departure` says whether that is a new plan | 0 |
| port the fix | the fix is already on `main` | the blocked row's branch takes `main`: an execution detail, reported | 0 |
| ride another open row | another open row's plan describes the fix, or its PR holds it | worked there as planned; the blocked row's Done is asked with that row's in one batch, its PR merged after. Never by revising that row. | 0 |
| its own row | the fix adds what the system did not have (a verb, a store field, a preference, a Rule property); or no row can carry or revise it (the blocked row's Done is recorded, or no row's work found it) | proposed, ordered first, the blocked row's board entry held on it; or the home names it in the next mandate of follow-ups | 3 (2 under `off`); none of its own inside a mandate |
| a carried row | a restore, and the blocked row's plan states the class with its ceiling unspent | born `open` under that plan-`Y`, its own plan file unasked; its Done as below | 0, or 1 |
| a revision | every other fix: a change, a reversible host action, or a restore the plan cannot carry (no class stated, ceiling spent) | the blocked row's plan is revised to describe it; the revision may carry it as a row, its Done as below | 1 |

Default: a revision. It shows you the fix before it is built, at one question.

The record reuses `plan-departure`'s outcomes rather than rebuilding them: port is its `execution-detail`, a carried row
its `mandate`, a revision its `new-plan`.

**The blocked row** is the row whose next act the fault stops. A fault that only turns `main`'s own checks red
(corroboration, the automaton's run, a sweep) has as its blocked row the open row whose work found it. A fault that no
row's work found, such as one a sweep notice reports, has no blocked row. It is the home's promotion candidate (P1, a
live defect).

**Spread sets when a carried row's Done is asked:**
- it stops the blocked row alone, or only `main`'s own checks: it rides the blocked row's done-`Y`, named under
  `accreted`. 0 questions.
- it stops another row too: it joins the first Done question its landing holds. That is the blocked row's, or the
  other row's, whose PR is then based on the fix's. 0 new questions.
- it stops every code push or every evidence run on `main`: it is asked alone, as soon as its evidence is clean, and
  lands first. 1 question. Every unit waits on it, and only your Done lifts it.

**Recurrence moves no outcome.** The completion evidence and the incident row name the failure mode and its earlier
occurrence. The fence is the incident-hardening exercise's, which reads the log. You can still amend at the Done you
answer anyway.

**Zone and unit move no outcome.** A fix in another zone is its own PR (Rule-1). The unit that builds it within its
charter is an execution detail. The preferences zone (a preference value) and the host (Rule-8) are the exceptions, and
the table already sends them to a question.
