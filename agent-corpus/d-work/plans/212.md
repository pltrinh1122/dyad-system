# Plan #212 — a performance trace for each d-work, reflexive

*Rule-15 phase 1. Base commit of `main`: 3a354c4 (2026-10-05). refs: 211 to 204.*

## Intent as read
"When done" means after #211's Done. Produce one performance trace per d-work, so that the
Operator and the Agent assess bottlenecks by the same measures. "Comprehensive" means the whole
d-work, not only the test runs. "Reflexive" means #212 traces itself too, by the same format.

## The trace format (the proposal to align on)
One file per d-work. Every second is placed in exactly one bucket. Overlap, such as a background
run while the Agent infers, is shown as overlap and never summed twice.

1. **Timeline.** Every event in UTC order, each with an actor: the Operator's prompt arrives; plan
   file written; plan question asked; plan-`Y`; each push (with gate duration); each evidence run;
   each PR created or merged; Done question asked; Done-`Y`; merges.
2. **Buckets of wall time,** from the d-work's first event to its last:
   - **Operator.** From a counter-prompt asked to its answer. The Agent waits.
   - **Agent inference.** Model turns: from a tool result, or from the prompt, to the next tool call
     or reply.
   - **Mechanical, by kind:** full-suite runs (push gate, evidence); guards-only push gates; GitHub
     API calls (create, merge); git and other local commands; subagent or workflow time.
3. **Counts.** Commits, ledger PRs, work PRs, full-suite runs, guards-only runs, tool calls, output
   tokens.
4. **Bottleneck line.** The top three buckets by share. The Agent-side share (inference plus
   mechanical, Operator excluded), compared with the median of the traced d-works.

## Sources (read-only)

  derived numbers only, never transcript text.
