## Intent as read

The Operator's disposition of plan #259 carried text: `Y: delegate to sub-agent`. Rule-3 Scope is
explicit that text accompanying a disposal is a prompt and opens a d-work, with no exemptions, so
this row exists because the Rule requires it and not because the direction is a second body of work.

The direction is read as **how #259 executes, not what it executes**: apply `delegation:
plan-and-execute` to the whole of #259's execution rather than to the mode records alone, which is
all plan #259 committed to. It is read as scoped to #259, not as a standing change — the preference
is already `plan-and-execute`, and a change to a preference value is a preferences-zone PR the
Operator disposes, never something read out of a disposition's text.

## Mutation this plan-`Y` authorizes

**No repo or host mutation of its own.** Every file #259's plan names is authorized by #259's own
plan-`Y`, already given; this row adds nothing to that list and takes nothing from it. What it
authorizes is a shape:

1. **Every draft of #259's output is drafted by a fork**, each in its own worktree, not by the main
   Agent: Part A's fifteen candidate rows and the change-log row; then, after PR-1 merges, one fork
   per group of modes for phase 1's records and phase 2's mitigation inventories.
2. **A fork reports the sentinel before it drafts** (Rule-3 Scope) and returns text, never a commit.
3. **Every act a disposition binds to stays with the main Agent**: the rows, the commits, the
   pushes, the PRs, the merges, the host actions and every counter-prompt. A fork that finds a
   reason to change plan #259 reports it; the main Agent stops and re-plans (Rule-3 Incidents).
4. **A fork's finding is not evidence until the main Agent has verified it.** The checks reported in
   any completion evidence are run by the main Agent on the exact head (Rule-2, Binding).
