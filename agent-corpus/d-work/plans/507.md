## Falsification
| # | attack | result |
|---|---|---|
| 1 | Invent a schema (Rule-13) | **refuted, scoped**: schema.org has the classification shape — `DefinedTermSet` (a set of terms) and `DefinedTerm` (one term, with `termCode`, `inDefinedTermSet`). A DMC is a `DefinedTermSet` whose terms are its outcomes; `dyad:` adds only what a classification *for deciding* needs: the question, the inputs, how it is judged, precedence, the default when undecidable, and the consequence of each outcome |
| 2 | A `.jsonld` record duplicates the prose Rule and drifts from it (Rule-6's one master record, by analogy) | **survives, scoped**: the prose stays the master; the record is its structured index and names its `dyad:home`. A guard fails a record whose home file is missing, whose `dyad:judgedBy` implementation path is missing, or whose outcome `name`s do not all appear in the home file (case-insensitive) — the cheap, mechanical drift fence (Rule-12) |
| 3 | One DMC is defined across two files (host-action-class: Rule-8 the authorization, sysadmin which actions) | **scoped**: the container is the file that defines the outcomes; the other file is `dyad:alsoIn`. Rule-8 keeps the authorization DMC's record (core) and sysadmin the action-to-class record — they are two decisions, two records |
| 4 | Records inside crafts are craft content and must stay generic (Rule-11 property 1) | **confirmed, procedure**: a craft's records go in its own tree (`dyad/dmc/`, `crafts/<craft>/dmc/`) and travel with it; instance DMCs (preferences, this instance's failure modes) go in `agent-corpus/dmc/`. `@id`s use a craft-relative IRI (`urn:dyad:dmc:<craft>/<id>`), not this repo's URL, so an installed copy names itself correctly |
| 5 | Zones (Rule-1): the records span three zones | **confirmed**: `dyad/` and `agent-corpus/` are both agent zone (one PR), every `crafts/*` craft zone (one PR, VERSION working bumps per craft). Two PRs |
| 6 | 120 hand-written records are a recurring inference task (Rule-13) | **survives, scoped**: the guard is the code the recurrence yields; writing each record stays inference, done once, checked mechanically thereafter |
| 7 | "DMC" is not a vocabulary term, and a guard named for it would be used by no Rule | **survives**: no Agent Rule is edited, so Rule-6 is not triggered; the term lives in the schema file's own glossary and the play-book for writing a record (`dyad/playbooks/dmc.md`) |
| 8 | Where does the schema live, and is a JSON-LD context enough to "standardize"? | **scoped**: a context fixes names, not shape. The standard is three files in the core: `dyad/dmc/context.jsonld` (the `@context`), `dyad/dmc/schema.md` (required keys, value forms), and the guard `dyad/guards/agent/dmc.py`, which enforces the shape on every record in every craft and the instance |

## Survivor — the DMC record schema
`@context`: `["https://schema.org", {"dyad": "urn:dyad:term:"}]` (the core's context file; a `dyad:` term is defined in
`schema.md`, never in a craft).

| key | from | required | holds |
|---|---|---|---|
| `@id` | JSON-LD | yes | `urn:dyad:dmc:<craft>/<id>` |
| `@type` | schema.org + ext | yes | `["DefinedTermSet", "dyad:DecisionCriterion"]` |
| `identifier`, `name`, `description` | schema.org | yes | the slug, a short name, one sentence |
| `dyad:decides` | ext | yes | the question it answers |
| `dyad:inputs` | ext | yes | what it reads (list of strings) |
| `hasDefinedTerm` | schema.org | yes | the outcomes: `DefinedTerm` with `termCode`, `name`, `dyad:when` (the condition), `dyad:then` (the consequence) |
| `dyad:precedence` | ext | no | order or tie-break among outcomes (e.g. the highest class wins) |
| `dyad:default` | ext | no | the outcome when undecidable (e.g. destructive when in doubt; explicit when a test cannot be answered) |
| `dyad:judgedBy` | ext | yes | `{dyad:kind: mechanical\|inference\|declared, dyad:implementation: <path or null>}` |
| `isPartOf` | schema.org | yes | the container: `urn:dyad:craft:<craft>` or `urn:dyad:instance` |
| `dyad:home`, `dyad:alsoIn` | ext | yes / no | the defining file (craft-relative path); other files that state part of it |
| `dyad:owner` | ext | yes | the Rule or craft rule that owns it (`Rule-11`, `sysadmin:host-mutation`) |
Forbidden, as in the identity record: versions, dates, commits, emails.
