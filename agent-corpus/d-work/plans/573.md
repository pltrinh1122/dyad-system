## Intent as read

2. **Remove the aliases** #554 names: `seat`, `attended-seats`, `waiting-on: seat <name>` and `executor`.

  which the home presents.

## What "public surface" means here (decision 1 of #570: the bundle and the core become 1.0; crafts keep their own numbers)
The surface is everything that a system installing `dyad-operator` writes, reads or types, and that would break on a
change. It has eight parts:

| # | part | what is frozen | source the test derives it from |
|---|------|----------------|----------------------------------|
| S1 | CLI | every `dyad <noun> [<verb>]` and its flags | the dispatch in `dyad/scripts/package.py` `__main__` and each `cmd_*` / script `main` |
| S2 | store formats | the path pattern and `key:` set of each store | each store's guard (named in the next table) |
| S3 | preference keys | every key a core Rule reads, and its allowed values | the `read by` column of `preferences-corpus/PREFERENCES.md`, filtered to Rule readers |
| S4 | Rules | Rule numbers 1–20 (17 retired, never reused), each Rule's `##` heading set, and its Intent/Target block | `dyad/rules/RULE-*.md` |
| S5 | DMC ids | every `@id` `urn:dyad:dmc:dyad-operator/<name>` in `dyad/dmc/` (104 today) | the `@id` lines |
| S6 | environment and repository variables | `DYAD_INSTANCE`, `DYAD_SESSION`, `DYAD_RUNBOOKS`, `DYAD_OPS`, `DYAD_HOST`, `DYAD_HOST_ZONE`, `DYAD_ROLE`, `DYAD_HARNESS_DIR`; repository variables `DYAD_AUTOMATON`, `RELEASE_APPROVAL` | `grep` of `os.environ` / `vars.` reads in `dyad/` and `.github/workflows/dyad-*.yml` |
| S7 | host-side hooks | `dyad/hooks/pre-commit` and `pre-push`; the workflows `dyad-package.yml`, `dyad-automaton.yml`, `dyad-release.yml`, `dyad-sweep.yml`; the import line `@dyad/CLAUDE.md` | `package.py` `CORE_HOOKS`, `WORKFLOW_PREFIX` |
| S8 | tag forms | `dyad-operator-vX.Y.Z`, `<craft>-vX.Y.Z`, the bundle's `vX.Y.Z` | Rule-11 properties 4 and 7 |

The S2 stores are:

| store | path | guard |
|-------|------|-------|
| rows | `<instance>/d-work/rows/<id>.md` (`id`, `title`, `opened`, `state`, `disposed`, `refs`, optional `mode`) | `rows.py` |
| board | `<instance>/d-work/board/<id>.md` and `_cos.md` | `board.py` |
| inbox | `<instance>/d-work/inbox/<unit>/<stamp>-<from>-<n>.md`, with its `.read` marker | `inbox.py` |
| presence | `<instance>/d-work/sessions/<id>.md` | `sessions.py` |
| provenance | `<instance>/d-work/provenance/<id>.md` (the title line and the `## <n> <kind> <date>[ <note>]` entry form) | `provenance.py` |
| traces | `<instance>/d-work/traces/<id>.md` | `traces.py` |
| plan files | `<instance>/d-work/plans/<id>.md`; frozen are only the `Base commit of main:` and `Files touched` lines the guards read | `plans.py` |
| events | `<runbooks>/events/<instance>.jsonl` (its record keys) | `runbook.py` primitives |
| evidence block | the line keys `head=`, `tree=`, `dirty=`, `code=`, `counts:`, `evidence-sha256=`; operators compare it by sha | `package.py` |

**Out of the surface:**
- Every Tended craft's own verbs, guards and stores. Each craft's number carries its promise.
- Internal modules and their function names, `LEDGER.md` (rendered and untracked), the suite memo and the
  `dyad-evidence/` cache.
- The `seat` entity of the cabinet guard: a craft identifier, kept unrenamed by the crosswalk.

## Mutation
Five steps. **Order: required:** 1 → 2; 3 before 4; 4 only after B3's release condition holds.

1. **Counsel, agent-zone PR:** `dyad/SURFACE.md`, the inventory.
   - Contents: S1–S8, one line per item, each marked `frozen`, `moving (#<row>)` or `alias → <term>, removed by #573`.
   - Moving today:
     - the four #554 aliases;
     - the keys A1t and C1 will add (#570);
     - automaton verbs T1 may add (#572);
     - `delegation-posture`, `delegation-posture-unattended` and `relay-form`, which are read only by the cabinet guide.
       These three are recorded as `craft-read` and stay out of the frozen set unless a core Rule reads them.
2. **Engineer, agent zone, stacked on 1:** `dyad/tests/test_surface.py`.
   - It derives S1–S7 from the code and the tree and compares them with `SURFACE.md` in both directions: an item in
     code but not listed fails, and a listed item that no longer exists fails.
   - `DYAD_SURFACE_RELEASE=1` also fails on any `moving` or `alias` mark. The release d-work runs it before R1's cut.
3. **The home asks the operator (preferences zone):** rename the instance's key `attended-seats` to `paired-units`,
   value unchanged (`communicate`). This is not counsel's PR.
4. **Engineer and counsel, one agent-zone PR or two (engineer's call, an execution detail):** remove the aliases.
   - Code (engineer):
     - `sessions.py` and `package.py` stop reading `attended-seats`;
     - `board.py` stops accepting `waiting-on: seat <name>`;
     - the deprecation-warning lines go.
   - Text (counsel):
     - remove the vocabulary alias rows `seat`, `attended` and `executor`, and repoint every Agent Rule `used by` them;
     - in Rule-16, delete "`seat <name>` its alias until the release after next" and "`attended-seats` its alias until
       the release after next, both read", and record the amendment in its falsification record;
     - in Rule-3 and Rule-7, change any "seat" that names the generic to "unit";
     - mark the four crosswalk `alias until` cells `removed (#573, <version>)`;
     - flip the four `SURFACE.md` entries to absent.
   - #554 is carried by this step and closes with #573's done-`Y` (it is cited in this row's refs).
5. **B3's warning release, in engineer's PR 2 or a separate small one:** both old forms print one `warn` line naming
   the new form. This lands before the first core cut past `v0.17.0`.

**Escalation (B3):** if the home finds no core cut planned between now and 1.0, the question "cut 0.18.0 first, or
remove the aliases in 1.0 one release early" goes to the operator through the home. Counsel does not choose.

## Counter and reconciliation
- **Counter.** Pinning the surface now, while three sibling children are still changing it, creates churn. Every
  PR pays an extra edit, and the inventory could simply be written once, at the cut.
- **Reconciliation.**
  - An inventory written at the cut is a snapshot, not a fence. The first breaking change after 1.0 would pass unseen,
    and preventing that is what 1.0 promises.
  - The extra cost is one line in `SURFACE.md` per surface change. Those changes are exactly the ones a reviewer of
    1.0 should see.
  - The `moving` mark makes in-flight changes legal until the release mode is switched on.
