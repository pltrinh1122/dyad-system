## Findings

**F1 — the parked state was never lawful rest, and was never asked.** Rule-2 classes a ledger-only
commit to `main` as *not ratification* ("they record a prompt received or a disposition already
given, never a decision"); Rule-3 says such commits "go directly to `main` without a PR". Only the
session's branch fence turns one into a PR. Rule-1's #23 clause governs exactly this collision and
prescribes: the Agent "does the corpus-legal part it can, **states the rest and asks**". Across five
occurrences the Agent did the first half and never the second.

**F2 — the preference's purpose was defeated while its letter was observed.** `merge-disposition:
with-done` exists so the Operator disposes merges *through the Done-Y*, never as a separate act. No
duplicate merge counter-prompt was asked — so the letter held — yet each parked ledger PR put a merge
on the Operator's desk, which is the one outcome the preference is chosen to prevent.

**F3 — requiring a Y for a ledger-only PR is an infinite regress.** Recording a disposition would
itself require a disposition, and no d-work could terminate. This is why Rule-2's *Not ratification*
section exists; the fence does not change what the act is, only the shape it must travel in.

**F4 — five occurrences, zero asks, and consent inferred from silence.** PR #27 (ledger close #32),
#38 (ledger close #15), #40 and #41 (row open and plan-Y for #56), #43 (ledger close #56). Rule-13
property 1's trigger fired at the second. Found while closing #56, whose own subject was exactly
this failure to convert a recurrence into a question or a code path at two and three occurrences.

**F5 — the resolution is a standing disposition, not a unilateral merge.** Rule-1 forbids reading
permission out of the Rule alone, so the Agent does not start self-merging ledger PRs on its own
inference. The survivor is: state the collision, ask **once** for a disposition covering the class,
and until it is given, ask per instance rather than parking and calling it "waiting on you".

## Falsification

- **"Rule-2 says merging any PR into `main` is a ratification event, so parking was correct."**
  Survives, scoped — the literal words cover it and Rule-1 forbids inferring permission; but the same
  clause requires stating and asking, which was not done. The scope is "never self-merge silently",

- **"The preference was not literally violated — no duplicate merge counter-prompt was asked."**
  Confirmed, reframed: mechanism differs, outcome identical. Purpose defeated, letter observed.
- **"The Done-Y could not bind #43 — it did not exist yet; a new PR needs a fresh Y."** Refuted:
  that clause governs PRs carrying work. A ledger-only PR carries a record of a disposition already
  given; requiring a Y to record a Y is a regress with no terminating d-work.
- **"Then self-merge every ledger-only PR silently."** Survives, scoped — Rule-1's #23 clause. The
  survivor is asking once for the class, not acting unilaterally.
- **"A one-off."** Refuted: five occurrences (F4).
- **"Merging them without complaint implied consent."** Refuted: the Operator has stated the
  opposite outright; consent was inferred from silence.
