## What the audit measured, restated as the thing to fix
`python3 -m unittest discover -s dyad/tests` costs **120.06 s** by hand and **39.13 s** with
`DYAD_NO_NESTED_TESTS=1`, the variable `check_rule_12` sets for every suite it spawns
(`dyad/scripts/package.py`, the `env={**os.environ, "DYAD_NO_NESTED_TESTS": "1"}` argument). The
3x is the nested scratch installs running their own full suites. Across the session: **134 hand-run
suites, 3,894 s, required by no Rule**, and eight of the ten longest commands of the whole session
are that one command.

The habit is not "runs tests"; it is "reaches for `python3 -m unittest` because it is the shortest
thing to type". Rule-13 property 1 is exactly this case: the second occurrence of an inference task
yields a code path, and this is the hundred-and-thirty-fourth.

## Mutation (what a plan-`Y` authorizes)
One agent-zone PR, branch `agent/155-cheap-test-path`:
1. `dyad/scripts/package.py` — a new `check --tests [<target>]` verb and its `cmd_tests`:
   - no target: every root `test_suites()` returns, each as `unittest discover -s <root> -q`,
     printing the same `[Rule-12] <root>: Ran N tests OK` line `check_rule_12` prints;
   - a target that is a directory: that root only;
   - a target that is anything else: passed to `unittest` as a dotted module, class or method;
   - **always** with `DYAD_NO_NESTED_TESTS=1` in the child environment, which is the whole point;
   - exit non-zero if any root fails, so it is usable in a chain.
   The verb is added to the entrypoint's usage text so it is discoverable where the others are.
2. `dyad/tests/test_package.py` — its mechanical check (Rule-12 property 1): that `check --tests`
   with a dotted target runs that target and nothing else, that it sets the flag in the child
   environment, and that a failing target makes it exit non-zero.
No Rule, vocabulary, preference, play-book or craft change. No `VERSION` bump: `dyad/VERSION` is
0.9.0 and no `dyad-operator-v0.9.0` tag exists, so `bundle.check_drift` skips; `BUNDLE.md` already
reads 0.9.0, so no infra PR and no release. Re-verified in the completion evidence.

The completion reply must carry a **timing** of the new verb against both existing paths on this
tree, or the d-work has not delivered its own premise.

Outside the mutation, and stated rather than hidden: I will also write the habit into this
machine's memory cache, which is per-machine and not corpus (Rule-2, Not ratification), so a later
session reaches for the verb at its first test run rather than at its hundredth.

## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | A command cannot fix a habit: `python3 -m unittest` still exists and is still shorter to type. | **Survives, scoped** | It cannot *forbid* the habit, and the audit's own finding is that conduct notes fail (#67 recurred within an hour of its note). What it changes is the reachability: the cheap path becomes one verb of the entrypoint already used forty times a session, and the expensive path stays available for the case it is actually good at — running one failing case with full output. |
| 2 | Simpler: export `DYAD_NO_NESTED_TESTS=1` in the shell or the hook and keep typing `unittest`. | **Refuted** | The variable is a per-invocation switch that tells a suite "you are already inside a test run; do not recurse". Setting it globally would silently hollow out a deliberate nested run — the scratch-install tests are Rule-11 property 5's tested install, and a global flag makes them stop testing the thing they exist to test, with no signal. |
| 3 | The real fix is to make the scratch installs cheap, not to route around them. | **Survives, scoped** | True and larger. Their cost *is* what they buy (Rule-11 property 5: CI installs the core and a craft into a scratch repo and runs the guards there). Making them cheaper is its own d-work with its own risk; routing the common case away from paying 3x for them is available today and costs nothing they check. |
| 4 | Rule-12 already requires the suite to pass, so a new verb adds nothing. | **Refuted** | Rule-12 binds the check, never the invocation; nothing in the corpus says how a suite is run by hand. This is Rule-13 property 1's clause, not Rule-12's, and Rule-13's Enforcement is inference for exactly this reason. |
| 5 | The saving is illusory — the runner's 39 s and the hand-run's 120 s measure different work, so the verb will not actually be faster. | **Must be measured, and the plan requires it** | `check_rule_12` and the proposed `cmd_tests` spawn the identical command with the identical environment, so they should agree within noise; if the timing in the completion evidence does not show the verb at the runner's cost rather than the hand-run's, the premise is false and the d-work reports that instead of shipping. |
| 6 | Scope creep: the Operator said stop doing it, and this writes code. | **Survives, scoped** | The honest counter. #135 established that an inference mitigation with no home is not a mitigation, and #128 that a candidate with no row is invisible; a note in a per-machine cache is the weakest container the corpus knows. The verb is the smallest durable form, and it is nine lines of dispatch plus a test. |
| 7 | Implement all four candidates while the file is open. | **Refuted** | Candidate 3 recommends changing nothing. Candidates 2 and 4 are conduct and measurement, not code, and the Operator named one to take first. Widening now would put three unfalsified changes under one `Y`. |
