### The mechanism, shared (core)

**The order.** Every candidate the home would show or propose gets a sort key:
- **obligation**: promotion's P1 (a live defect) and P2 (a promise). These outrank everything, because they are owed
  and not chosen.
- **alignment**: the horizon of the goal the row serves (long-term, intermediate, or none).
- **focus**: today's focus weight, if the row matches it.
- **urgency**: the rest of promotion's classes, P3–P6, and Recommended for next's trigger kinds, in their existing
  order.

How the key is compared depends on the operator's conflict rule:
- `goals-first` compares lexicographically: obligation, then alignment, then focus, then urgency. Focus can reorder
  only within one alignment tier. This is this operator's rule as entry 1 states it, and the default.
- `blend` sums alignment and focus as weights, for an operator who wants the day to count for more.

Departure from the reading (b), stated: WSJF's denominator is size, and the dyad measures no size. Sizing
(`dmc:altitude`) splits a row; it does not estimate one. So the order has no size term. If a size estimate is ever
recorded, it would enter by a revision of the record.

**Focus decay.** A focus's weight is its source weight (stated 1, inferred `inferred-focus-weight`, default 0.5) times
0.5^(age / `focus-half-life-days`, default 1). A weight below 0.05 counts as nothing.

**Grounding.** Which goal a row serves is the home's inference. It is recorded write-ahead, as Recommended for next's
inferred lines are (#695): a `serves:` line on the home's cross-row board entry, `#<id> G<n>|none (<reason>) @<ISO time>`.
An entry the row has changed past is dropped with a warning. The board holds only the goal's id (`G<n>`), never its
words, so a public store holds no goal text.

**What it authorizes.** Nothing: a form, not an authority (`dmc:preference-kind`). Each item still becomes work only by
its own question or an operator prompt.

### The store, per operator (h)

**In the operator's central repository** (#700; named per checkout, never in a tracked file), under `operator/`:
- `goals.md`: one block per goal, `## G<n> <long-term|intermediate> review <date>`, then a fenced body holding the
  operator's words verbatim (as Rule-7's entries are) and a `status: active|retired` line. Goal ids are never reused.
- `focus.md`: append-only, one block per focus, `## <ISO time> <stated|inferred>`, then a fenced body. A stated focus
  holds the operator's words. An inferred focus holds the home's one-line reading, marked as such: it is never the
  operator's words (i).
- `settings.md`: `key: value` lines for `attention-conflict`, `focus-half-life-days` and `inferred-focus-weight`.
- `dmc/`: the operator's own decision records. A record is admitted only if it declares
  `dyad:extends: dmc:attention-strategy`, and its outcomes may only add an order or a tie-break. A record whose outcome
  declares `acts` or `skips` is refused, so an overlay can never authorize or skip a question.

**Fallback, in a checkout that names no central repository:**
- the goals and the settings in `preferences-corpus/ATTENTION.md`, operator-owned and changed by a preferences-zone PR
  the home presents as its own question;
- the focus as a `focus:` key on the home's cross-row board entry, which is ledger-only and overwritten.

The fallback is public, and the play-book says so where the operator reads it.

**Settings precedence:** the central repository's `settings.md`, then `preferences-corpus/PREFERENCES.md`, then the
record's default.

The agent writes a goal only from the operator's words in a prompt, verbatim, by `dyad attention goal` (below). It
never composes one.

### Verbs (`dyadlib.CLI` rows; `dyad/scripts/strategy.py`, new)

- **`dyad attention goals`** (read-only): prints the goal stack from the store, with each goal's review date and an
  `overdue` mark.
- **`dyad attention goal add|retire …`**: writes a goal block from `--said-file` (the operator's words) to the store,
  committed in the clone and pushed with sync's retry, or prints the fallback PR's diff.
- **`dyad attention focus --said-file <f>` / `--inferred "<line>"`**: appends a focus.
- **`dyad attention order [--full]`** (read-only): prints the candidates (backlog rows and the Recommended items) in the
  strategy's order, each with its key, its grounding (`serves G<n>` or `serves none`) and today's focus weight.

### Consumers

- `board.recommended` orders the `promote` and `hardening` items by the strategy, and the closing line names each
  item's goal id: `promote 2 (#a G2, #b)`.
- The home's promotion proposal (`dmc:promotion`) reads the order: goal alignment sits after P2 and before P3.
- Grooming (`dmc:backlog-staleness`): `unwanted-candidate` gains one more input. A row read `holds` at two readings and
  recorded `serves: none` at both joins the still-wanted group.
- The weekly goal review rides grooming. The play-book's report gains `goals:` lines (each goal, its review date, and
  the rows it served since the last review) and the **uptake** count: of the items Recommended or promoted since the
  last review, how many the operator took up, by goal. This is a proxy for the strategy's effect, stated as a proxy
  (Guide §12 item 7).
