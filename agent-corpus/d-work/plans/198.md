## Falsification
| # | Attack | Result | Survivor |
|---|--------|--------|----------|
| 1 | The two PRs are test and guard hygiene; ship without them. | **Refuted for #223** | It is not hygiene. Until it merges, `infra/manifest`'s verdict depends on whether a `__pycache__` directory exists on the machine running it — a guard that can disagree with itself between two runs of the same tree. Publishing a core craft with that in it hands every downstream install a check that is not deterministic, which is the property `crafts/syseng/rules/determinism.md` exists to keep. |
| 2 | Then #224 at least can wait. | **Survives, scoped** | It can. Three assertions that cannot fail cost nothing downstream; they are a gap in what the suite proves, not a defect it ships. It is in the same branch family and lands in the same window, so waiting for it costs nothing either. |
| 3 | Merge them from here and be done. | **Refuted** | Rule-2: the Done-`Y` is the Operator's verification of *that d-work's* output, asked on the evidence its own session gathered. This session has neither. |
| 4 | Release the four bundled crafts now and the core later. | **Refuted** | `BUNDLE.md` names `dyad-operator 0.10.1`; a bundle release naming an unreleased component is what #158's ordering avoided, and a craft-only release would leave the bundle un-cuttable until the core catches up. |
| 5 | Nothing is urgent, so do nothing. | **Survives, scoped** | True: nothing downstream is broken today, and the release is the Operator's to time. The cost of waiting is that six components drift further from their tags, which is the drift guard's own subject. |

**Verdict.** One thing needs merging first and it is not mine to merge: PR #223. PR #224 may as
well ride with it. After both land, the release is a clean sequence with no other branch outstanding.
