Proposed steps (for the plan to fix):
1. Symptom: the act the operator questions, quoted.
2. Trace back: for each step, the Rule sentence, record outcome or preference that decided it, cited by path and line, read on main, never from memory.
3. Conflicts: where two of those disagree, or one is stale against main.
4. Classify the cause, by a decision record: agent error (a record decided it and the agent misapplied it), record gap (no record or Rule decides the case), conflict (two disagree), stale text (text no longer matches the code or the store), working as intended (the behavior is what the rules say, and the operator's model is what moves).
5. Outcome by class: an incident row for an agent error; a proposed row for a gap, conflict or stale text; nothing but the explanation when it is working as intended.
6. The trace itself, corrections to the agent's earlier answers named as such.

Names (the operator's reference; recommended first):
- **judgement trace**: says what is followed, the agent's judgement, step by step. Beside the d-work trace (time) it reads as "the other trace".
- **conduct review**: names the subject, the agent's conduct, and the review as a whole, including a "no change" outcome.
- **root-cause trace**: plain and familiar, but it presumes a fault, which the working-as-intended ending denies.
- **examination**: the operator's own word; short, but too general to grep for in a corpus that already uses it.

Definition of done (proposed): the play-book `dyad/playbooks/<name>.md` with the six steps; the decision record `dyad/dmc/<name>-cause.jsonld` with the five classes and their outcomes; the term in the vocabulary; a test that the play-book cites the record; the operator can start one by writing "<name>: <the behavior>".
