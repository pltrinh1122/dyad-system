## Falsification
- "D1: derive the floor from imported symbols (the report)" — refuted by the reproduction: every
  symbol predates the break; the break is a value. Survivor: check the floor by running the
  craft's invariants against the floor core's `dyadlib`. Attack on the survivor: "a craft may read
  a value without asserting it in an invariant, and still break" — survives, scoped: the check
  catches what the craft *declares* it depends on; `invariants.md` already says a module's
  dependence on constants is its `INVARIANTS` — the discipline this makes load-bearing.
- "D2: keep the grammar strict and let derived installs bump patch" — refuted by the report's own
  point and Rule-11 p4: a patch number is a release the authoring repo may cut; a derived tree
  claiming it is D2's collision in advance. Build metadata is what semver defines for this.
- "D2: `+local` will leak into the authoring repo's releases" — refuted: `bundle.check` requires
  row == live `VERSION`, and `tag_name` still `<name>-vX.Y.Z`; a `+local` `VERSION` in this repo
  fails the bundle row and cannot be tagged as a release by the release path.
- "D3: keep 'one craft per surface' (projection.md p4) — it was a design choice" — refuted by the
  register's own precedent: guards, vocabulary and paths are all craft-qualified; the surface was
  the exception because sysarch was the only projector craft when p4 was written (#160). #99 and
  the report both hit it with a second craft. The *qualified* uniqueness is kept.
- "D3: fix the core key only" — refuted, as the reporter verified: the sysarch guard re-derives;
  the survivor collapses to one source (the runner's `projectors()`), the guard reading it.
- "D4: conjunctive was intentional — a stricter contributed row should be able to *tighten*" —

  `workstation-corpus/`); tightening a native pattern is a syseng change, not a contribution.
