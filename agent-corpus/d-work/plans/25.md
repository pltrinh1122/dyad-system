Falsification: inline below (Rule-9).

## Intent as read
"Are you using a run-time invariant in the `.py` code touched by this flow? Seems suitable." Three
questions in one: did #24 skip an invariant, is this flow invariant-shaped at all, and if the
instinct is right, what exactly does it point at.

## The answer, in three parts
**1. #24 skipped nothing.** Its diff is one line of bash and two markdown files. `invariants.md`
property 1 binds "a module that carries a data model — an upper-case module-level name bound to a
tuple, list, dict, set or frozenset". No such module is in that diff; there is nothing to declare.

**2. #24's own fact is not invariant-shaped.** "A hook must not invoke a path the mode rules keep at
644" is a fact about tracked files and index modes. Property 1 puts that out of bounds in as many
words — a predicate "over the module's constants (never over the instance corpus)", run before any
check, with no filesystem read. Its home is a guard `check_package`, which is the backlog row #24
proposed, not an invariant.

**3. The instinct is right one level down, and this is the row for it.** `containment.py` dispatches
its CLI on a dict literal *inside* `main()`:

    fn = {"staged": …, "commit": …, "commits": …, "range": …, "tree": …}.get(mode)

with `zones` handled by an earlier `if`. Six verbs, and not one of them is named by a module
constant, so no invariant covers any of them — while the sibling constant `MODES` (the two *check*
modes, `commits` and `range`) is covered by `modes-declared-and-distinct`. Three surfaces must
already agree and nothing checks that they do: the dispatch table, `MODES`, and the docstring's
usage block that `sys.exit(__doc__)` prints when a verb is unknown. `staged` is the shipped
`pre-commit` hook's entire contract with this module, and `zones` is what Rule-1 tells a reader to
run. Checked: `containment.py:152` is the only hidden dispatch table in the tree — this is one
module's gap, not a pattern, so no syseng guard is warranted (Rule-13 wants recurrence first).

## Mutation — one PR, agent zone
1. `dyad/guards/infra/containment.py`: lift the dispatch to a module constant
   `VERBS: dict[str, Callable[[list[str]], list[str] | None]]` covering every CLI verb, `zones`
   included; each handler takes `args` and returns the fails list, or `None` if it printed its own
   output (`zones`). `main` becomes a lookup and keeps its present output exactly.
2. Three invariants over those constants, no filesystem:
   - `modes-are-verbs` — `set(MODES) <= set(VERBS)`: every documented check mode is dispatchable.
   - `hook-verb-is-a-verb` — a new constant `HOOK_VERB = "staged"`, naming the shipped hook's
     contract, must be in `VERBS`.
   - `verbs-in-usage` — every verb appears in the module's own `__doc__` usage block, so a verb
     added without its usage line trips before any check runs.
3. `dyad/tests/guards/infra/test_containment.py`: the lift is behaviour-preserving (each verb
   dispatches as before, an unknown verb still exits the usage) and the three invariants hold.

## Falsification
- **"This closes the loop #24 left open."** Refuted, and stated so rather than sold: it does not. A
  coordinated rename that updates `VERBS`, `HOOK_VERB` and the docstring but not the bash hook still
  breaks, and only a guard that reads the hook file catches that — the deferred backlog row.
  `hook-verb-is-a-verb` catches the *careless half* of such a rename, which is the common one.
- **"Churn in a guard that is currently correct, for partial coverage."** Survives, scoped — the
  honest cost. The refactor is small and behaviour-preserving, and what it buys is not the invariants
  alone but the declaration: an implicit data model becomes an explicit one, which is what
  `invariants.md` property 1 asks of every module that carries one. If the Operator weighs the churn
  higher than the declaration, `N` is the right answer and nothing else in the system depends on this.
- **"Then every module hiding a dict should be lifted — this is a sweep."** Refuted by measurement:
  `containment.py:152` is the only one in the tree. n=1, so no rule and no guard, just this module.
- **"An invariant over `__doc__` reads a string, and property 1 exempts string-only modules."** Refuted:
  the exemption is about a module whose *only* constants are strings needing no invariants at all;
  `__doc__` is a module constant like any other, and this module carries `ZONES`, `MODES` and now
  `VERBS` besides.
- **Overlap (Rule-16):** peer `dev-main` is stale with an empty `files` set; no overlap on these two
  paths.
- **No honest counter found** to the reading in part 2: `invariants.md` property 1 excludes the
  instance corpus in as many words, so #24's fact could not have been an invariant however it was
  framed.
