# Self-diagnostic test levels (seed; the core craft's, `dyad/templates/`, since #369 C4, d-work #378 — born the countersign
# craft's; the classification: the audit play-book `dyad/playbooks/audit.md`, its self-diagnostic section; the check:
# `dyad/scripts/levels.py`). Copied by hand to <host>/self-diagnostic-levels.txt, the instance file levels.py checks
# (<host> is the host path, preference `host-path`): `cp dyad/templates/self-diagnostic-levels.txt <host>/`.
#
# One `<level> <path>` per line: level `unit` (L1, run in-process) or `integration` (L2); path a repo-relative
# test module, run one at a time as `dyad/bin/dyad check --tests <path>`. `#` starts a comment, here or after a
# line's fields. The granularity is the module: a module any of whose tests builds a scratch repo, runs git,
# installs or spawns the runner is `integration`, however many of its other tests are not.
#
# This seed covers the core (`dyad/tests/`) and the bundled sysadmin craft (`crafts/sysadmin/tests/`). A system adds a
# line for every test module of every other craft it installs, and revises a line whenever a module it names is
# added, moved, removed or changes level: the check fails on a module present but unclassified and on a line naming
# no module, in that system's own tree, and the run-book's `health` step, which runs it, stops the diagnostic there
# (a script, not a guard: it runs on no push). A system whose core predates a module named here deletes that line on
# copying it. The levels below are this tree's, and a receiving system re-observes its own core's modules before
# trusting a `unit` line: on an older core, a test that runs its guard over the live repo through
# `dyadlib.repo_root` starts `git rev-parse` there and is `integration` by the criterion below.
#
# Observed, not judged, in dyad-system at bdd74b3 (core 0.11.0, 2026-10-15): each module was run alone under an
# audit hook on `subprocess.Popen`. A module that started no child process is `unit`; one that started any — git,
# an interpreter, a shell, the runner — is `integration`, and the comment names what it started. Reading the
# package's own files in-process (a Rule, a data file) starts nothing and stays `unit`. A module edited since
# can move; re-observing it is the classification's only test. The two modules the core gained from the countersign
# craft (#378) keep the levels observed there: test_levels.py started no child process; test_project_countersign.py
# builds scratch repos and runs git log and tags.
