# Rule-14 check data (beside its guard, guards/infra/manifest.py; crafts/sysarch/rules/guards.md): which manifest component each invocation token belongs to.
# One entry per line: `<component>: <token> <token> ...`. `<component>` is the manifest's
# `component` cell (backticks ignored). A token is a shebang interpreter, a subprocess argv[0],
# a shell command word, a workflow `uses:` value, or `import:<module>` — the top-level name of a
# third-party Python import (stdlib and package-internal imports need no entry). A lone `-` marks
# a component the package never invokes (Claude Code runs the Agent; Linux provides the kernel; GitHub is a remote).
# Blank lines and # comments ignored. Only core components are mapped here: a map naming a component
# the core does not declare fails on every system that lacks it. A system's own operating rows
# (`<host>/INFRASTRUCTURE.md`: Gitea, Docker, GHCR, curl on dyad-system, #175) need no entry — the
# package never invokes them.

Python: python3 python

bash + GNU coreutils, grep, awk, sed: bash sh grep awk sed tr cut sort uniq mktemp cat ls rm cp mv mkdir printf echo tail head wc
